# case-03 · 这个月为什么贵了 · 阶梯电费账单解剖

- **作品**：`final.png` · `final.snapshot`
- **尺寸**：780 × 1688（手机竖屏）
- **接受版本**：v2（B06-req-0007；v1 配对修复见 B06-req-0008）
- **受众 / 环境**：收到电费账单后不明白涨幅从何而来的住户；居家查看手机账单页，
  需要看清分档边界。
- **观看目标**：知道本月电费由哪几档构成、涨的钱落在哪一档。

## 用户原本卡在哪里

账单给出一个总额和一个用电量，涨了多少一目了然，但**涨的钱从哪来**没有答案。
阶梯电价的真实结构是"超过某个量之后单价变贵"，所以同一个用电增量在不同的档位
里价格完全不同。住户看不到档位边界，就只能把涨幅归因于"电贵了"或者"我用多了"
这两个都不精确的说法。

## 场景与受众

收到电子账单的当晚，居家、安静、可以细看。需要同时读到三件相互关联的事：本月
几档各用了多少度、每档单价多少、比上月多出来的钱具体压在哪一档上。

## 内容

- 三档结构（制度背景；SRC-03 正文 HTTP 404 未取得，**档位电量与单价、用电量
  金额一律标为示例演示**，不逐字引用）。
- hero 三数据卡：本月用电、本月电费、环比涨幅。
- 分档明细表：180 / 186 / 0 度 · 93.60 / 106.02 / 0.00 元 · 合计 199.62 元。
- 增量归因卡：明确指出多出来的钱落在哪一档。
- 阶梯面积图：台阶高度 = 该档单价，宽度 = 该档电量，面积正比于该档电费。
- 来源边界卡。

## 视觉选择

**视觉隐喻是"台阶"**：单价不是一个数字，而是一个**高度**；电量是**宽度**。于是
"第三档为什么贵"变成"这段台阶为什么高"，"这个月为什么贵了"变成"多出来的面积长
在哪一级"。面积 × 单价的乘法关系因此是可看的，而不是需要信任的一个数。

纵轴（电价 元/度）与 0.4 / 0.6 / 0.8 刻度让台阶高度本身可读，否则图上半部只是一
片没有刻度的空白。
