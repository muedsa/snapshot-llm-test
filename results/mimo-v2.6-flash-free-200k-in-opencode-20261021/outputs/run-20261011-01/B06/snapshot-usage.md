## 4. 修改记录与踩坑

以下均为**本题真实遇到**的问题，不是从文档了解到的注意事项。未触发的注意事项不列入。

### 4.1 `dashed_v` / `dash_line` 返回字符串，必须 append 入图层（case-10 v1）

| 项 | 内容 |
|---|---|
| 类型 | 视觉迭代（渲染成功但视觉不符合要求） |
| 现象 | v1 曲线只画出四条水平档位，看不到价格在何处跳升 |
| 原因 | 三处跨档攀升线只调用了 `dashed_v(...)` 取返回值，从未 `B.append(...)`，对象未进入图层 |
| 确认依据 | `_probe10.py` 沿期望攀升位置扫描，橙色像素计数为 0；而四条水平线本身像素正常——**若无探针，「渲染成功 + 整图看起来正常」会掩盖此缺陷** |
| 修改 | 三处 append 入图层，并由 2px 加粗为 3px |
| 验证结果 | v2 复看：三处攀升可见；v4 定版，三处均带时刻标注 |

相关文件：`drafts/case-10-v1.snapshot` … `case-10-v4.snapshot`、`scripts/_probe10.py`

### 4.2 `in` 对列表是成员判断，不是子串判断（case-06）

| 项 | 内容 |
|---|---|
| 类型 | 逻辑缺陷（生成期断言失效） |
| 现象 | C4「不把概率换算成时长/雨量」的文本审查逻辑未按预期筛出条目 |
| 原因 | `simp in FIXES` 中 FIXES 为列表，`in` 做的是**元素成员判断**，不是子串匹配 |
| 确认依据 | 改为 `any(simp in f for f in FIXES)` 后逐条命中行为符合预期 |
| 修改 | 改用 `any(...)` 生成器表达式 |
| 剩余问题 | 无；v2 定版后 31 条渲染文本审查全部通过 |

### 4.3 生成器覆盖了旧版 DSL，导致 DSL 与 PNG 失配（case-03）

| 项 | 内容 |
|---|---|
| 类型 | 留痕事故 |
| 现象 | 生成器 v2 再次运行时覆盖了 `case-03-v1.snapshot`，v1 的 DSL 与已渲染的 v1.png 不再配对 |
| 原因 | 生成器写死了输出文件名，未按版本号区分 |
| 确认依据 | 文件 mtime 与 requests.jsonl 中 v1 请求的时间关系不符 |
| 修改 | 重建 `case03_v1.py`（还原原图表绘制顺序）重新生成 v1.snapshot 并重渲染 |
| 验证结果 | 重渲 md5 = `614bf75b94c488e21632cb8a49d5e104`，**与原图逐字节一致**，配对恢复。副产品证据：**服务渲染是确定性的**——同一 DSL 重渲染得到完全相同的 PNG |
| 相关请求 | B06-req-0008 |

### 4.4 色彩容差必须小于相邻填色的色差（case-09）

| 项 | 内容 |
|---|---|
| 类型 | 验证手段失效 |
| 现象 | 核验同分色带范围时，色带与页面底色无法可靠区分 |
| 原因 | v2 色带 #E8F2FB 与底色 #EDF1F5 在蓝绿通道仅差 5/255、1/255，容差取 12 时两者都被命中 |
| 确认依据 | 逐通道比对色值；同时该色差在 3–5 米观看下也确实过弱（目标环境为大屏） |
| 修改 | v3 把色带加深为 #D9E8F6（与底色差 20/255），并把容差收窄；并列标注 15→17px |
| 经验 | **取色容差必须显著小于目标填色与其相邻填色的色差**；否则断言通过不代表画面正确 |

### 4.5 整数像素取整使严格比例断言过严

| 项 | 内容 |
|---|---|
| 类型 | 断言方法缺陷 |
| 现象 | 短条形的「宽度 / 数值 = 常数」比值断言在数值较小时频繁失败 |
| 原因 | 端点坐标取整，1–2px 误差在短条上被比值放大 |
| 修改 | 改用 `abs(实际宽度 − 数值 × 比例常数) ≤ 容差`，容差随 |数值| 缩放 |
| 验证结果 | case-07（秒数 × 2.6417px/s）、case-09（|净胜球| × 25px/球，误差 ≤1px）、case-04（落点比例最大偏差 0.008）均通过 |

### 4.6 渲染文本中 ASCII 全角括号不可用

| 项 | 内容 |
|---|---|
| 类型 | 字符兼容 |
| 现象 | `<` / `>` 在渲染文本中不可用 |
| 修改 | 全部改用全角 `＜` `＞` |
| 已验证安全 | `÷` U+00F7、`→` U+2192、`−` U+2212、`∝`、`μ` 均正常渲染；`①②③` 因豆腐块风险避开，case-01 改用带色圆点内嵌数字 |

### 4.7 字体宽度估算对拉丁粗体偏低约 4–5%

| 项 | 内容 |
|---|---|
| 类型 | 跨题复用经验（源自 B05 探针实测，本题直接沿用） |
| 现象 | `tw()` 对含拉丁粗体的串报出的宽度低于真实墨迹宽度 |
| 影响 | case-07 的 60 条与 case-10 的 47 条文本宽度断言均按 `tw_slot` 槽宽留余量 |
| 验证 | case-10 v3/v4 期间用**实测墨迹宽度**建框，对图表标注两两重叠 / 压住攀升线 / 越出绘图区加断言，全部通过 |

### 4.8 超长中文命令行导致 PowerShell 解析崩溃

| 项 | 内容 |
|---|---|
| 类型 | 环境问题 |
| 现象 | 通过 shell 调用 `log_iter.py` 并传入超长中文观察/修改文本时，PowerShell 报 `TerminatorExpectedAtEndOfString`，日志未写入 |
| 修改 | case-09 v3 改用一次性脚本 `_log09.py` 写入；此后长日志一律走一次性脚本，命令行文本控制在约 500 字符内 |
| 相关文件 | `scripts/_log09.py` |

### 4.9 日志字段补齐与时间基准的如实处理

**(a) requests.jsonl 补齐必需字段。** 渲染器写入的记录只有渲染相关字段，缺 AGENTS 要求的
`case_id` / 请求类型 / 起止时间。**原始字节完整保留于
`tmp/run-20261011-01/B06/requests-raw-000001.jsonl`**，其后为每条追加派生字段：
`case_id`（由 dsl_path 确定性推导）、`request_type: "render"`、`endpoint: "/snapshot"`、
`started_at`（= ts − elapsed_seconds）、`finished_at`、`timezone`、`credentials_used: false`。
**未删除或修改任何原值**，派生字段在 `derived_fields` 中列明。
服务响应未返回 `requestId` / `Server-Timing` 头，两个字段如实记为 `null` 并附说明，
不编造。

**(b) 看图时间不编造精确值。** `iterations.jsonl` 的 `ts` 是 `log_iter` 的**写入时刻**
（部分按用例批量写入，同一用例多版共用一个 ts），不是看图时刻。为此另建
`iterations-view-times.jsonl`，每条记录：

- `viewed_recorded_at` = 写入时刻，`viewed_recorded_basis` 说明其含义；
- `render_completed_at` = 该版真实渲染完成时刻（来自 requests.jsonl）；
- `view_window_seconds` = 两者之差，即**看图发生在这个区间内**；
- 区间为负或过长时给出 `view_window_note` 说明原因（case-03 v1 的证据修复重渲晚于
  首次看图；批量写入的批次上界）。

**不为看图动作编造精确时间戳。**

**(c) `log_tool.py` 的自动时间戳不适用于已发生的事件。** 该脚本 `ts` 取 `now()`，
对研究抓取、校验脚本运行等**已经发生**的动作会写入错误时刻。因此改用一次性脚本
`_logtools.py` 写入 22 条 tool-usage 记录，每条附 `ts_basis` 说明时间来源
（plan-v1 的 `fetched_at` / 脚本文件最后写入时间 / 本次补写动作自身），并在
`outcome` 中记录结果。时间未知处写 `null`（SRC-03 无 `fetched_at`），不猜测。

## 6. 设计选择、经验与未解决事项

### 6.1 关键设计选择（预览如何影响选择）

十件的分界线是**读者缺哪一类推理**，而非共用一套版式。三处由预览直接推动的决定：

- **case-06 由柱状图改为 100 格阵列**。柱状图会引导读者去找横轴，而横轴会被默认为
  时间——这恰好会**强化**要纠正的误读。格子没有轴，只能被读成份数。
- **case-09 同分组由三个色块改为一条连续色带**。规则说的是「这三队同分」（一个状态），
  而三个分离色块读作「三行各自被高亮」（三个事件）。v1 实看发现后改为连续带。
- **case-10 补上三处攀升线**。只有水平段时读者看到的是四个互不相关的高度，而不是
  「从这一级跳到那一级」。补线后「什么时候跳价」才从解不等式变成指认虚线。

### 6.2 可复用经验

1. 只调用图元构造函数不会让它入图层，必须显式 append（§4.1）。
2. 列表上的 `in` 是成员判断，子串匹配要 `any(x in s for s in seq)`（§4.2）。
3. 生成器必须按版本号写输出文件，否则旧版 DSL 会被覆盖、与 PNG 失配（§4.3）。
4. 取色容差必须显著小于目标填色与其相邻填色的色差，否则断言通过不代表画面正确（§4.4）。
5. 比例断言用「绝对偏差 ≤ 容差」而非严格比值，容差随数值缩放（§4.5）。
6. `tw()` 对拉丁粗体低估约 4–5%，槽宽要留余量；关键标注用实测墨迹宽度建框（§4.7）。
7. 像素探针能发现「渲染成功但内容缺失」的缺陷，是整图实看的必要补充而非替代（§4.1）。
8. 日志的时间基准要逐条说明来源；不可测的写 `null`，不编造（§4.9）。
