# case-08 · 登机前一小时在做什么 · 登机牌与状态时间轴

- **作品**：`final.png` · `final.snapshot`
- **尺寸**：1440 × 900（网页横屏，浅色）
- **接受版本**：v2（B06-req-0017）
- **受众 / 环境**：遇到航班延误、不确定还要等多久的旅客；候机厅笔记本或大屏查看，
  2–3 米距离。
- **观看目标**：知道**当前处于哪个环节**、延误原因、以及登机口是否变更。

## 用户原本卡在哪里

延误发生后，登机牌上的时间不再可信，而航显上的每个时刻都只是孤立的数字：
18:40 和 19:35 之间发生了什么？现在是 18:32，我在哪个环节？登机口变没变？——这
三个问题分别散落在登机牌、航显和广播里，**没有一处把它们放在一起并指出"你在这
里"**。

## 场景与受众

候机厅，可能是笔记本也可能是大屏，距离 2–3 米。横屏因此需要更大的字与更强的
对比。这是一个"扫一眼就回手机"的场景：五件事（航班号 / 日期 / 登机口 / 座位 /
登机时间）必须一次性可读，时间轴必须一次看清当前节点。

## 内容

- 左侧登机牌卡片：自拟演示数据药丸、岚城 → 沁川大字航段、航班号 XA 2049 / 日期
  10 月 26 日 / 登机时间 19:15（新预计）三行带分隔线、**登机口 A15 与座位 32C
  两个 44px 大号高亮格**、示意条码并标注非真实值机码。
- 右侧红色延误块：**延误 55 分钟**（48px 大字）、原因（目的地机场雷雨绕飞）、
  原计划 18:40 → 新预计 19:35、登机口 A15 未变 · 座位 32C。
- 右侧白色状态时间轴：15:50 / 18:10 / 18:32 / 19:15 / 19:35 五节点，绿 / 红 /
  橙 / 蓝 / 蓝四色圆点区分已完成 / 已延误 / 当前 / 待办。
- 页脚边界说明。

## 视觉选择

**视觉隐喻是"把两种证件叠在同一屏"**：登机牌回答"我是谁、坐哪"，状态时间轴回答
"现在到哪了"。左侧是**静态不变的事实**（登机口、座位没有变），右侧是**正在变化
的状态**（延误、新时刻）。左右分区本身就在传达"改的是时间，不是位置"。

时间轴的关键不是节点，而是**你在这里**。所以当前节点需要一个显式的标记，而不是
让读者拿"现在几点"去心算比对。

## 实际自检

两个版本，逐张实看：

| 版本 | 观察到的问题 | 修改 |
|---|---|---|
| v1 | 用户目标是「知道现在处于哪个环节」，但时间轴上当前节点（18:32）没有显式标记，读者需自行判断 | 在 18:32 当前节点后加淡橙高亮带与「现在」药丸，直接标出当前环节；标题与说明框宽度 440→340 让出右侧药丸位 |
| v2 | 淡橙高亮带（744-1386 × 572-637）+ 橙色「现在」药丸已标出当前环节；框宽 340 内无任何文案溢出 | 接受为定版 |

`_verify08.py` 像素核验全部通过：

- **C1 五要素**各自渲染：航班号 XA 2049 墨迹 1186px、日期 10 月 26 日 1548px、
  登机时间 19:15 2205px、登机口 A15 1157px（大字 32px 字高）、座位 32C 1218px，
  且各自位于独立浅蓝高亮格内；
- **C2** 时间轴五时刻墨迹 bbox 由上而下递增（y 450 / 520 / 590 / 660 / 730）且
  逐一右对齐至 x=874，圆点颜色依次 绿 / 红 / 橙 / 蓝 / 蓝 与 已完成 / 已延误 /
  当前 / 待办 对应，四段连接线齐备；
- **C3** 延误块左侧强调条为红、延误大字 4649px 红色墨迹、原因与新预计时间行均有
  墨迹；当前节点高亮带恰在其行内且不溢出上下相邻节点，药丸为橙底白字；
- **C4** 登机口与座位在 登机牌两格、状态块、时间轴说明 **四处**全部呈现且一致；
- **C5** 边界说明、页头与登机牌演示标识均在；四周边距逐像素扫描零越界，条码墨迹
  限于卡片内 x 64–675。

脚本断言：延误 55 分钟由 19:35 减 18:40 **派生**（非硬编码）；登机时间与时间轴第
4 节点一致。

**C1–C5**：全部满足。

条码为示意图形并已标注非真实值机码。
