## 3. 实际使用到的 DSL 能力（跨题汇总）

只列在 30 题中真实用到、且有渲染证据的能力：

**排版与容器**：`Snapshot > SizedBox > Stack(alignment=TOP_LEFT, clipBehavior=NONE)`
的单根嵌套定式；`Positioned` 绝对定位；`Row` / `Column` / `Stack`；有界伸展。

**外观**：`DecoratedBox` 面板与卡片；填充与描边；`border`（单一属性，含
`shape="CIRCLE"` 无填充即成环）；圆角；`transparent` 透明色与 `#RRGGBBAA` 尾部 alpha；
线性渐变（`gradientBegin` 用 `CENTER_LEFT` 等合法枚举值）。

**文本**：多字号 / 多色 / 多行高 / 左右居中对齐；`line_h`；宽字距 tracking。

**图形与变换**：矩形、圆点、线段、弧与扇形、双向与堆叠条形、参数化格阵；
`Transform` 旋转与镜像；滤镜（背景模糊、`Opacity`）。

**接口行为**：`POST /snapshot` 无凭据；服务返回 PNG 原始字节与 400
`PARSE_ERROR` 错误体（含 `diagnostic.allowedValues` 一类可直接照改的正解）。

**未使用**：外部图片素材嵌入。A 赛道 `asset_policy: dsl_only`（素材仅可研究参考），
B 赛道虽为 `dsl_primary_with_supporting_assets`，但 60 件作品全部纯 DSL 完成。

## 4. 跨题踩坑（全部有题内证据，按性质分类）

以下是**在本套中真实触发**、且在两题以上反复出现或教训特别重要的问题。
每条都注明首见题号；完整现象、确认依据与前后对比见对应题的 `snapshot-usage.md`。

### 4.1 服务端语法与能力边界（表现为 400 或渲染不符）

| 坑 | 表现 | 处置 | 首见 |
|---|---|---|---|
| `color="none"` | 首个请求直接 400 `PARSE_ERROR` | 改用 `transparent` | B05 |
| XML 声明头 `<?xml …?>` | 首字符即 400 | `emit` 不带声明 | B02 / B03 |
| 单根多子节点 | 平铺多子节点 400 | `Snapshot>SizedBox>Stack(TOP_LEFT, NONE)` | B02 / A23 |
| `Container` 无 x/y | 想当然的 x/y 被忽略 | 绝对定位一律 `Positioned`；读源码确认 | B02 |
| `gradientBegin` 词汇表 | `LEFT_CENTER` 400 | 服务错误体直接给 `CENTER_LEFT`，照改一次通过 | B02 |
| `BorderStyle` 无 `DASHED` | 无虚线边框可用 | 手造 `dash_line` | B03 |
| `circle border` 双格式化 | 400，且错误位置两次一致 | `border=颜色`、`border_w=线宽` 分开传 | B03 |
| `bold` + `italic` 拆成两属性 | 400 | 单属性 `BOLD_ITALIC` | B03 |
| ASCII `<` `>` | 直出为 `&lt;` `&gt;` | 全部改全角 `＜` `＞` | B05 / B04 |
| `smcp` 小型大写 | 对 CJK 完全不生效 | probe-02 实测后不依赖它 | B03 |
| `Text` 默认 `overflow=CLIP` | 文本框不足直接截断（探针实测截掉「分配」） | 保守估宽 + 生成期断言 | A18 |
| 边框属性写法 | 3×400 | 改单一 `border` 属性 | A24 |

> **可迁移教训**：400 响应体本身是最好的文档——`diagnostic.allowedValues` 常直接给出
> 合法值。读 `parser-tags.html` / `enums.html` / Kotlin 源码比猜测更快、且不浪费请求。

### 4.4 几何、坐标系与语义自洽

| 坑 | 表现 | 处置 | 首见 |
|---|---|---|---|
| 单位混淆 | 像素 x 当 km 送入插值，山体只剩 8px 残片 | 显式 `sx(k)` 换算；条带统一坐标系 | B01 |
| `zip` 步长 off-by-one | 数据列整体右移、末列掉出画布 | 列下标一律 `xs[i]` 对 `COLS[i]` 定点 | B01 |
| 语义换算错误 | 「水位 139%」为重复除 10 | 换算写成**单一公式**，文案与填充比例同源 | B01 |
| `Transform` 描边偏移 | 描边比声明宽半个描边宽 | 发射时做 `±(w/2)·法向` 补偿 | A20 |
| `Transform` 不裁剪 / AABB 失真 | 体块消失或外溢 | 探针对照 + 面构造定式 | B03 |
| 断言方向写反 | 生成期失败（未发请求，省下一次渲染） | 改 `reverse=True` | B04 |
| **恒值表达式** | 镜像坐标写成冗长算式被化简成常量 | 用渲染前几何断言（两两中心距）兜底 | A18 |
| 切片切多 / 重复字 | `ROUTES[0][3][3:]` 切掉「滨江」；`CITY` 已含「市」渲染成「云州市市」 | `[1:]` + `startswith` 回归断言；标题拼接加断言 | B05 |
| 日期与周期口径 | `NOW_DATE` 周四却硬编码 10 月 21 日；周报含周四–周日却称「本周」 | 统一日期并断言；周报改标「上周」+ 日期完整性断言 | B05 |
| 跨案状态色不一致 | case-10 待复核误用橙，与 case-08 蓝不符且撞色 | 统一常量并断言同值 | B05 |
| 图例差 7px 肉眼难辨 | callout 右缘 462 vs 图例左缘 469 | 改为按**字形实测宽度**做双轴判定 | B05 |

### 4.5 量测工具自身失效（最需要警惕的一类）

**验证手段先于画面失效，会让「断言通过」变成假信号。本套出现四次：**

1. **A14 · 整墙量测 ±6px 窗口在 35px 行距下互相渗漏**，产生 8 起假溢出 → 改行带分析。
   卡片量测首跑 **22 起失败全部是工具缺陷**（行盒 leading 判定、`r=22` 边框弧、
   注记亮底圆角外暗底）→ 改包含判定 + `x±12/y±6` 内缩窗 + 注记反相检测，复跑 0 失败。
   **渲染本体未因此返工**——区分「工具错」与「画面错」避免了无谓重做。
2. **A15 · 行扫描被切成两段**，KPI3 定位错 → 检测器合并 ≤2px 间隙的游程。
3. **B05 · 图例差 7px 肉眼难辨** → 改用字形实测宽度做判定。
4. **B06 · case-09 同分色带 `#E8F2FB` 与页面底色 `#EDF1F5` 仅差 5/255、1/255**，
   不仅 3–5 米观看对比过弱，**验证时两者也无法可靠区分**（容差取 12 时双双被命中）
   → 加深至 `#D9E8F6`（差 20/255）并收窄容差。

> **可迁移教训**：取色容差必须**显著小于**目标填色与其相邻填色的色差；量测窗口必须
> 小于相邻结构的间距。否则断言通过并不代表画面正确。另两条配套经验：**比例断言用
> 「绝对偏差 ≤ 容差」而非严格比值**（整数像素取整在短条上会放大比值误差）；
> **连线残差判定 > 距离阈值**（反走样像素必然落在某条 blend 连线上，取最小残差可
> 同时处理反走样与调色板互混）——A09。

### 4.7 服务与环境

- **A21 round-02 出现 6 次 `RemoteDisconnected`**（无状态码、无 `Retry-After`）。
  用最小 DSL 探针定位为**服务端间歇性问题**而非本题 DSL 缺陷，退避重试后恢复；
  全部失败尝试保留在 `requests.jsonl`，未伪装成成功。
- **429 / `Retry-After` 路径全套未触发**（0 次），因此**未编造任何等待记录**。
  共享渲染器 `snap_render.py` 仅对 429/503 做重试，其余失败如实记为失败。
- 服务端未返回 `Server-Timing` 头，200 响应亦无 `requestId`；相关字段一律记为 `null`
  并附说明，不臆造服务端计时。

## 5. 跨题工具与验证方法

以下方法在多题复用，构成本套的验证底座：

| 方法 | 作用 | 典型应用 |
|---|---|---|
| **参数化生成器 + 发射期断言** | 计算 → 断言 → 一次写出 DSL+JSON；数据错误在**发请求前**拦截 | A04–A09、B01–B06 全线 |
| **像素量测脚本** | 从最终 PNG 取像素，验证几何/颜色/落点 | A09、A15、A19、B04–B06 |
| **裁切放大复看** | 细粒度要求（共享段双身份、箭头方向、标签不重叠） | A08、A09、A13（×8 放大） |
| **接触表 / 缩略对比** | 批量回归；**不替代逐张完整看图** | A14、A24 |
| **定点像素探针** | 发现「渲染成功但内容缺失」的缺陷 | B06 case-10、A24 接缝透色 |
| **生成期几何断言** | 渲染前拦截重叠/恒值/越界 | A18、B04、B06 |
| **最小能力探针** | 未知能力先测后用，避免整图返工 | A18 Transform、B03 smcp、A21 服务诊断 |
| **离线边界量测** | 补 `FIT-WARN` 只看单框的盲区 | B05 `_audit8.py` |

**看图纪律**：每张成功响应都实际打开观察，不以 HTTP 成功当作质量通过。全套记录
**463 次实际看图**、**144 次完整视觉迭代**（看旧图 → 修改 → 新渲染 → 看新图比较）。
首版即达标的作品不制造凑数迭代——A12 四图、A22 r1/r3 等均在首版直接定稿并如实说明。

### 6.2 口径差异如实说明

### 6.3 质量判断的依据

「完成」的判断依据是**检查完成且缺陷已知项已处理**，不是渲染成功、文件齐全或数量达标：

- 每张最终图均在交付尺寸下实际打开观察；关键几何主张用**独立脚本重新取像素复测**
  （不引用当初的生成断言）；数据主张独立重算。
- 已知缺陷**要么修复后重新渲染复查，要么显式判定为可接受并写明理由**——例如 B06
  case-01 药点 ② 与已完成勾标擦边约 3px，放大复看后判定可接受（07:30 与 08:00 在 24 小时
  环上仅差 7.5°，勾标语义正确、字形完整可读），理由写入题内 `design-review.md §4.1`，
  而非默默留下。
- 未经验证的效果明确不作为结论：例如 B06 十件均未做用户实验，可观察改善（55 条）与
  未经验证效果（26 条）在 `problem-evidence.json` 中严格分列。
