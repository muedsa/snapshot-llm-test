| A01 保存的 `/fonts` 结果（复用，未重复请求） | `Noto Sans CJK SC`、`Noto Sans Mono CJK SC` | 标题/讲者用前者，K-id、日期、时间、状态文字用后者 |

**本次新确立的三条硬知识（全部由真实探针得出）**

1. **解析器不解码 HTML 实体。** 探针 `probe.entities.v2.png` 实测：`&lt;` 原样显示为 4 个字符，`&#60;` 同样原样显示；全角 `＜` 能显示但改变了原文；而 `&`、`>`、`“”`、`×` 直接原样书写即可正确渲染。`dslkit.Doc.text()` 的 `&lt;/&amp;/&gt;` 转义在本服务上是**错的**，A14 因此自建 `text_node()`，只在含 `<` 时改用 `<![CDATA[…]]>`。
2. **字面量 `<` 会直接 400。** 探针第一版里 `A < B & C > D` 触发 `{"code":"PARSE_ERROR", … "near: … >A < B & C > D</Text>"}`（错误体保留在 `probe/probe.entities.v1.png.failed.txt`）。
3. **实测字宽（72px，`probe.advances.v2.png`）**：CJK ≈ 0.99em、小写 ≈ 0.527em、大写 `A` ≈ 0.604em、数字 ≈ 0.546em、CJK 标点 ≈ 0.965em。断行模型取「非 CJK 0.60em + 空格 0.50em + CJK 1.00em」，比实测整串宽度高约 18%，实测最宽标题行 1042px < 可用 1120px，未发生一次溢出。

## 6. 设计选择、经验与未解决事项

**关键设计选择**

1. **一套常量 + 一个断行器**：8 张卡的页头高度、徽标行、标题区、分隔线、页脚 y 全部是共享常量；唯一随内容变化的是**标题字号**（96→36 阶梯）与**断行位置**。这既满足「不通过全局缩小整图适配长标题」，也保证 8 张看起来是同一套物料。
2. **标题在固定标题区内垂直居中**：1 行的 K01 与 3 行的 K08 都落在同一个 `[212,494]` 区域里，区域边界不随内容变化。
3. **状态三通道**：颜色 + 几何符号（○ ● ◐ ×）+ 文字，徽标同时给出同色描边、同色 10% 淡底与同色文字；页头下方再加一条 4px 状态色条。取消卡在此之上追加白底红框「本场取消」标签，标题与时间保持原样不灰化。
4. **断行器**：先求最少行数，再用动态规划最小化各行松弛平方和；叠加中文禁则（行首禁闭合标点、行尾禁开启标点）与破折号不可拆。K07 的「——」因此留在第一行末，K03 的「：」留在第一行末。
5. **字宽模型来自真实探针**，而不是猜：先渲染 72px 探针量测每个字符类，再按整串宽度校准。

**可复用经验**

- **该服务不解码 HTML 实体**：含 `<` 必须用 CDATA，`&` 与 `>` 原样写即可；通用 XML 转义库（如 `dslkit.Doc.text()`）在这里会画出 `&lt;`。
- 字面量 `<` 会让请求 400，错误体里有 `state [TAG_OPEN]` 与附近文本，`curl.exe` 能读到。
- 探针排版要按**行盒**（约 1.3×字号）而不是字号留行距，否则测量结果会被相邻行污染。
- 中文标题的自动断行，只做「贪心 + 均衡」还不够，必须加禁则，否则会出现行首标点与拆开的破折号。
- 拉丁字符在 `Noto Sans CJK SC` 里的实际宽度（0.53–0.60em）明显小于常见估计（0.75em）；高估会把标题逼成多余的行。

**未解决事项**

- K01「开始」只有两个字，即使取到阶梯上限 96px，版面上仍有较大留白；这是内容本身决定的，已按「极简但成型」处理，未额外添加装饰或用更大的字号破坏与其他 7 张的统一感。
- K06 的断行落在「为 / 什么」之间。中文允许任意两字之间断行，且 96px 下这是唯一满足禁则与宽度的均衡解；若日后允许更小的字号，可以整体排成「两张看似相同的图片，为什么 / 不能证明语义相同？」。
- 中间轮次的 DSL 文本未逐版留档（渲染 PNG 全部保留），见第 4 节末尾说明。
