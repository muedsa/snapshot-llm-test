## 3. 负轴与柱高（题面四条硬约束逐条验证）

| 约束 | 做法 | 证据 |
|---|---|---|
| 在**原图表区域内**增加负轴范围 | 绘图区仍是 `(160, 396, 750, 270)`，面板仍是 `(40,316,900,410)`，一个像素都没挪；只是比例尺由 `0..250,000` 扩成 **`−50,000..250,000`**（步长仍 50,000），零线由 `y=666` 上移到 **`y=621`** | `layout-map.json.regions.chart.plot` 与 round-01 完全相同；`scale = {ymin:-50000, ymax:250000, step:50000, zero_line_y:621, negative_range_added:true}` |
| 不得**裁掉**负值 | 柱从 `y(−5632)=626.07` 画到 `y(0)=621`，完整落在绘图区（底边 666）内 | 5× 放大图 `v2-negbar-01.png` 肉眼可见零线**下方**的琥珀短柱；`change-audit.negative_profit.clipped = false` |
| 不得**画成正值** | `profit_y = Y(0) = 621`、`profit_h = Y(−5632) − Y(0) = +5.07`，即从零线**向下**长；`change-audit.negative_profit.rendered_below_zero = true` | `layout-map.json.regions.chart.bars` 中 `2026-09.profit_below_zero = true` |
| 不得**只修数字不修柱高** | 每根柱高都由 `|value| / (ymax−ymin) × plotHeight` 反算，脚本再把 DSL 矩形高度与该期望值逐根比对，**最大偏差 0.0032px** | `change-audit` `problems = 0`；`layout-map` `regions.chart.bars[].profit_h` |
| 视觉回归：**主区域边界 ±2px** | 五块区域边界与 round-01 **完全相同（0px 偏移）** | `change-audit.visual_regression.max_region_delta_px = 0`（容差 2） |
| 视觉回归：**主字体与视觉系统** | 字体栈、页面/面板/墨色/柱色/网格色全部未改 | `change-audit.visual_regression.fonts_unchanged = true`、`palette_unchanged = true`、`bar_colors_unchanged = true` |

**为什么负柱只有 5px**：`−5,632` 相对 300,000 的量程只占 1.88%，在同一比例尺下就是 5.07px。
这是**共用同一零起点比例尺**的必然结果 —— 若为了显眼而单独放大，就等于给负值换了一把尺子。
因此额外加了红色标注 `2026-09 利润 -5,632` 与表格中的红色 `-5,632`，把「小」和「负」都明确交代给读者，
同时**柱色体系不变**（利润柱仍是琥珀 `#FFB020`，红色只用于文字）。

**未改内容（9 条，`change-audit.unchanged`）**：画布、五块主区域边界、主字体、配色视觉系统、
共用零起点分组柱图与比例尺步长、四 KPI 标签与口径、表格五列、2026-04..2026-09 六个月未被删改、
