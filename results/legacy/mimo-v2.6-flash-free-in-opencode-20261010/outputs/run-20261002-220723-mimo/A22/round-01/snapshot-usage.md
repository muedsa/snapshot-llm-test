## 7. 真实文档应用

* `A22-doc-000`（`requests.jsonl`）：用工具**实际重读**了 `https://open-snapshot.muedsa.com/ai-guide.md`，
  但**未发起新的 HTTP 请求** —— 该 URL 全套唯一一次真实 GET 是 `A21-doc-001`（200 / 846.4 ms / 3718 B），
  按总 AGENTS「缓存文件/原请求保留并引用，仅复用时不在后题重复计为新 HTTP 请求」归为 `shared-suite-cache`。
  因此本行起止时间、耗时、HTTP 状态一律记 `null`，**不伪造请求**；去重后全套仍只算一次文档访问。
* 由指南落实到本题的点：
  * 请求体是 **UTF-8 纯文本**而非 JSON，`Content-Type: text/plain; charset=utf-8`；
  * 根节点 `<Snapshot type="png">`，输出扩展名与实际编码一致；
  * 颜色用 CSS 语法（本题只用不透明 `#RRGGBB`）；
  * `fontFamily` 逗号分隔、名称必须与 `GET /fonts` 返回值一致 —— 本题用 `Noto Sans CJK SC` 与
    `Inter,Noto Sans CJK SC`，两者都在已取得的 `/fonts` 列表内；
  * 不臆造属性（未使用任何未见过的标签/属性）；
  * 非 2xx 是 `code/message/requestId` 的 JSON，429 参考 `Retry-After`（本轮无错误、无限流）。
* 未在本题新增 DSL 文档 HTTP 请求：A17/A11 的标签属性与字体缓存（`A17/tag-attrs.md`、`A17/doc-excerpts.md`、

## 9. 设计选择

1. **五块固定网格**：标题 / KPI 行 / 图 / 表 / 主结论，全部绝对定位且互不重叠 —— 这样 round-02 更正、
   round-03 加行时只需改内部内容，主区域边界可以一动不动（为后续 ±2px 回归约束做准备）。
2. **单一主色体系**：主色 `#5B4FE8`（净收入柱、徽标、KPI 短条）+ 琥珀 `#FFB020`（利润柱）+
   中性墨色阶，页面 `#EDEFF7`、面板 `#FFFFFF`，与本套其它 A 类任务一致。
3. **图表不加柱顶数值标签**：12 根柱加标签必然互相压叠，且表格已经给出全部精确值；
   图只负责形状与量级对比，精确值交给表 —— 这也是「仅根据实际数值成立的主结论」的取数路径。
4. **探针落在离字形 6px 处**：左对齐取框左缘外 6px，右对齐取框左缘内 6px（右对齐字形结束于框右缘、
   左邻列右对齐字形恰好结束于本框左缘，`x+6` 两侧都够不到字形），保证采到的是文字真正所处的背景层。
5. **负值配色预留**：`#DC2626` 已定义为「利润列负值 / 负值标注」专用色，本轮无负值故未触发 ——
   round-02 把 2026-09 算成负利润时会直接用上，不需要改视觉系统。
