# case-10 · 软木园等轴测导览图

- 作品名：软木园 COORKEN PARK 导览图
- 尺寸：1200 x 1200（售票处折页与入口立牌共用的方图）
- 主图：`final.png`（122860 字节）｜ DSL：`final.snapshot`（18865 字符）
- 主导手法：**`Transform` 16 元矩阵等轴测投影**（30°/30°，`K=0.8660254`、`H=0.5`）
- 最终轮次：round 5（1 张基线 + 3 次结构/语义修复 + 1 次语法修复 + 1 次图例补全）

## 受众与使用场景
刚进园区、站在售票处或立牌前的游客，0.4–1.5 米，可能手里还拿着折页。
任务是**三秒定位**：我在哪个角、要去的馆在哪、怎么走。
所以必须是**轴测**而不是平面图——平面图看不出"哪座楼更高"，而高度正是这个园子的识别特征。

## 使用者要完成的事
从图上确认入口在**西南角**（左下）→ 对着图例认出 5 座馆体的颜色
（儿童馆蓝 / 花房橘 / 主展馆金 / 观景塔紫 / 茶室绿）→ 找到树木与水景、草坪、步道
→ 读底部条拿到开放时间与闭园规则（10:00–18:00，闭园前 30 分钟停止入场）。

## 内容依据
自拟演示数据：虚构「软木园 COORKEN PARK」，6×6 地块、5 座馆体、5 棵树、
1 处水景，页脚 `入口在西南角 . 步道全长 1.4 km . 建筑高度按 3 层等比缩放`、
`等轴测 30° / 30° 投影`，右上与底部条两处 `DEMO . 演示数据`。
园名、开放时间、步道长度、馆体名称均为虚构，不指向任何真实公园。

## 主要视觉主张
**用一个矩阵把三维关系压平成可比的高度**：所有地面砖、左面、右面、顶面都由同一个
`Transform` 16 元变换算出（顶面是 `K/H` 菱形，两个侧面是按 `±K/H` 切出的平行四边形），
所以整张图的透视严格一致——这是"能比较"的前提。配色按**三面三色**给每座馆：
顶面最亮、左面最暗、右面居中，明度差就足够读出体积，不需要描边。
图例分三行（地面 / 展馆 / 绿化）**把图上每一种形体逐一键出**——这是本件反复修正的重点。
指南针只用一个圆 + 一个旋转后的圆角矩形做指针，与整体的几何语言一致。

## 实际使用能力
`Transform matrix="(...)"` 16 元列主序矩阵、`Positioned` + `Transform` 组合、
画家算法排序（`Sort-Object @{Expression = { $_.u + $_.v }}` 再按 `u`）、
三面三色的方块构造、`Rotate`（指南针指针）、圆角矩形、分栏图例。

## 完成标准（自定）
1. 全图**共用同一个投影矩阵**——不允许任何一块方块的倾角不一致；
2. 遮挡关系正确：前面的体块必须盖住后面的（画家算法按深度排序）；
3. **图例能解释图上每一种形体**：5 座馆 + 5 棵树 + 3 种地面全部有键；
4. 图例块不得与图形最高点重叠（需坐标核算，不接受"看起来没碰到"）；
5. 画面两处可见 `DEMO . 演示数据`。

## 实际自检与修改
- `B03-case-10-r1`（200，3668.2 ms，PNG 60654 B）→ 读图诊断出**两处结构性错误**：
  1. 脚本内 `$U` 与循环变量 `$u` **大小写冲突**，PowerShell 变量不区分大小写，
     导致 `$UNIT` 被写坏、体块比例全部失真；
  2. `IsoTop/IsoLeft/IsoRight` 的 `transform matrix` **带了与 `Positioned` 重复的平移**，
     双重位移把图形推飞。
- `B03-case-10-r2`（200，2883.6 ms，PNG 115917 B）→ 变量改名 `$U → $UNIT`，
  矩阵去掉平移项。比例恢复正常，但**塔身仍被后画的绿色方块盖住**：
  体块按数组原始顺序绘制，没有按深度排序。
- `B03-case-10-r3`（200，2967.7 ms，PNG 113583 B）→ 体块改为**单一数组并按
  `(u+v)` 升序、`u` 次序排序**后绘制；树从 `(0,0)` 移到 `(0,5)`（原位恰好落在
  馆体 `(1,1)` 的屏幕投影 `x520..680 / y379..522` 内，正确排序后会被完全遮死）。
  定点探针取色复核：塔身在 r2 取样 `#7FB07A/#7FB07A/#4F7A45`（被树色覆盖），
  r3 取样 `#C98A4A/#E9B978/#DCA464`（正确塔色）→ 遮挡关系修正，5 树 5 馆全部按深度渲染。
- `B03-case-10-r4`（200，4922.4 ms，PNG 120494 B）→ 首版图例**只列 3 项地面材质，
  画面却有 5 座馆体**，图例与画面不符 → 改为两行带键：
  地面（步道/草坪/水景）+ 展馆（儿童馆/花房/主展馆/观景塔/茶室），
  色块自 `x=140` 起步长 160、标签自 `x=72` 起宽 60。
- `B03-case-10-r5`（**400**，1987.3 ms，239 B）：第三条图例行写成
  `@(@('#7FB07A','树木'))`，PowerShell 的 `@()` 对**已经是数组的表达式原样返回**，
  外层括号被吃掉 → `items` 变成扁平字符串数组 → `items[0]` 是字符串，
  `[0]` 取到**首字符 `#`** → `PARSE_ERROR: color must be #RGB…`。
  改为 `@(, $treePair)` 强制保留一层数组。
- `B03-case-10-r5`（200，4040.7 ms，PNG 122860 B）→ 新增第三条图例行
  **「绿化 / 树木 #7FB07A」**（`y=300`，单项 `x140..294`）。
  坐标核算：图形最高点是馆体 `(1,1)` 的顶面 `x520..680 / y319`，与图例块
  `x72..294 / y300..326` **横坐标完全不相交** → 不重叠。
  读图确认三条图例齐全、指南针、页脚、底部条完好 → 通过。
- 尺寸核对：PNG 1200x1200 == DSL 首个 Container 宽高。
