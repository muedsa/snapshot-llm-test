## 2. DSL 构造方式

主体完全由 DSL 手工构造，无外部素材。生成脚本 `tmp/.../A20/gen-a20.ps1`（同一脚本负责求解、审计与发射），产物 `annotated-map.snapshot` 18,672 字节，118 个 `Positioned`、77 个 `Container`、42 个 `Text`。

### 2.1 坐标映射（不翻转）

```
px = 280 + x * 10.4        py = 920 - y * 7.6
主图区 left 280 / top 160 / width 1040 / height 760   →  右下 (1320, 920)
```

题面原话是「映射到像素时不要反转错误」—— 要求的是**反转必须做对**，而不是不许反转。屏幕像素 y 向下、逻辑 y 向上，因此 `py = 920 - y*7.6` 必然施加一次上下反转；关键是这次反转有没有施加正确、有没有顺手把数据镜像掉。所以 `label-layout.json.mapping` 不写一个含义含混的布尔值，而是给出**可复算的四角实测**（`corner_checks`，四个角都用与加载点位时**完全相同的表达式**算出，算完再断言，任一角对不上脚本直接抛错）：

| 逻辑 | 像素 | 期望主图区角 | 结果 |
|---|---|---|---|
| (0, 0) | (280, 920) | 左下 bottom-left | ✅ |
| (100, 0) | (1320, 920) | 右下 bottom-right | ✅ |
| (0, 100) | (280, 160) | 左上 top-left | ✅ |
| (100, 100) | (1320, 160) | 右上 top-right | ✅ |

同时落 `pixel_y_inversion_applied = true`、`pixel_y_inversion_correct = true`、`data_mirrored = false`、`inversion_note`（文字说明没做左右镜像、没把任一轴写反）。

> 早先版本这里写的是一行 `y_axis_flipped = true`。它本身不算错（说的是"像素行相对逻辑 y 反了"），但在「不要反转错误」这句要求旁边，字面读起来像"我们把它翻了"。交付前用上面的四角实测替换了它：**渲染字节完全没动**（`annotated-map-v10.snapshot` 与交付的 v09 SHA-256 同为 `278E38994752ECD3…`），`markers`/`center6`/`top3`/`label_style`/`leader_rule`/审计正文逐字节相同，只有 `generated_at` 与 mapping 块变化。早先的 v08/v09 产物全部保留，不覆盖。

y 轴在像素上向下、在逻辑上向上，翻转只发生在映射公式里，**点的锚点严格按位置算出，不为排版移动任何一个点**。逻辑原点、方向、量程、比例、翻转标记全部写入 `label-layout.json.mapping`。

### 2.2 图层顺序（正交分层，后画的压住先画的）

背景 → 主图区白底 + `2 SOLID #475569` 边框 → 内部 1/4 网格线 → 轴刻度短标 → **引导线** → 点环与点圆 → **标签底片 + 标签文字** → 标注文字。

这个顺序是"标签不遮点、网格被标签盖住"的关键：引导线画在点之前，所以线头伸到点心会被点圆盖掉；标签底片是不透明白底，所以被它压住的网格线自然消失，不需要额外挖洞。

### 2.3 标签与引导线

* 标签 `Noto Sans CJK SC`、`fontSize 20`（题目下限 20，取等值）、底片高 40、文字框 `top+6 / height 30`（20px 字行高约 29.2），`textAlign="CENTER"`。
* 宽度按字符估算：CJK 记 `fs*1.05`、ASCII 记 `fs*0.60`，再加 20 内边距 → 普通标签 146、M23 167。实测最宽的 `M23 研究所 90` 估算 167 而真实字宽约 131，余量充足，`textAlign` 居中后不会溢出。
* 自作贪心求解：按"离图心距离"降序放点，候选方向 N/S/E/W/NE/NW/SE/SW × 间距步进，先要求"≤24px 且本点明显最近"（不需要线），不满足再落回"带引导线"的候选；越界、压标注框、压非本点、标签互相 < 6px 一律拒绝，超阈值后按 `PENALTY` 表放宽重试。
* 引引导线**只走正交折线**（L / Z 形），因为 DSL 没有线段元素、只有不带旋转的 `Container`；本版 4 条线里 2 条是单段直连（锚点与点恰好同 y 或同 x，折点退化）、M08 与 M18 各带 1 个可见折弯。折线候选是全量生成的，按"穿过标签数 → 穿过非目标点数 → 交叉数 → 长度"排序取最优，所以折弯只在真正有用时才保留。

## 7. 本题踩坑小结

1. **`r` 是默认别名**（`Invoke-History`），别名优先级高于函数 —— 任何叫 `R`/`r` 的辅助函数都会被静默顶掉，报错还是"缺一个能接收 '160' 的位置参数"这种毫不相关的文案。已把三个短名 `F`/`R`/`T` 全部改成长名并保留 `trap` 报行号。
2. `if ((Fn ...) -lt $x)` 必须给函数调用加括号，否则 PowerShell 报 `Missing statement block after if ( condition )`。
3. `New-Object Type(args)` 不是构造器写法，要用 `[Type]::new(...)`；`Graphics.DrawImage` 的 `Rectangle` 与 `RectangleF` 重载不能互转，源矩形必须是 `Rectangle`。
4. DSL 没有线段元素，引导线只能用 2px 厚的 `Container` 拼正交折线；因此"折弯"天然免费获得，而"斜线"根本画不出来 —— 设计时就把折线路由做成首选项。
5. 并行 `read` 读图可能串缓冲区；涉及精确几何的结论一律回到像素测量，不靠肉眼。
6. 标签底片用不透明白底 + 画在网格之后，可以让网格线"自动"被标签挡住，省掉所有挖洞运算。
