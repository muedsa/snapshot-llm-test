## 3. 设计选择与关键数据

### 3.1 12 个几何单元

全部为 60×60 `RECTANGLE`、`borderRadius=6`，7 种颜色，6 帧完全一致（数量 / 颜色 / 尺度零差异）：

| id | 角色 | 最终位置 (x,y) | 颜色 |
|---|---|---|---|
| u01 | roof-eave-1 | (150,240) | `#5B4FE8` |
| u02 | roof-eave-2 | (210,240) | `#5B4FE8` |
| u03 | roof-eave-3 | (270,240) | `#6E63FF` |
| u04 | roof-eave-4 | (330,240) | `#5B4FE8` |
| u05 | roof-eave-5 | (390,240) | `#5B4FE8` |
| u06 | roof-apex | (270,180) | `#8A7DFF` |
| u07 | wall-top-left | (210,300) | `#2DD4BF` |
| u08 | window | (270,300) | `#38BDF8` |
| u09 | wall-top-right | (330,300) | `#2DD4BF` |
| u10 | wall-bot-left | (210,360) | `#22B8A6` |
| u11 | door | (270,360) | `#FF8A3D` |
| u12 | wall-bot-right | (330,360) | `#22B8A6` |

末帧关于 **x=300 严格镜像对称**；中部横条 300 px 比下方主体 180 px 左右各出挑 60 px；顶部尖块与底部橙色门块落在同一中轴。题面只要求「末帧构成可识别图形」，实际可读作「宽屋檐带尖顶的小屋」，也可读作「张开双臂、头顶有冠的人形」，`frame-data.json` 的 `final_figure.readings` 已如实并列两种读法，不锁死为单一物象。

### 3.2 轨迹（核心设计选择）

- 公式：`p(t) = start + (final - start) * t`，`t = (frame_index - 1) / 5`，坐标四舍五入到 2 位小数（t=0 / t=1 保留精确端点）。
- 逐帧最大位移 **30.45 / 30.46 / 30.45 / 30.46 / 30.45 px** —— 五步几乎完全相等，即**匀速直线**，轨迹连续、无跳变。
- **起始布局不是拍脑袋定的**：`design-a23.ps1` 用 `start_i = 画布中心 + s_i · unitvector(final_i − 中心)` 的径向分散形式，seed `20261005` 随机搜索 **400 000** 组半径，只保留同时满足「**101 个 t 采样 × 66 单元对全部不重叠**」与「完全在画布内」的 **3828** 组，再取 frame-01 最小圆心间距最大者 → **103.57 px**。
- 最终 frame-01 散布范围 x[42.32..574.06]、y[58.49..572.27]，**最小圆心间距 103.56 px > 单元边长 60 px**，两两不接触，读作「12 个散布满画布的方块」，聚合后的图形只在末帧出现。

### 3.3 为什么不宣称无缝

`frame-06 → frame-01` 平均跳变 **104.3 px**，而正常相邻帧步长 **30.5 px**（约 3.4 倍），首尾不连续。因此 `timing.json` 里 `seamless = false`，并写明「循环播放时会从 frame-06 跳回 frame-01，出现可见跳变」。若要真正闭环，需要增加反向回程关键帧，但那会破坏「末帧构成可识别图形」，故本交付主动选择不闭环，并给出对应数据而不是含糊带过。

## 4. 实际问题、修复与验证

### 问题 1（v01 → v02，几何）单元在飞行途中互相压盖

- **怎么发现的**：`inspect-a23.ps1` 发现不透明像素抽样数在 3441~4731 间大幅波动；`overlap-a23.ps1` 定位到起始布局用「半径 235 的均匀圆环」时，单元在中段互相穿过。
- **量化**（用同一套最终几何重算，可复现）：

  | 帧 | t | 重叠单元对 | 重叠面积 |
  |---|---|---|---|
  | frame-01 | 0.0 | 0 | 0 |
  | frame-02 | 0.2 | 1 | 21.6 px² |
  | frame-03 | 0.4 | 2 | 826.7 px² |
  | frame-04 | 0.6 | 8 | 5 306.1 px² |
  | frame-05 | 0.8 | 14 | 14 124.7 px² |
  | frame-06 | 1.0 | 0 | 0 |

  合计 25 对；101 个 t 采样 × 66 单元对 = 6666 个样本中命中 **596**。
- **为什么要较真**：被压住的单元在画面上会「消失」，直接违反题面「单元轨迹连续、**无突然消失**」。
- **修复**：改用 §3.2 的径向分散搜索 + 生成器内建 6666 样本硬校验（不通过就写入 `problems` 并拒绝交付）。
- **验证**：`problems = 0`；6666 样本命中 **0**；6 张交付帧重叠对 **0**；不透明像素抽样数收敛到 **4595~4716**。

### 问题 2（v02 → v03，文字）封面页脚末字被吞

- **怎么发现的**：用图像查看器打开封面时看到页脚写成「…1200×800 RGB 封」。
- **量化**：fs26 时该行墨迹 x[73..1110]，容器可用到 x=1128；补上「面」需要约 1064 px > 1056 px，超出即折行，而容器高 42 px 只放得下第一行，第二行被裁掉。
- **修复**：`fontSize` 26 → 24（整行 → 975 px，留 81 px 余量）；同时把分镜之间 24×24 的灰色圆角方块占位改成 `<Text>「→」`，表达 01→03→06 的方向。
- **加护栏**：生成器新增单行文本宽度检查（全宽字 1.0 em、其余 0.52 em，比例来自两次真实渲染的实测标定），9 处封面文本全部参与，超框即记 `problems`。
- **验证**：页脚第一行墨迹 x[73..1047]、宽 975 ≤ 1056；末三个字形游程 `982..994(B)`、`1001..1023(封)`、**`1026..1047(面)`** ——「面」确实画出来了；推进标记的逐列墨迹图呈现「水平杆 + 向右收口的头部」，确认是 `→` 而非豆腐块。6 张帧的 `.snapshot` 与上一版字节一致（0/6 变化），因此**没有重新渲染帧**，避免无意义请求。

### 问题 3（v04，工具）图像查看器返回陈旧缓冲

- **现象**：连续 13 次图像 `read` 返回了**别的文件**的像素（读 `frame-03` 却返回封面对照图；连全新生成的 200×120 纯色诊断图也返回 `frame-01`）。`browser.preview` 因桌面浏览器未连接同样不可用。
- **处理**：① 用换文件名重试，观察到查看器最终恢复；② 在恢复前，对所有关键结论改用**不依赖查看器**的第二条证据链 —— GDI+ 逐列字形游程扫描 + `ascii-a23.ps1` 点阵成像（直接采样真实像素）。
- **结果**：查看器恢复后，**6 张最终帧逐张单独打开 + 最终封面 + 接触表**均确认为真实像素；两条证据链结论一致，此前的几何 / 格式结论未被该故障污染。

### 过程偏差（如实记录）

- attempt-01 的 7 张服务原始 PNG 已归档到 `tmp/…/A23/attempt-01-ring/`；但归档时只拷了 PNG，其 `.snapshot` 随后被生成器**原地重写**，因此 attempt-01 的 DSL 文本未能保留。这是本任务唯一一次「先覆盖后归档」，已在 `iterations.jsonl` 的 `a23-v01.note` 中记录。
- attempt-01 版本只做了程序化解析（GDI+ + 几何），**没有用图像查看器打开**；后续每个版本都配了真实看图。该情况也已记入 `a23-v01.observed_problems`。

3. **过程偏差**：attempt-01 的 `.snapshot` 未归档即被重写（见 §4）。
4. **工具故障**：图像查看器一度返回陈旧缓冲，已通过重试 + 双证据链规避；后续任务如复现，建议沿用 `ascii-a23.ps1` 的文本点阵方式兜底。
