## 0. 选题方法

观察真实生活中"信息难理解 / 难比较 / 难找到 / 难采取行动"的时刻，挑 10 个：

1. 问题必须**在货架前、报告前、站台上、被窝里**真实发生过，而不是编造的痛点；
2. 每个问题要能写清"用户原本卡在哪一句 / 哪一个数"；
3. 重构后必须给出**可观察的改善**（少几跳、少几次心算、少几个必须记住的词），并把"未经用户实验验证"的部分单独标出；
4. 十件必须在**媒介、画幅、结构骨架、配色系统**上互不重复 —— 不允许"同版式仅换色/换字"。

## 3. 数据与声明纪律

- **能查到的就查**：阶梯电价档位口径、药品说明书与用药指导要求、体检报告参考区间、信用卡分期费率换算、租赁押金退还、降水概率定义、快递服务时限、路内停车计费、明码标价比价、地铁列车到站预告 —— 每个都做真实抓取，进 `requests.jsonl`。
- **查不到或不确定的**：不写法条号、不写具体罚则金额、不写"国家规定"，只写产品化的解释规则并标注"演示规则 DEMO"。
- **自拟案例**：楼栋、药名、金额、班次、快递单号、超市商品全部标 `DEMO` 或 `样例`；不做真实背书，不引用不存在的调研。
- **明确区分**：可观察的改善（条目数、心算次数、视线跳数、字数）写进 design-review.md 的"可观察"节；未经用户实验验证的（更快、更放心、更愿意照做）单独写"未验证"节。

## 4. 执行顺序

1. `fetch-b06.ps1` 真实抓取研究资料（docs 复用同套文档请求 + 研究请求），写 `requests.jsonl`
2. `calc-b06.ps1 → calc-b06.json`：所有数字先算好（单价换算、分档增量、年化换算、扣减瀑布、到件时间窗）
3. `lib-b06.ps1`：本题绘图库（按需，各件骨架差异大，公共部分尽量少）
4. `gen-b06-a/b/c.ps1`：01–04 / 05–07 / 08–10 分段生成，带文本越界守卫与属性校验
5. `render-b06.ps1` 真实渲染 → 逐张 `read` 看图 → 缺陷记录 → 修 → 重渲染 → 再看（无固定轮次上限）
6. 逐件 `case.md`，输出根 `portfolio.json/md`、`gallery.html`、`snapshot-usage.md`、`task-metrics.json`，另加 `problem-evidence.json`、`design-review.md`
7. 整体最终审查：独立性、完整性、关系是否适合 TASK.md
