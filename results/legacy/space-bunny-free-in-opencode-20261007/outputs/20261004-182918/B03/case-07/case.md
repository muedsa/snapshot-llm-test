# case-07 · 叠印配方单 · 四色

## 场景与受众

- **受众**：虚构印厂「文盛印务」的机长（看叠印梯与矩阵）与调墨工（看墨量与
  叠印顺序）；页面是给机长的**配方单**，不是给客户看的效果图。
- **使用场景**：开机前 5 分钟，机长要确认三件事——四色叠在一起会变成什么颜色、
  青/品交界要不要做陷阱、每一版占多少墨量。
- **用户要完成的事**：按配方单核对印版，确认 TAC 与叠印顺序，决定青品交界做
  0.3 pt 陷阱、黑版不参与交界。
- **观看环境**：印厂控制室，屏幕上并排对比色块，色差 1 px 都要看得出来。

## 内容依据

- 商户、工单号、印厂、成品尺寸、出血、陷阱值：**自拟演示值**，页脚已注明。
- **墨量（TAC）按画面几何实算**：版面分成三个矩形区域，每区列出它的版序，
  每版面积除以总面积 → Y 100%、C 40.9%、M 40.9%、K 18.2%，TAC 合计 200%。
- **12 个交点颜色全部从服务返回的 PNG 上采样读回**（PIL 读像素），不是取色器
  估算，也不是我手填的。

## 视觉选择与探索的能力 + 一个必须写下来的发现

先用 `tmp/20261004-182918/B03/probes/probe-c07-blend.png` 做了**决定性实验**：
子节点画青色实心方块，`ColorFiltered(color=品红, blendMode=MULTIPLY)` 包住它。

> **结果渲染成深藏青（C×M），不是纯品红。**
> 也就是说 `ColorFiltered` 的 `color` 是和**节点自己画的像素**混合，
> **不是**和背景混合。

这条把整件作品的实现推翻重做了一次（见迭代记录 v3），也是本套里最重要的
一条 DSL 语义。它同时给出两件事：

| 手法 | 用在哪 | 实测结论 |
|---|---|---|
| `ColorFiltered(color=X, blendMode=MULTIPLY)` 包住「画成 under 色的子节点」 | 叠印梯的每一个色块、12 个交点、陷阱演示的两块版 | 结果 = under × over（逐通道 sRGB，四舍五入）。**这是减色叠印的算术** |
| 十二种 `blendMode` | 探针第 2 行 | MULTIPLY/SCREEN/OVERLAY/DARKEN/LIGHTEN/PLUS/DIFFERENCE/EXCLUSION/HUE/SATURATION/COLOR/LUMINOSITY **全部可用且各不相同** |
| `blendMode="ADD"` | 单独一次探针 | **不存在**：`400 PARSE_ERROR: No enum constant org.jetbrains.skia.BlendMode.ADD` |
| `ColorFiltered` + 透明子节点 | 探针第 3 行第 2 格 | MULTIPLY 会把透明区**染成滤镜色**（FAQ 里说的 tint transparent gaps 属实） |
| `ColorFiltered color` 必填 | 探针第 3 行 | 写 `color=None` 是 `400 Attr [color] must not be null` |

**关键的对称性验证**：C×M 与 M×C 渲染出来完全相同（都是 `#000083`），
这正是减色叠印该有的性质；如果服务做的是背景混合，这两格必然不同。
12 个实测值：C×M `#000083`、C×Y `#00A500`、C×K `#00131A`、M×Y `#EC0000`、
M×K `#19000F`、Y×K `#1B1A00`——与逐通道乘法完全一致。

## 迭代过程（实际看图记录）

1. **v1**：按「ColorFiltered 能读背景」的假设做了一版海报叠印效果。看图发现
   `ColorFiltered(color=M, MULTIPLY, Container(color=M))` 渲染出的是
   **M×M（#DA004D）** 而不是「M 压在青上」。→ 意识到语义假设错了。
2. **v2**：用探针做决定性实验（子=C、滤=M、MULTIPLY）确认是子×滤。
   同时发现 v1 的矩阵格把两版**并排**画了，根本没重叠——修成「下版满格 +
   上版盖右半」。
3. **v3**：按 `over(under, over_ink)` 重写。为了让叠印梯的每一块都恰好是
   一次乘法，把版面从「圆 + 斜矩形 + 横条」改成**三个轴对齐矩形区域**
   （顶带 Y+K / 左下 Y+C+M / 右下 Y+C），这样每个区域的 under 都是纯色。
4. **v3**：梯子四格原本 220 px 宽却按 180 px 步进，互相压在一起；改为
   归一化坐标 + `SQ=168` 后四格独立；梯子下方的陷阱区与说明整体上移。
5. **v4**：矩阵 96 px 格导致最后一行压住说明文字 → 收到 88 px。

## 遗留 / 不足

- **陷印（trap）只是画出来的示意图**：DSL 能在画面上标出 0.3 pt 的让位，
  但真正的陷印是印前文件里的一条扩张轮廓，本服务做不到，页面已写明。
- MULTIPLY 是逐通道 sRGB 乘法，不是分色叠印的专业模型（真实叠印要考虑
  纸张、墨层厚度、总墨量限制与陷印），本单只做颜色算术这一层。
- 灰梯尺按 `1 − 0.075v` 线性生成，不是印厂 GCR 曲线。
- 没有做 ICC 特性化：`#FFF200` 这类 Pantone 近似值直接当作 sRGB 使用。
