# case-04 · 舞台透视 · 演出座位选座预览

## 场景与受众

- **受众**： fictional 演出《夜航》在「潮汐音乐厅」的购票观众；页面出现在
  选座流程的第二步，桌面浏览器 1500×1100。
- **使用场景**：观众要先看懂「舞台在哪、我在哪一层、我的座位离舞台多远」，
  再决定要不要换到中区或前区。
- **用户要完成的事**：找到 B 区 05 排左区，确认 24 号还空着，付钱。
- **观看环境**：桌面显示器、明亮办公室、鼠标操作，可滚动可缩放（这里只交付静态帧）。

## 内容依据

演出、场馆、场次、订单号、持票人、座位号与票价全部为**自拟演示值**，页脚已注明。
票价 A ¥680 / B ¥480 / C ¥280，26 座一排（8+10+8），10 排，A3+B4+C3。

## 视觉选择与探索的能力

主打**Transform 的 4×4 列主序矩阵**。先用
`tmp/20261004-182918/B03/probes/probe-c04-transform.png`（12 格，每格只改矩阵，
红框是变换前位置）逐项验证：

| 手法 | 用在哪 | 实测结论 |
|---|---|---|
| `matrix` 16 个浮点、列主序 | 全部 | 必填；不写 `rotate` 属性，旋转必须自己算 |
| `rot θ`（屏幕 y 向下，正值为逆时针） | 主视角 −3°、缩略图 +22°/−14° | 与 `probe 02` 一致 |
| `skewX` / `skewY` | 「俯视：斜切 16°」缩略图 | 出平行四边形 |
| `m[2][3]` 透视项 | 主视角 0.0004、缩略图 0.002/0.006 | 有真实效果，但表现更像**前缩 + 侧向切变**，不是干净的梯形收缩；数值越大越强 |
| `scale sx, sy` | 探针「scale 1.5x / 0.6y」 | 非等比缩放生效 |
| 矩阵内平移 | 探针「矩阵内平移 (24,14)」 | 可替代改 left/top |
| `origin` + `alignment` | 探针「origin=(60,0) · alignment=CENTER」 | 旋转中心可挪；不写 `alignment` 时绕子节点左上角 |
| `Stack clipBehavior="NONE"` vs `"HARD_EDGE"` | 探针第 3 行第 3/4 格；主视角内部每排 | 变换后的角在 NONE 下会露出来，HARD_EDGE 会切掉 |

### 真正的几何在 Python 里，不在矩阵里

把整份座位图交给矩阵去「透视」是不够的（DSL 的矩阵没有路径、没有 3D 相机）。
所以我先用**标准针孔投影**在 Python 里把 10 排的位置和行高算出来：

```
s_i = F / (F + z_i),  z_i = z0 + i·Δz,  F = 3.2
行宽 = (W − margin) · s_i          ← 越远越窄
行高 = base · s_i ，base 由盒高反解  ← 保证一定填满给定盒子
```

`plan(w, h)` 因此**任何尺寸都能填满**，主视角和四个缩略图调用的是同一个函数、
同一组 `z_i`，只是外面套了不同的矩阵。四个缩略图因此不可能和主视角对不上——
这是本页真正的设计手法，矩阵只是最后一步修饰。

## 迭代过程（实际看图记录）

1. **v1**：主视角矩阵里透视项给到 0.0021，整张图被甩到左上角并出血；
   缩略图因为 `bw = (w−120)·s` 在 145 px 宽的盒子里算成 25 px，排缩成一列小点。
   → 行距未计入 `label_h` 导致标签互相压；`margin` 改为自适应；透视项降到 0.0004。
2. **v2**：行标签仍然压住上一排 → 发现 `y += rh + gap` 漏了标签高度，
   改成 `y += rh + gap + label_h`。
3. **v3**：主视角仍有明显的斜切感（`m[2][3]` 的表现更像切变而非梯形）→ 旋转由
   −4.5° 降到 −3.0°、透视由 0.0006 降到 0.0004，让透视感主要由几何承担；
   「确认选座」按钮被面板裁掉 → 上移并压缩。
4. **v4**：复查四个缩略图，确认「正视 / 斜视 / 俯视斜切 / 强透视反向」四种矩阵
   在同一份几何上产生了肉眼可辨的差异，且都没有出血。

## 遗留 / 不足

- `m[2][3]` 表现偏切变，真正的梯形收缩由 Python 侧的针孔投影提供；这一点已写在
  页面与本文件里，没有假装矩阵能做相机。
- 主视角每排是独立矩形，左侧收分形成阶梯状边缘；在真实票务产品里通常会用
  一条路径一次成形，DSL 没有路径图元。
- 只交付静态帧，未做交互（点选、缩放、滚动）与无障碍焦点顺序。
