# case-10 · 日照剖面研究墙 · 青屿书院实验楼

## 场景与受众

- **受众**：虚构项目「青屿书院实验楼」的建筑师与报建审图员。成果是一张钉在
  工作室墙上的 A1 分析墙（这里按 1600×1150 出图），以及同一张图投到评审会屏幕。
- **使用场景**：冬至是审图最关心的设计日。四个人要在图前同时回答四个问题：
  太阳从哪边来、什么时候照到、进屋能照多深、明年一年里最差和最好各是多少。
- **用户要完成的事**：指着方位角色带确认「冬至 118° 升、242° 落，南向偏东」；
  在剖面上确认四层窗台标高；读逐时表确认 09:00 高度角 20.4°、进深 4.03 m；
  用月条确认 12 月昼长 9.97 h 是全年最差。
- **观看环境**：墙面远观 2 m（所以每个数字都在 10 px 以上并配大字块），
  评审时近看 60 cm。

## 内容依据

场地、纬度 31.23°N、窗台 0.90 m、窗顶 2.40 m、单侧进深 6.00 m、4 层 × 3.15 m：
**全部为自拟的演示值**，页脚已注明。

日照几何是**真实计算**，不是编的：

```
赤纬     δ(n)   = 23.45° · sin(360° · (284 + n) / 365)        （Cooper）
高度角   sin α  = sin φ·sin δ + cos φ·cos δ·cos ω,  ω = 15°(t − 12)
方位角   A      = atan2( −cos δ·sin ω,  sin δ·cos φ − cos δ·sin φ·cos ω )
日出日落 cos ω₀ = −tan φ · tan δ  →  t = 12 ∓ ω₀/15
日照进深 p      = min(6.00, 1.50 / tan α)                        （南向窗带）
```

天穹上三条日轨、方位角色带的两端、逐时表的 7 行 5 列、剖面的进深条、
12 个月的昼长条与「最短 9.97 h（12 月）／最长 14.03 h（6 月）／年较差 4.07 h」，
全部出自这五个函数，因此互相不可能对不上。

## 视觉选择与探索的能力

主打**自适应排版族**，而且是「内容真的需要等分」的地方才用，
不是拿来装饰。先在 `tmp/20261004-182918/B03/probes/probe-c10-flex.png`
八行探针上验证，并在 `probe-c10-readback.txt` 里用 PIL **从返回的 PNG 上
读回像素边界**与 Python 的 flex 算术逐像素对照：

| 手法 | 用在哪 | 实测结论（括号内是读回值） |
|---|---|---|
| `Row` + 12 × `Expanded(flex=1)` | 「十二个月昼长」的 12 根柱子 | 份额算术精确（探针第 ① 行：1200 px 容器、flex 1+1+2+1 → unit 240，读回 RED[40,279] GREEN[520,999] BLUE[1000,1199]） |
| `Row` + 7 × `Flexible(flex=1, fit="LOOSE")` + `FractionallySizedBox` | 剖面右侧每层的 7 根进深条 | LOOSE 子节点拿到的是份额内的**松约束**上限，所以 FSB 的 widthFactor 才有意义 |
| `FractionallySizedBox widthFactor/heightFactor` + `alignment="CENTER_LEFT"` | 进深条 | 条长 = p / 6.00，与房间进深同尺度；换任何进深都不会画出轨道 |
| `AspectRatio` | 右上「三个代表日的日轨」三张 1:1 极坐标缩略 | **先按宽度试，放不下才回退高度**：父盒 300×180 里 ar=1 得到 180×180 而不是 300×300（读回高度 168 / 180 / 180 / 180） |
| `mainAxisSize="MIN"` / `"MAX"` | 探针第 ② 行 | MIN 时 Row 只占 250 px，MAX 占满 600 px |
| `mainAxisAlignment` 六值 | 探针第 ⑤ 行 | 读回首块偏移 0 / 160 / 80 / 0 / 40 / 54，与 Flutter 语义一致 |
| `IndexedStack index="0"` | 三个代表日的三页 | 只有 index 那一页被画；子节点仍全部参与布局 |
| `Align` / `Padding` / `widthFactor` | 探针第 ⑧ 行 | `Align widthFactor=2 heightFactor=1.5 + Padding(6,10)` → 自身 240×39 |
| `SWEEP` + `gradientStops` **当坐标轴用** | 方位角色带 | 用 stops 把「冬至白昼窗口」直接刷到 0–360° 的方位轴上：日出 118°、日落 242°，色带的亮区边界与天穹上那条日轨的首尾点一致 |
| `Stack fit="EXPAND"` 的真实代价 | 全页 | 非定位子节点会被拉满 Stack、`width/height` 失效；这页每一个矩形都包在 `Positioned` 里 |
| `ClipOval` | 冬至正午的日轮 | 唯一能拿到正圆裁剪的地方 |
| `Transform` 列主序 4×4 | 左侧 12.60 m 竖向尺寸线的竖排文字 | 复用 case-04 已验证的旋转矩阵 |

## 迭代过程（实际看图记录）

1. **v1**：`daylen()` 里把 `acos()` 的**弧度**当角度用（漏了 `degrees()`），
   12 个月昼长全变成 0.24 h → 柱高算出负数 → 400
   `minHeight must be between 0 and maxHeight`。改成
   `2 · degrees(acos(−tanφ·tanδ)) / 15` 后得到 9.97–14.03 h 的合理区间。
2. **v1**：`lo/hi` 设成 10.4/14.2，12 月的 9.97 h 仍然落在下界外 → 柱高为负，
   同样 400。→ 改 9.8/14.2。
3. **v2**：`FractionallySizedBox` 直接作为 `Row` 的子节点 → 400
   `widthFactor needs a finite maximum size`（Row 给非 flex 子节点的是
   **无界**宽度）。→ 每根条包一层 `Flexible(flex=1, fit="LOOSE")`。
4. **v3**：看图发现剖面被压成 12 px 高的一条线——我把「米」直接当成了「像素」
   （层高 3.15 px）。→ 引入 `SCALE = 17 px/m`，四层 214 px，窗带 25.5 px，
   并补上 1 px = 0.0588 m 的比例注记。

   Python 端 `TypeError: sequence item 153: expected str instance, list found`。

6. **v3**：太阳光线从建筑右上角往右上画，长度 130 px，**压穿了右侧进深条的标题
   与第一行**。→ 起点贴到建筑边缘、长度收到 96 px，说明文字移到地面线下方。

## 遗留 / 不足

- **日照模型只有几何，没有遮挡。** 没有做邻栋遮挡、地形反射、
  玻璃透光率与室内反射，所以「进深 4.03 m」是纯几何上限，
  实际房间会更短。这一点写在页脚与面板注释里。
- **只画了冬至 / 春分 / 夏至三个代表日**，没有出 24 个节气或全年 8760 小时的
  热力图。DSL 里做全年热力图会撞到 4096 元素上限（case-06 实测过）。
- **`IndexedStack` 在静态交付里等于单页。** 三个代表日的几何同源是可验证的，
  但「切换」这个行为本身不在交付范围内，页面上已明确写出。
- 时区用的是**真太阳时**，没有做经度时差与均时差修正，所以表里的 12:00 不等于
  北京时间的 12:00。这在设计日照分析里是常规做法，但容易被误读，已在
  面板里标注「真太阳时」。
- 场地纬度、窗洞尺寸与层高是虚构的；赤纬、时角、日出日落公式是真实的。
