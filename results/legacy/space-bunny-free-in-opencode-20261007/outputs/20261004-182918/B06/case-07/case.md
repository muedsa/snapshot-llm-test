# case-07 · 差 5 元跨过门槛，能省 25 元；多买反而更贵

- **成品**：`final.png`（1720 × 1080，服务返回的原始响应字节，未做后处理）
- **DSL**：`final.snapshot`（与上面这张 PNG 同一次渲染的完整 DSL，可直接复现）
- **媒介与观看环境**：下单前的横向决策页，鼠标或手指停在结算按钮之前。

## 1. 用户原本卡在哪里

满减规则让「折扣率」变成一条锯齿：同一张券，只差几元跨过门槛，到手价会突然便宜一截；不跨门槛时买得越多反而越贵。所以「满 200 减 30，到底是优惠前还是优惠后满 200」这种问题，消费者自己算不清。

- **受众**：大促期间一次下单 3–6 件日用/服饰商品的普通网购用户。
- **希望他完成的事**：把折扣率随购物车金额的变化画成一条能直接读的锯齿线，并算出每个门槛那一格的最优凑单点与超出后的浪费。

## 2. 原来的信息问题，和这张图怎么解决它

上半是折扣率锯齿：横轴是优惠前金额，纵轴是实际省下的比例。深红竖墙是三道满减门槛，每道墙右上角标着超过它的 60 元全按原价走（浅红底）；紫色竖线是「每满 300 减 30」的台阶，300 / 600 / 900 / 1200 / 1500 各触发一次。绿圈标出三个最优凑单点 199 / 299 / 399 元——注意是门槛那一格本身，再多花 1 元就已经按原价走。下半把同一套规则套进一个 3 件 395 元的购物车，四个场景并排，最后一栏给出结论。

## 3. 视觉选择解决了什么

只有两种强色：深红代表『你亏了』（墙与它后面的平价区），紫代表『另一套规则』，粉红代表『划算的那几格』。绿只留给最优凑单点，因此三个绿圈在整页里是最先被看到的。

## 4. 实际自检（逐条对照最终图核对过）

- 锯齿的每个拐点与规则表逐条对应：199−25 / 299−50 / 399−80 / 每满 300−30 / 600 叠加 / 封顶 300
- 四个场景由同一 pay() 算出：直接下单 315、加 5 元 290、加 55 元 340、硬凑到 600 得 460
- 最优凑单点落在 199 / 299 / 399 本身；399 的折扣率 27.6% 高于 400 的 27.5%，所以图上明确写『门槛那一格最便宜』
- ② 与 ③ 的编号不再重叠（旧的 299 与 300 两道墙只差 1px，编号会叠在一起）
- 金额标签全部整数、不再出现 200.0 元，也不再被墙线穿过
- 真实投诉按海报新闻原文：500 元 9 折券与 300+400 同下单时 300 元那件只减 21.43 元、实际成交 278.57 元，比单独买 270 元更贵；规则表声明为自拟演示

## 5. 取舍与不足

把『每满 300』从编号里拿出来、只留颜色，是这一版最重要的取舍：它原本是 ③，但它的竖线落在 299/300 之间，会把 ② 压掉。改成只用紫色表示这一族之后，四个编号墙互不干扰，代价是读者要靠底部那行紫色说明才能知道紫色代表什么——所以那行说明写得很长。
