## 如何避免长标题与新增信息碰撞（本轮核心问题）

不是靠"看起来没问题"，而是靠四个可复核的手段：

1. **手工断行，不依赖自动换行**。标题是逐行 `Text` 元素，断点选在真实标点处（冒号后、以及
   "让复杂信息变得清晰 / 的结构化方法" 的语义边界）。每个 `Positioned` 都**不给宽度**，因此
   `softWrap` 在结构上不可能把一行折成两行——这正是 DSL 手册里"静默丢字/静默换行"的根因。
2. **行宽按实测留余量**。竖版栏宽 912px，最宽标题行实测墨迹 776px → 余量 136px；横版栏宽
   628px，最宽行实测 539px → 余量 89px。余量为正，就不存在"为了塞进去而压字"的压力，
   也就没有用变形或负字距的必要。数据写在 `content-map.json → measured_collision_evidence`。
3. **纵向分层 + 专属保留带**。竖版顺序是 主标 → 品牌小标(32) → 标题两行(52) → 分隔线 →
   信息卡；两条新增文案落在卡片自己的行里（第 1 行右端、第 2 行右端），与标题不同行、
   不同块。横版则把两条新增文案放进分隔线下方的专属两行，再下面才是整宽事实条。
4. **像素级复核**：最终图与"去掉 Text 层的同构图对照图"做差分，每个变化像素归属到最近的
   声明墨迹框，得到每条文案的真实墨迹框；然后
   - 逐条检查真实墨迹框是否越出声明框（允许 6px 抗锯齿边缘）；
   - **两两检查所有文案墨迹框是否相交** → 结果 **0 处相交**；
   - 未归属到任何文案的变化像素 → **0**。
   竖版 11 条、横版 12 条文案全部通过（`audits/launch-*-r02-ink.json`）。
