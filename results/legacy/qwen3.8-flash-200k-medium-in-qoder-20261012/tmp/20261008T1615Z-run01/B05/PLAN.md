# B05 作品计划（可随研究修订）

## 题目要解决的问题（现实、可说清谁在何时何地用）

城市行道树的日常管理与汛期倒伏风险，是一个"人人路过、没人负责到底"的问题：

- 树在谁名下、上次谁看过、看过之后有没有下文，多数城市靠纸质台账与微信群照片；
- 隐患判定（倾斜、空洞、根系、下游暴露对象）散在巡检员个人经验里，换个人就换个结论；
- 台风暴雨前"先加固哪 100 棵"没有可解释的排序，只能按路段喊话；
- 市民发现歪树不知报给谁，报了以后也没有回音；
- 雨后统计靠层层电话上报，数字到上级手里时已混入未核实项。

## 产品方案（虚构品牌，全部演示数据）

**「枝安」——城市行道树风险巡检与处置协同平台**。示范城市：汀州市（虚构，6 个街道、
23 条路段、3,725 棵在册行道树）。五个角色各有一个真实工作面：

| 角色 | 设备与环境 | 要完成的事 |
|---|---|---|
| 市民 | 手机，人行道上一手遮阳一手操作 | 把一棵歪树报上去，并被认得出来是哪棵 |
| 巡检员 | 手持机，户外强光、戴手套、单手持 | 现场读档案、录实测值、拿到判级依据 |
| 值班调度 | 值班室 2560×1440 大屏，3 米外 | 看清风险在哪、今天谁去做什么、哪单超时 |
| 技术复核 | 平板，办公室 | 判读倾斜序列、确认加固优先序是否合理 |
| 作业班组长 | 现场平板/打印单 | 按单作业，围挡与交通导改画得明白 |
| 上级主管 | 会议室投屏 | 看覆盖率与数据质量，而不是看宣传语 |

**统一风险分**（跨屏一致的唯一算法，十张图里所有分级都来自它）：

```
R = 0.30·S_倾斜 + 0.25·S_空洞 + 0.20·S_根系 + 0.15·S_暴露对象 + 0.10·S_历史病害
```

分级阈值：R≥70 立即处置／55–69 限期处置／40–54 观察期／<40 正常。

## 视觉语言

- 底：树皮墨 `#141210`／纸面 `#F4EFE6`；主绿 `#3E7C4B`（健康）、警示橙 `#D9752B`、
  立即处置红 `#C8402F`、数据青 `#4FA3A5`。避免与 B01/B04 的夜色系统雷同。
- 界面骨架随媒介变：手机有状态栏/底部导航与可点胶囊；大屏用 12 栅格与 3 米字号；
  打印件用页眉页脚与签字位；说明图用比例尺与剖面。
- 树形用 DSL 原语拼：冠幅＝圆盘（borderRadius），主干＝矩形，根系＝扫描线，
  倾斜＝Transform 旋转；服务无矢量 path，曲线一律逼近并在件内注明。
- 所有按钮/胶囊只画"确实由该件解释其作用"的控件，不做无意义的假控件。

## 一致性与验证边界

- 单一数据源 `tmp/<run>/B05/research/trees.json`（`b05data.py` 用固定种子生成，
  可复算）；派生统计 `stats.json`。十件里出现的每个数字都由脚本从同一份数据算出。
- 关键交叉校验：件-01 报的那棵树（TZ-JS-0417）必须与件-02/04/07 是同一棵，
  实测值、判级、派单时间前后一致；件-03/05/09/10 的总量（立即处置 98 棵／限期 229 棵／观察 669 棵／正常 2,729 棵，覆盖率 24.9 %、超时工单 87 张）互相对得上。
  > 收尾更正（2026-10-11T13:22Z，脚本回查十份 final.snapshot）：立即处置 98 实际出现在件-01/03/05/06/09/10；
  > 3,725 与 327/87/24.9 %/726 出现在件-03/09/10；限期 229 只在件-03；观察 669 与正常 2,729 未印在任何一页
  > （件-03 标注「条长＝非正常棵数，不含正常」），四级求和=3,725 只是数据集层校验，不是页面事实。
- 未做真实用户验证，不声称做过：产品假设写在 `product-brief.md` 的"假设与验证边界"，
  `journey.json` 里每件标注它验证的是哪个假设、缺哪一步证据。
- 演示数据声明：品牌、城市、树种名录、街道名、工单号、台风名与所有数字均为虚构。

## 流程（每件）

`b05data.py` → `caseNN.py` 生成 → TextFit 闸门（带警不提交）→ `b05run.py` 真实渲染 →
打开实际 PNG（含必要 2× QA 裁图，只存 tmp）→ 记 iterations → 修改重渲 →
`promote.py` 按字节指纹提升 final.png/final.snapshot → `case.md`。
收尾：`product-brief.md`、`journey.json`、portfolio.json/md、gallery.md、
snapshot-usage.md、task-metrics.json、tool-usage 留痕。计划随研究推进修订。
