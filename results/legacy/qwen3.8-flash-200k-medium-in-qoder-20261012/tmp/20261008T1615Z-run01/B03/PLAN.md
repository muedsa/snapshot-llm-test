# B03 作品计划（可随研究修订）

本题目标：用 10 件独立完整作品探 Snapshot DSL 的创意边界。每件都要有明确受众、
真实使用情境、用户要完成的事，以及一个由探针验证过的独到手法。

## 规则

- 每件都要真实看图并至少完成一轮「看图→改→再渲染→再比较」的完整视觉迭代；
  初版即合格的不制造无意义修改。
- 手法服务于内容：任何滤镜、遮罩、变换都必须解释它让哪部分信息更好读。
- 不宣称未验证的能力；`fontFeatures`、`INNER` 阴影、透视项这类只写实测结果。
- 所有数字来自 `data.json`（固定种子生成，标注为演示数据）或真实抓取的研究资料。
- 辅助素材：本题十件默认纯 DSL（`<Image>` 计数为 0）；探针 16b 的平铺瓦片只用于
  能力验证，不进入作品。若某件确需素材，另在 `asset-sources.json` 记录来源与生成方式。

## 执行期修订（真实渲染后写回）

- case-02：主视觉由「潮线波纹」改为「日轮 + 海面」两层几何，因为叠印分色必须能按
  格子判定 A / B / A×B；圆形半径按像素换算成 `u/v`（`SUN_RU=R/AW`、`SUN_RV=R/AH`），
  否则在非方形画布上会画成扁椭圆。同时加了两条机械自检：TextFit 问题数必须为 0，
  以及各栏底边不得越出页脚线（首版按 1080×1528 排下来曾与阵容栏重叠，改压缩了
  标题区与网屏行数）。

### case-03 写回（10 次渲染后）

- **矩阵元组是行主序**：`b03kit.matrix_attr` 把 6 元组写成 `[[a,b,tx],[c,d,ty]]`，
  于是局部 x 轴落到 `(a,c)`、y 轴落到 `(b,d)`。把基向量按 `(cu[0],cu[1],0,cv[0],cv[1],0)`
  摊平等于传了转置，轴测面之间会错开一个白缺口——数据完全正确、渲染不对时优先怀疑这一条。
  已新增 `b03kit.basis(cu, cv)` 统一口径（探针 `B03-probe-anchor-02-*`，120×40 非方形）。
- **圆柱侧面必须按切点构造**：剪切后的椭圆盖竖直跨度是 1.5r，用竖直 2r 边会让端盖露出筒壁。
  `tangent_uv()` 对 `a×Mv` 取极值解出切点，侧面＝两切点连线沿轴拉伸。
- **缩放系数只能进一次**：既进尺寸又进方向向量，线会被 Positioned 槽位的视觉宽度误导成水平线。
- **空心件要有壁厚折算系数**：按外包络算体积会把整机算到 359 g（手电实测量级约 100 g）。
- 常驻断言：轴测体不越绘图区、下部区块不越页脚线、说明块不压分隔线、装配累计长度＝装后总长。

### case-04 写回（5 次渲染后）

- **SWEEP 可以做硬边界饼图**：`gradientStops` 里每段给两个相同色标（`[s0,e0,s1,e1,…]`
  配 `[c0,c0,c1,c1,…]`）即得无过渡带的扇区；`gradientStartAngle` 传非负 `3π/2`
  让 0 落在 12 点钟，与 Flutter sweep 的顺时针方向一致，刻度环与扇区天然对齐。
- **环形/饼形唯一可控构造＝大圆压小圆**：无 ClipPath、无 path，所以「环」只能画满盘
  再用 `INK_DISC` 圆盘 + 沟槽盘压掉中心。压住之后外环才成为「唱片刻度环」。
- **等宽字体名会回退**：`fontFamily="IBM Plex Mono,…"
  在 `"21:59 / 22:00"` 上实渲约 118 px，而 TextFit 估算 108 px 判为通过——
  含空格的数字串必须留 ≥25% 余量，并用 1:1 裁切复核，不能只看缩略图。
- **缩略图会造出假问题**：v03 目视以为 `A4 5:44` 贴边，逐行扫描证明文字在 x 65..131、
  左侧竖条在 44..50。看图发现疑点后用像素测量定性，再决定是否改。

### case-05 写回（1 次 400 + 4 次成功渲染 + 19 条探针）

- **`<Container>` 的 `clipBehavior` 一律 400**（`PARSE_ERROR "Check failed"`，有无子节点都一样）：
  文档 `parser-tags.html` 说明「非 NONE 时需提供背景装饰作为裁剪路径，仅纯色不够」。
  想裁切溢出内容用 `ClipRRect` / `ClipOval`，不要给 Container 加这个属性。
- **只含空格的 `<Text>` 什么都不画**：200 响应、PNG 里零深色像素。所以「空白文本 +
  UNDERLINE 装饰线」画引导线这条路是假的，线型必须自己用几何节点画（点＝`d.dot`，
  虚＝`d.line`，双＝两条 `d.line`）。
- **`decoration` 枚举是 `TextDecorationLine`**：`LINE_THROUGH` / `OVERLINE` / `UNDERLINE` 可用，
  `STRIKE_THROUGH` 报 `No enum constant`；`decorationLineStyle="DOUBLE"` 与 `LINE_THROUGH`
  组合成立（`probe-through3.png`）。
- **同一视觉语言里不能让两个元素长一样**：停印书名的双线删除线与停印的双线引导线
  在同一水平线上连成一条，读者以为书名被划了 300px。修法是把其中一个退回固定列留出空白。
- **偶数样本的中位数**是 (第 n/2 项 + 第 n/2+1 项)/2，不是第 n/2+1 项；这类统计口径
  要在看图时专门核一遍，不然会带着错数字交付。

### case-06 写回（1 次 400 + 4 次成功渲染 + 1 条探针）

- **正文含 `<` 会让整份 DSL 400**：`Unexpected character '9' in input state [TAG_OPEN]`。
  解析器不做实体解码，`&lt;` 也不解；唯一办法是 `<![CDATA[<90mg]]>`。已把这条做进
  `b03kit.tlab`，之后写文案不用绕开小于号。
- **`WidgetSpan` 能嵌带 `Text` 的 `Container`**（探针 wschip），字母角标比纯色点信息密度高；
  但行内方块按基线对齐会**偏高**、前后空格宽度不可控，需要精确对位时改用几何圆点 +
  `TextFit.w()` 估算横移（和 case-05 引导线同一个套路）。
- **`overflow="ELLIPSIS"` 确实产出省略号**（配合 `softWrap="false"`），可以在故意截断时
  用 `assert tf.w(s, size) > box_w` 保证一定截断，而不是依赖运气。
- **口径要诚实**：奶咖的「杯量 ÷ 粉量」不是萃取比。本件把萃取液量（意式＝粉量×2）
  与稀释量分开算，meta 行显示 `280ml 杯 / 18g 粉 → 36ml 液 1:2.0`。
- **分支顺序**：`ml` 为 None 的品项要先判 `ml` 再判 `dose`，否则点心会掉进「不含咖啡」分支。

### case-07 写回（4 次成功渲染 + 1 次探针 + 4 次传输故障）

- **实测优先于推算**：块字符按 0.833em 定位时，每段右端比预期短 4.7~14.1px，画面出现
  规则的「砖缝」。probe-adv 直接量 40 连排：前进宽 12.0px＝0.60em（与空格同宽），
  墨迹高 24px＝1.2em。改步长后同一套 PIL 复测偏差降到 ±0~1px。教训：**凡按字号推算
  字距的排版，必须先用一行长串实测**，probe-block 当时的结论就是靠短串外推错的。
- **`<Raw>` 只能整段定位**，多色行必须按颜色切段；切段后段与段之间不再自动衔接，
  步长误差会逐段累积，所以网格类作品宁可多切段也要保证每段起点精确。
- **量化损失要显式补回来**：字符网格把高程量化到约 43m/格，阶梯缺口让路线读不顺，
  于是叠一条「未经字符量化」的插值线，并在图例里说明两者关系，而不是假装字符是连续的。
- **天空留白是信息区**：最陡段区间与无水源区间用括注落在空白处，两处数字都来自航点表。
- **传输故障不当成品**：curl 28/56 与「200 但正文短于 Content-Length」三种情况都要留痕，
  最后一种 `render.py` 拒绝落盘；v03 因此没有图像证据，迭代表里如实写「未看图」。

### case-08 写回（2 次 400 + 5 次成功渲染 + 内核修正）

- **天文内核三处易错点**（错了画面照样「好看」，只有校核能抓住）：
  1. `jd()` 必须含 `+2451545.0` 历元，否则 GMST 差出整个数量级；
  2. GMST 的日运动系数是 **360.98564736629**（写成 360.9856473662 之类会累积成度级偏差）；
  3. 太阳黄经用太阳平黄经 `280.46646+36000.76983T` 加中心差，**不能**套用月球的
     `218.316+481267.88T`；另外 `atan2` 出来的方位是「南起」，要 `(+180)%360` 转成罗盘方位。
  这三条各自都会让「北极星高度≈当地纬度」「太阳上中天高度=90−|φ−δ|」两条独立校核失败，
  所以校核要留在 `data.json.checks` 里，而不是只在开发时看过。
- **`border="0"` 不合法**：服务端 400 `PARSE_ERROR: Attr [border] value is invalid`。
  不要边框就整个省掉 `border` 属性，别写零宽或 `none`。
- **Python 3.11 的 f-string 表达式里不能有反斜杠**：`f'...{"a" if s else "\"b\"=0\""}'`
  直接 SyntaxError。要先在 f-string 外把片段算好（本案用 `battr` 变量）。
- **诊断时不要吞 stderr**：一次 `python … >/dev/null 2>&1 && grep …` 把 SyntaxError 藏了，
  链式命令后面那个 `grep` 又读到旧文件，于是「看起来修好了」。之后一律分开跑并复验产物。
- **视轴不必等于锁定目标**：低空目标与高空参考星同框的唯一诚实解法，是把相机视轴抬高、
  准星仍画在目标的真实投影像素上，并把「偏轴 17.2°」写在读数里。硬把目标摆到画面中心
  ＝伪造坐标。
- **投影缺陷可以变成内容**：等距方位柱面不保大圆，指极星延长落点与北极星差 57px＝2.94°；
  把它测出来、标在图上，比悄悄改成「看起来对」的摆位更有说服力。
- **算出来「没有」也是一种交付**：银道面反算表明本视场银道面在 56°~74° 高，银河带
  根本进不了这一帧，于是画面不贴银河，只在档案卡留一行读数。
- **可读性要算法化**：面板/准星/读数/标尺登记为 BLOCK、星点登记为 RESERVED，标签从
  20 个候选偏移里选不压字的位置， displaced 时补「星点小圈＋从圈边出发的引线」。
  v01 只放出 1/8 标注，v03 起 8/8、0 跳过，且不再需要手调坐标。
- **注记必须与图面一致**：曲线注记写「「,」为地平线下」而实际一个逗号都没出现
  （低于地平的点全落在最底行）——这类「代码里写了但图上看不见」的话要删掉或改成实算文案。

### case-09 写回（8 次请求：1 次 curl SSL 超时 + 7 次成功渲染）

- **遮罩拼贴要站得住，就得让窗口边界等于真实几何边界**：本案的七块色板不是「好看的
  矩形」，而是 ISO 216 沿长边裁半的序列（下→右→上→左→下→右 走成风车），每级由
  `sub_rect()` 递推并与标准表逐级 assert。这样任何一块的大小、位置、字数都能当场核算。
- **裁半语义最容易写反**：`y += 0.0 if side=="下" else h` 会让「取下半」实际取到上半，
  画面照样对称好看，只有上级标签被子级整块盖住时才看得见。规则：先算裁完后的半高 `h/=2`，
  再 `y += h`（取下半）／`x += w`（取右半），并在 assert 里**允许长短边互换**
  （裁半后的纸就是同一张纸转了 90°，容差 0.6px 来自标准表取整）。
- **绘制尺寸要取落位槽，不取 ISO 表的长短边顺序**：v03 按 `PX[name]`（竖幅）画进横幅槽，
  单块超出 164px 直接压住右栏要目。文字始终水平排，所以槽是横幅就画横幅。
- **后画的遮罩会盖掉先画的内容**：`ClipOval` 圆环的「内圆」是用底色填出来的，先画正方形
  与对角线、后画圆环，作图就整个消失（v05 看图才发现）。遮罩类元素一律**先画**，
  被它承载的几何注记后画。
- **标签不要压在字上：让正文让带，而不是把标签挪走**：先按「角位 × 纵向微调（0/±22/±44/66）
  × 双行→单行两档」定出标签矩形，再按剩余带高重算 `rows`。v05 的「贴纸感」消失，
  代价是字数变化（A0 552→504），标签与 `data.json` 同步更新即可。
- **深色板上的深色标签要描边垫层**：A5 的 DEEP 底配 `#12100CD9` 标签几乎糊成一片。
  加一层 2px 纸色（`#F4EFE6`）垫矩形比改标签配色更稳，浅色板上几乎不可见、不干扰。
- **旋转会吃掉边距**：套准错位 ≤1.5° 时，距板边 6px 的标签有转出板外的风险
  （半对角 ≈483px × sin1.5° ≈ 12.6px），角位内缩改 9px 并保留「标签必须完整落在板内」的断言。
- **圆弧与文字相交只有放大才看得出**：√2 标签居中放在交点下方时，圆环下弧正好穿过它
  （读成「−2」）。全图 1080×1440 缩略时完全不可见——PIL 2× 裁剪是这一案的主要发现手段。
- **提升脚本要防「同名多次尝试」**：`promote.py` 原实现取 `requests.jsonl` 里首条前缀匹配记录，
  v07 首试是 curl (28) SSL/TLS 超时的 http 0 记录，于是拒绝提升。改为取**最后一次 200**，
  失败记录保留不删（本案 128 行请求日志里它是真实证据）。
