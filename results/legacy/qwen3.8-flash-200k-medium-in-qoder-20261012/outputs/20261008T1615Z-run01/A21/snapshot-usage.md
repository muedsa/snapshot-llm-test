3. **第 3 轮（浅色主题 + 对比度）**：整套色板换成浅色，文字与**实测合成背景**全部 ≥4.5:1

## 跨轮一致性是怎么保证的

- 三轮由同一个生成器 `tmp/…/A21/gen_launch.py` 产出：`BUILDERS[round]` 选择版式，
  `PALETTES[round]` 选择色板，坐标只在 `build_*_r02()` 一处定义，第 3 轮直接复用它并传入
  `tagline`，因此"两图同步改动"不是靠人工对齐，而是结构上不可能走偏。
- 回归证据：第 3 轮改动完成后重跑 `--round 1`、`--round 2`，产出的 `.snapshot` 与已归档的
  第 1、2 轮 DSL `cmp` 逐字节相同；重跑第 2 轮 `ink_audit.py` 得到与归档一致的
  0 重叠 / 19px / 18px / 扩展带 0 非背景像素。
- 每轮的 `content-map.json` 用 `locate()` 在按渲染顺序拼接的全文里定位必需文案，
  长标题以 `covers: part` 记录它由 3 个元素共同呈现，避免"文案在图里但被拆行"被误判为缺失。

## 服务与 DSL 结论（本题新增，供后续题目复用）

1. 8 位 hex `#RRGGBBAA` 在 `Container color` 上由服务真实合成（`#FF000080` 压 `#0B1020`
   得 (133,8,16)）；这是半透明叠光的唯一可用机制。
2. `Container opacity` 与 `<Opacity value=...>` **都被静默忽略**，不要用。
3. `Transform matrix="…"` 必须 16 个值（15 个 → HTTP 400 `PARSE_ERROR`）；
   `alignment="CENTER"` 时绕自身盒中心旋转，旋转方向经像素标定确认（见第 3 轮报告）。
4. `border="N SOLID #RRGGBB"` 且无填充 = 真透明环；8 位 hex 描边未验证，故一律预混实色。
5. `Text` 超盒会被静默裁切且无省略号；CJK 步进 ≈1.02×字号、拉丁 ≈0.58×、空格 ≈0.30×，
   带 `letterSpacing` 时再加 `spacing*len(s)` 并乘 1.10 余量。
6. 字族只能在 `Doc(font=…)` 设定，默认 `Inter,Noto Sans CJK SC` 已能中西文混排。
7. 浅色主题下低 alpha 装饰会"看不见"：同一 `#3D6BFF1A` 在深底可辨、在 `#F5F7FC` 上亮度差
   仅 0.11，需要 3A~4D 才有同等存在感。

## 统计与耗时

- 任务级 `task-metrics.json`：17 个渲染请求 / 16 成功 / 1 失败（`A21-probe01`，matrix 少一个
  值，真实错误响应保留）/ 17 个 DSL 版本 / 15 次实际看图 / 10 个完成闭环的视觉迭代 +
  4 个轮次需求变更版本 / 1 次空重渲染（缓存命中，如实记为 `noop_render`）。
- 分轮：R1 10 请求 8 看图 2 成品；R2 3 请求 3 看图 2 成品；R3 4 请求 4 看图 2 成品。
- 时间口径：`timings.elapsed_seconds` 是墙钟时间（含看图与本地计算），不等于服务耗时之和；
  `timefit.py` 会把未分类为活动的间隔写进 `idle_gaps[]` 并从 `active_seconds` 中扣除。
  本题三轮在 2026-10-09T05:36Z–06:32Z 连续完成，无空闲间隔。
