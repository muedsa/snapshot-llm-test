## 6. 设计选择、经验与未解决事项

### 关键设计选择（由实际预览驱动）

- **三米屏 vs 手机屏决定字号与密度**：case-04/05/10 的时刻列用 40~70px 粗体 tnum，case-06/09 靠分块与小标题层级而不是绝对字号；这个差别是看 v01 缩略后定的，不是先验设定。
- **状态必须多重冗余**：case-10 的「延误/登机中/取消」用色条 + 文字胶囊 + 倒计时 + 计划删除线四重编码；读图时发现有色盲风险的远看场景后加的删除线，成为本题最有效的改动之一。
- **不要和程序化几何硬拼**：case-07 曾用大量矩形堆「摄影感」海面失败，改为分层色带 + 少量高光条 + 反射柱后成立；case-08 的盐壳同理（v08~v12 四次失败尝试都保留）。
- **数据类作品先建可反算表**：case-03/04/05/06/07/08/09/10 的所有可见数字都由一个生成模型派生，结论句用 `max()/all()` 生成；case-09 的手写句与数据矛盾是直接促成这条标准的案例。
- **区间图形画成「一整块 + 挖出例外」**：case-10 时区带从 24 段离散小方块改成夜底挖昼窗 + 同源游标后才读得出昼夜。
### 可复用经验

1. 能力结论必须落到共享封装（`b01kit.K` / `dslkit`），写在笔记里一定复发——case-08 v01 又踩了 RADIAL 混参。
2. 渲染成功 ≠ 画面更新：**每版比对 size + md5**，与上一版相同即空转（case-10 v03 就是这么发现的）。
3. 看图要看原图：长图等高裁带、可疑处 2x 放大；把「查看侧下采样」当成渲染缺陷会白白烧掉一次迭代。
4. 生成器崩溃要在写盘前拦截：DSL 未更新时渲染脚本仍会发出合法请求并返回合法 PNG，日志会误报成功。
5. 超宽/超高看板用「显式列宽 + 末列求余」；逐列自适应必然跨行错位。
6. 半透明大面积填充一律预合成实色（`mix()`），8 位 alpha 重叠会叠出条纹。
### 未解决 / 遗留

- 服务无矢量 `path` 图元：case-05 海岸线与 case-09 折线面积用逐列矩形 + `K.polyline` 近似，曲率细节受此限制，无法进一步平滑（属平台边界，不是未完成项）。
- `fontFeatures="tnum"` 在当前渲染环境是否与系统默认等宽数字有可见差异，探测结论为 inconclusive；成品保留该属性但不宣称视觉差异已被验证。
- `Border` 标签的渐变描边为何未出现，原因未确认（推测其绘制路径与 Container border 不同），已用双层 Container 替代。
- 传输抖动（curl 28/52/56 与一次 Content-Length 截断）无法从客户端根除，只能保留失败留痕后重试；服务端未提供 Retry-After，等待时长不可测。
- 日志字段的一处历史不一致：早期用例的 `iteration_id` 形如 `20261008T1615Z-run01-case-01-v01`，后期形如 `…-case-10-case-10-v04`（版本名自带前缀导致重复）。日志为追加式历史记录，不改写；引用时以 `case_id + version` 为准。
### 结束依据

十件作品逐件完成「实际看图 → 修改 → 重渲染 → 再比较」，最终版本 0 TextFit 问题，final.png 与某次 http 200 服务响应的 md5 相同，final.snapshot 为同名完整 DSL，case.md 记录了场景/数据反算/自检；整体终审见 `portfolio.json` 的 `final_collection_review`。达到题目要求，非因请求或迭代次数用尽而停止。
