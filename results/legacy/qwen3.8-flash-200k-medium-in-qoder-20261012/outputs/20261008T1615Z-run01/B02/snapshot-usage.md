## 4. 修改记录与踩坑

**渲染器/DSL 层（构件烟雾测试 8 轮换来）**

1. 把 `Stack/Positioned` 塞进带 `border` 的 `Container` 里，文字在真实渲染中整块消失
   （v1、v3 两次踩同一坑）。印章构件最终拆成同心的三层旋转图元：外框、内框、文字各一层。
2. `d.pos()` 返回 `None`，把它当对象继续链式调用会让图元跑到画布左上角（v2）。
3. 纸底噪点用固定取模网格散布，放大后像纱窗；改成确定性伪随机（v6）。
4. 六边形用扫描条填充出现横纹；改为整数行铺满 + 外沿宽度 + 同色压边（v7）。
5. 页脚文案原本硬编码，与 `data.json` 的费率不一致（v8 改为从 brand/rules 生成）——
   这是本题「同一数字两处写就会分叉」的第一次预警。
6. 大面积 8 位 alpha 在深底发灰：改为 `blend(hex, a, over)` 预算实色。
7. 圆角轨道 + 方角堆叠分段 → 两端缺口；方角轨道 + 2px 纸色分隔线才对（case-08 v01→v02）。
8. 描边必须按圆角半径内缩，否则圆角处描边脱离形状。

**文字与排版层**

9. Snapshot 裁字不给省略号，TextFit 是唯一事前防线；但 TextFit 会低估：case-09 v03 的横幅文字
   按 190px 判可容纳，真实渲染仍被切在横幅外。**结论：TextFit 通过不等于看过，局部必须放大。**
10. 列间留白：case-10 v02 的「80 次」右边界顶到下一列色片，整列读成一坨；数字盒固定内缩并
    留 ≥80px 列间距（v03）。
11. 小字不能压在大字上：case-10 v01 的「ZONE A」落在大字母两脚之间，改成独立铭牌条（v02）。

**数据与口径层（比视觉更容易越界的地方）**

12. 占比刻度按「最大类目归一」会把 28.5% 画成满条——刻度一律锚定真实分母（全馆 2946 次）
    并在说明行写清（case-10 渲染前修正）。
13. 把 `cats[].names[]` 的登记顺序当「最常借出」排名属于伪造；改为遍历 `loans_2025` 合并机型计数，
    并如实标注前四名只差 3 次、各机型保有量相同，名次只作找物参考（case-08/09/10 同一口径）。
14. 「在册 96 件」不等于「在架 96 件」：case-10 v01 用错词，v02 起把登记数与 `state=="在馆"`
    的现场计数分列（96 / 81）。
15. 编造峰谷归因（「10 月峰值因装修季」）在 case-08 v01 被删；台账没有天气与节假日字段，
    图面改写「不作归因」。
16. 无来源的逐件历史不能手填：为档案卡新增 `ledger_for()`（独立 `Random("ledger:"+id)`），
    在数据块与图面双重标注为演示自造，且重跑后复核 2946/1344/10589.8/逾期率/续借率/峰值月未变。
17. 无法折算的三项（会费总收入、维修实际支出、捐赠折算）在年报里明确写「不折算」，
    而不是补一个看起来合理的数。
18. 全套声明纪律会在收尾时露底：写 `asset-sources.json` 时对 11 份成品 DSL 做字符串核对，
    发现 case-10 是唯一没带虚构演示声明的版面（页脚用了 micro 档），回补为 v06 重新定稿。

**过程留痕层**

19. `render.py --task` 必须传裸题号（`B02`），把用例写进 `--task` 会让日志走错文件；

## 6. 设计选择、经验与未解决事项

### 关键设计选择（由实际看图驱动）

- **同一品牌十种版面**：拒绝把 case-01 的版式缩放到其余九张上；共用的是构件库与色序，
  不是构图。三米铝牌（case-10）与口袋通知（case-05）视觉差异刻意保留。
- **信息密度分档而非删内容**：`footer` 做 full/short/micro/receipt 四档，密度不够时删层级
  不删虚构声明——case-10 的教训正是 micro 档把声明删掉了。
- **估算与可复算物理分离**：年报底部四栏「口径与边界」带，把可复算 / 估算 / 不折算 /
  唯一现金项分列，读者不会把 1344 件避免购买当成台账统计。

### 可复用经验（写给 B03–B06 与后续题）

1. 先写数据生成器再写版面：`b02data.py` 单点定义数字，十个版面才不会互相打架。
2. 构件先做烟雾测试再进正式用例：8 轮 smoke 换来 10 个触点里只有 1 次构件级返工。
3. 断言内容止点（`assert BODY_BOTTOM + ... <= H`）能在渲染前抓住溢出，省下真实请求。
4. 收尾核对本身会发现单题自检漏掉的东西（第 18 条）；跨成品的字符串核对值得每题做一次。
5. 请求归属用文件路径反查比用 ID 字符串可靠。
