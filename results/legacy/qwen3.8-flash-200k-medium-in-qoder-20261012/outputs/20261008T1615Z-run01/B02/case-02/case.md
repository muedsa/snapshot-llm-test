# case-02 会员卡正反面 · 1020x646 ×2（final.png = 正面，back.png = 背面）

## 这一件要解决的问题
卡在柜台上被递来递去，它同时是**身份凭证**和**规则提示**。
所以两面分工不同，不是同一张图的正反装饰：

- 正面（深色，大字号，5 组信息）：谁、哪一档、还能不能借、什么时候到期
- 背面（浅色，小字号，密集排版）：五条规则 + 电话 + 安全课 + 两个取还点 + 条码

- 尺寸：1020x646 = 85.6x54mm 标准 PVC 卡在 12px/mm 下的出血前尺寸
- 受众：会员本人（一年看它几十次）与服务台工作人员（扫条码）
- 完成标准：正面在手里 1 秒内看出「3 件已满 / 有逾期 / 快到期」三件事

## 视觉与品牌
沿用牛皮纸 + 墨黑 + 朱橙 + 计量黄。正面用深色底（`paper_doc(dark=True)`）把
「卡」和店内的纸质物料分开，但母题不变：六角编号、刻度条、印章、页脚识别锚。
槽位左侧 4px 竖条用类目色（与 case-01 底部刻度带同一张 `CAT_COLOR` 表），
这是全套触点共用的一致性锚点。

## 过程错误（如实记录，不重跑掩盖）
`render.py --out` 传目录（带尾斜杠）时被 `Path` 归一化成了文件路径，正面与背面
两次请求写到同一个 `case-02.png`，正面 PNG 被覆盖。已按字节从该请求的原始响应副本
`requests/B02-case-02f-v01-20261010T050656Z.response.bin`（95587 字节，
md5 `1f32a734a408cf5325a4134a0fb87c6b`，与日志 `response_bytes` 一致）恢复，
**没有为此重新请求**；此后所有渲染改为显式 `--out <文件>.png` + `--seq-dir` 按用例归档。
