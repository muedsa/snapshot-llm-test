## 3. 文档与 DSL 能力的实际使用

- **`Opacity` 是“先拍平子树、再整层合成”**（文档「Opacity 与 Transform」）：所以 ② 的重叠处
  不是两层各 50% 的叠加，而是纯蓝的一层 50% → (128,128,255)。这一点是本题 ①② 对照的全部意义，
  实测 Δ(①,②) = (1,63,64) 与预测一致。
- **hex alpha 与 0.5 不等价**：`80` = 128/255 = 0.501961。文档写作 `#RRGGBBAA`，因此 ① 的期望值
  必须按 128/255 而不是 0.5 计算，否则期望 (128,64,192) 会与实测差 1 级、判据失效。
- **`ColorFiltered` + `MULTIPLY` 的透明区行为**（文档「透明度与颜色滤镜」中“部分混合模式也会给
  边界内的透明间隙着色”）：`out = dst × filter / 255`，dst 透明时留下源色，故 ⑤ 的滤镜盒整块变实色
  琥珀 (246,185,74)。这是实测确认的行为，不是推测。
- **`BackdropFilter` 必须放在 `ClipRRect` 内且其下有已绘制内容**：v03 的 ③ 是空白白底，因为节点表
  漏了条纹层——`BackdropFilter` 没有可读的 backdrop 就什么都不做。修正后卡内糊、卡外锐。
- **`ImageFiltered` 的 sigma 与取样范围**：σX=σY=6 的高斯台阶 10–90% 上升宽度 = 2·erf⁻¹(0.8)·σ
  = **15.38px**；④ 卡边实测 14.28px（反推 σ≈5.57），50% 交叉点落在区域 y=39.5（设计值 40）。
  周期 16px、占空比 50% 的方波经 σ=6 模糊后残余波纹 = 2·(2/π)·exp(−2π²σ²/P²) = **0.0793** 满摆幅
  → 卡内预测 16.1 级，实测 14（③）/ 68（④，因卡片填充本身是 70% 透明白）。
- **`ClipOval` 在滤镜链之后生效**：圆内是模糊结果、圆外是原图，边界为 1.6px 硬台阶（抗锯齿），
  与 ④ 的 15px 羽化形成直接对照。
- **服务硬约束（承自 A09，本题再次遇到）**：`<Positioned>` 必须是 `<Stack>` 的直接子节点，
  否则 HTTP 400 `renderBox.parentData must be StackParentData`（v02 即因此失败，请求体与错误响应
  都留在 `requests/A10-v02-20261008T140710Z.response.bin`）。
- **TextFit 门禁**（`tmp/…/_suite/scripts/` 的 `fit` 模块）：盒宽 ≥ 估宽/0.96、行距 1.45；
  CJK 与 U+2190–24FF/≥U+2E80 等按 1.02 em、字母数字 0.58 em。每次生成 DSL 都跑一遍并把结果写进
  `fit-report.json`：交付版为 47 个文本项、`fit_problems: []`、`min_font_pt=20`。
  文案改动（尤其 v07 加 “±2/±1” 与 “实测 14 级”）每次都重新过门禁，靠加宽盒与缩短措辞解决，
  没有把字号压到 20pt 以下或让文字溢出格框（`preview/v07/crops/` 的 ②③⑤ 三张裁图逐字复核）。
- **未使用的能力**：`BackdropFilter` 之外的其他 blendMode、`ShaderMask`、外部素材（A 类要求纯 DSL 主体）。

## 4. 视觉迭代、判据证伪与自检结论

6 次渲染请求（5×200 出图 + 1×400 语法错误），7 个 DSL 版本（v01 为本地草稿未提交服务；
`final` 因文案改口径渲染了 v06、v07 两次），4 轮完整视觉迭代（v04、v05、v06→final、v07）
+ 1 轮基线（v03）+ 1 轮语法修复（v02）+ 1 轮审计判据自校。
实际打开图片 18 次：整图 5（v03、v04、v05、v06、v07）+ 局部 13（v06 的六格、header、footer、
`zoom_c3_rim`、`zoom_c5_halo` 共 10 张，v07 的 ②③⑤ 三张文案复核）；放大裁图共生成 20 张。

1. **v03（基线，首张可用图）**：整图打开即发现 ③ 是空白格 —— 缺 backdrop 源；同时 ①② 的
   “(180,100)” 标注画进了实验区、正好压在待测像素上，⑤ 的框标注跑到白区外。
2. **v04（视觉迭代 1）**：补条纹层 + 把标注全部移到标题带（新增 “⑤ 紫框 = 滤镜作用盒 200×150”）。
   复核时又发现 ④ 的 2px 深描边正好覆盖在卡边 10–90% 上升的测量窗口上（实测上升宽度只有 0.8px），
   于是删掉 ④ 描边（③ 保留锐利描边作对照），并把 ④ 卡边剖面改为沿 y、x 方向覆盖整数个 16px 周期平均
   → 14.28px。
3. **v05（视觉迭代 2）+ 判据证伪**：用 `probe_a10.py` 打印原始剖面，三个“看起来合理”的判据被图像本身否掉：
   - ⑤ 盒外晕染：原计划按 CLAMP 的 Φ(d/σ) 台阶模型预测“盒外 6px 已接近白”，实测 6px 处 B=82（仍是琥珀）。
     该模型连同被否定的原因保留在 `composite-audit.json` 的
     `naive_step_model_rejected` 里，判据换成三条实测断言（6px 仍暗、30px 回白、50% 点距盒沿 8–22px），
     并据实测把结论写成“σ≈5.2 的高斯台阶，中心在盒沿外约 15.5px”。
   - ③ 卡沿“浅蓝晕”：`lum<90` 会误计蓝条纹；`probe2_a10.py` 逐像素打印证明描边外侧每个像素都是纯条纹色
     (29,78,216)/(255,255,255)，那条淡线只是 2px 深描边的 1px 反锯齿 → **不是背景渗漏**。
     曾考虑的“把卡片填充从 `#FFFFFF1A` 提到 `#FFFFFFCC`”被否决：那会抹掉 ③ 要演示的东西
     （透过 10% 色调看到的模糊背景）。
   - ⑥ 圆弧：原取样角撞进白色矩形区，平台值失真；改 220°、r 88–109，并把台阶测量窗口限定在 98–106，
     才区分开“滤镜场自身梯度”与“裁剪硬边”。
   - 文本清晰度：`mean|ΔI|` 是全变差，对模糊几乎不变（③/④ 只有 1.36），判据方向本身就是错的；
     改为通道 B 的 ≥60 级硬台阶计数（820 vs 0）+ 平均梯度（13.29 vs 2.141）。
4. **final → v06（视觉迭代 3）**：格内文案改成实测口径，TextFit 复跑 0 违规；对当时交付路径
   `compositing-lab.png` 重跑 `check_a10.py` → **27/27 通过**，最大点色偏差 5 级
   （⑤ 青环被模糊衰减后的 (147,170,72) vs 预测 (152,171,72)，预测本身用
   `erf(半宽/(σ√2))=0.4403` 的细笔画保留率算出）。
5. **v07（视觉迭代 4，最终交付）**：逐格 2× 复核 v06 时发现**板上印的仍是公式期望值而不是实测值**：
   ② 印 (128,128,255) 而像素是 (126,126,255)、③ 印“波纹 16 级”而实测 14、⑤ 印 (29,30,17) 而实测
   (29,30,18)。这类 1–2 级的差来自服务侧取整，不影响判据，但既然把数值印在图上就必须与像素一致。
   改为 ② “… → (128,128,255)±2”、③ “卡内波纹实测 14 级，卡外 226 级”、⑤ “…→(29,30,17)±1”，
   重新渲染并复核：`check_a10.py` 对**交付路径**仍 **27/27 通过**，三格裁图确认文案未溢出。

**逐格看图结论**：① 紫重叠 + 两侧半透明、② 重叠处只剩纯蓝淡出一层（与 ① 明显不同）、
③ 卡外条纹根根分明而卡内是柔化的蓝白场 + 锐利文字、④ 卡内文字与形状一起糊掉且卡边呈可见羽化带、
⑤ 整块琥珀 + 深板 + 间隙被染实 + 盒外晕圈、⑥ 同一效果被圆硬边切走且圆外保留原色青环
——六格的两两对照都读得出来，不是靠标签宣称。
