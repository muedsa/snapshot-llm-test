# case-04 · 急诊中心分诊态势屏（2560×1440）

## 使用场景与受众

三甲医院急诊科夜班值班台的挂墙态势屏，3 米外可读。受众是急诊值班组长、分诊护士和
轮转医生：他们要在几秒内判断"哪个分区压不住、下一个床位该给谁、救护车还有几分钟到"。
因此这块屏不是 KPI 汇总，而是一张**决策屏**：告警条直接给出可执行建议，右侧优先级列表
直接给出前 5 个待处置患者编号。

## 完成事项

- 三栏 12 列栅格：左＝分诊等级构成 + 分区压力与床位；中＝候诊时间轴；右＝救护车在途 +
  主诉分布 + 当前处置优先级前 5；顶部 5 个 KPI 胶囊 + 大号时钟；整宽告警条。
- 全部数字来自同一个反算队列：`random.Random(20261009)` 生成 17:30–21:30 的 96 人次到院，
  按 ESI 权重（1:0.035 / 2:0.16 / 3:0.52 / 4:0.86 累积）分诊，按状态权重（候诊 26 / 在诊 34 /
  待床 14 / 已处置 26）流转，得到 34 人在院候诊、平均候诊 114 分钟、最长 3h57m（A-178）、
  待床 12 人、在岗医护 9/14。KPI、条形、时间轴圆点、优先级列表、床位格数全部读同一批对象。
- 告警条不写死：取 `OCC` 中占用率最高的分区生成，实渲染为
  「留观 10/10 满员 · 6 名 ESI-1/2 仍在候诊（最久 2h58m）· 建议启动二级分流，把 ESI-4/5
  转至合作门诊单元（需值班组长确认）」。
- 时间轴：纵向 6 个分区、横向 17:30→21:30，圆点半径按 ESI 分级（13/12/11/9/8 px），
  紫环＝已确诊待床，红色 NOW 竖线；无候诊患者的分区显示"当前无候诊患者（空床 N）"。
- 床位格（waffle）严格等于真实容量：抢救室 6、急诊内科 14、急诊外科 12、儿科 8、骨科 6、
  留观 10，实心＝已占，颜色随剩余床位档位变化（满员红 / 紧张黄 / 可收治绿）。

## 内容来源（虚构声明）

医院名"云州市第一人民医院"、患者编号（A-1xx / 皖A·xxxxx 车牌）、主诉、年龄性别、
到达时刻与等待时长全部为脚本按种子生成的演示数据，不含任何真实患者信息，
画面顶部副标题与页脚都明确标注"虚构演示数据"。ESI 1–5 分级、"抢救/留观"分区名称、
"二级分流"术语取自公开急诊分诊常识，用于让演示数据在语义上可信。

## 视觉与技术选择

- 深蓝底 + 高饱和分级色（红/橙/黄/绿/青）是态势屏惯例：夜间值班室低照度，暗底减少眩光，
  等级色必须一眼区分。
- 全部图形为纯 Snapshot DSL：`Container` 圆角/描边做卡与胶囊，`box` 实心矩形做条形与
  床位格，`d.line`（旋转矩形）做网格线与引导线，`d.dot`/`ClipOval` 做时间轴圆点，
  `Frosted`（`ClipRRect`+`BackdropFilter`）只用于告警条边缘的轻微玻璃感，其余保持硬边。
- 文本全部走 `TextFit.check`，本轮 12 项检查 0 项超限；右对齐数值统一用
  `align="END"` 且锚点减掉卡片内边距，避免越界裁切。
- 未使用任何外部素材（`asset-sources.json` 中 case-04 为空），符合 B01
  `dsl_primary_with_supporting_assets` 的 DSL 主导要求。

| 版本 | 看到的问题 | 改了什么 |

## 复现

```sh
export SNAPSHOT_TASK_ROOT=/绝对路径/任务根 SNAPSHOT_RUN_ID=20261008T1615Z-run01
python tmp/$SNAPSHOT_RUN_ID/B01/case04_triage.py      # stdout 打印反算队列指标，stderr 写 .snapshot
python tmp/$SNAPSHOT_RUN_ID/_suite/scripts/render.py --task B01 \
  --in tmp/$SNAPSHOT_RUN_ID/B01/case-04/case04.snapshot \
  --out tmp/$SNAPSHOT_RUN_ID/B01/case-04/case04-v06.png --version case-04-v06 \
  --seq-dir tmp/$SNAPSHOT_RUN_ID/B01/requests
```
改 `NOW` 或种子即得另一时刻的态势；所有派生指标（含告警文案）会自动同步。
