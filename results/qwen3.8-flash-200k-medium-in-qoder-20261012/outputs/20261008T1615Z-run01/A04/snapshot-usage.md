## 2. 数据推导（全部用 `Fraction`，不用浮点累加）

`inputs/conversion.csv` 只有 4 行：前期 直接 8000/2400、前期 推广 2000/200、
后期 直接 2000/700、后期 推广 8000/960。

| 量 | 精确值 | 显示 |
|---|---|---|
| 分渠道率 | 2400/8000, 200/2000, 700/2000, 960/8000 | 30.0 % / 10.0 % / 35.0 % / 12.0 %（两渠道都上升） |
| 总体率 | 2600/10000, 1660/10000 | 26.0 % → 16.6 %（下降） |
| 访问构成 | 8000/10000, 2000/10000 → 2000/10000, 8000/10000 | 直接 80 % → 20 %，推广 20 % → 80 % |
| 加权复算 | 0.8×30.0 % + 0.2×10.0 % = 26.0 %；0.2×35.0 % + 0.8×12.0 % = 16.6 % | 与“成交总数 ÷ 访问总数”一致 |
| 禁用算法（反例） | (30+10)/2 = 20.0 %，(35+12)/2 = 23.5 % | 图上明确标注“常见误读（反例，非总体值）” |
| Δ 三分解 | 组内 +4.4 pp、构成 −12.0 pp、交互 −1.8 pp，合计 −9.4 pp | 与观测 −9.4 pp 闭合 |
| 同构成反事实 | 0.8×35.0 % + 0.2×12.0 % = 30.4 %（+4.4 pp） | 只写入 `analysis.json`，图上不占版面 |

两期总访问数都是 10,000 次，因此总体差异完全由“率的变化”和“构成迁移”两项承担；
`analysis.json` 的 `direction_check` 记录“分组同向上升、总体反向下降”＝Simpson 悖论。
