## 2. 文档阅读与实际使用的能力

DSL 与服务指南在 shared 阶段一次下载并缓存于 `tmp/20261008T1615Z-run01/_suite/docs/`，
本题只读缓存、未重复请求，因此 `document_requests = 0`（复用不重复计数）。

实际用到并验证过的能力：

- **文本**：`text` 的 `font/size/color/align/valign/lines/letter-spacing/line-height`。
  本题最重的依赖是 `lines`（多行盒）与 `align=END`（数字右对齐）；
  件-09/10 的表格完全靠定宽盒 + `align` 拼出列对齐。
- **形状**：`rect`（含 `borderRadius` 当圆盘用）、`outline`（描边框，`card` 的边线）、
  `line`（分隔线、时间轴、比例尺）、`circle`/`disc`（计数点、图例、树冠）。
  注意 `Doc.rect()` **没有 `border` 参数**，描边必须走 `panel()`/`outline_rect()`。
- **变换**：`rotate` 用于件-02/08 的树倾斜（6.8°）与件-06 的导改箭头。
- **透明度与叠色**：`opacity` 做斑马纹、禁用态与件-03 的风险热力底纹。
- **字体**：只用服务默认字体栈，未调用 `fonts` 查询（`fonts_queries = 0`）。

明确不存在或不可用的：服务无矢量 `path`，`B.line`/`B.dot` 这类图元也不存在
（踩过一次，见第 4 节）。所有曲线（树冠、根系扫描线、导改弧线、折线）都是
矩形/线段逼近，件内已注明"示意，非规范尺寸"。

## 3. 迭代过程、服务调用与图像检查

- HTTP 请求 **73 次**，全部是渲染提交：HTTP 200 **40 次**，失败 **33 次**
  （响应体截断 10 次、无响应体/传输失败 23 次，含 `curl (28) SSL/TLS connection timeout`）。
  失败行原样保留在 `tmp/<run>/B05/requests.jsonl` 与 `build-log.jsonl`，
  按 `--kind retry` 重发才拿到成品；没有任何一次把错误响应存成图片。
- DSL 版本 **37 个**（去重），预览文件 **37 张**，全部保留；
  迭代留痕 **38 条**（baseline 10 / visual 27 / retry 1），每条 `image_viewed=true`，
  即**每个版本都实际打开看过图**再决定下一步。
- 2× / 1.6× QA 裁图 **17 张**，只存 `tmp/<run>/B05/case-NN/`，不作为交付图。
- TextFit 闸门累计 **4,462 次**逐框检查（42 次提交，warnings 0），
  另有 **2 次在提交前拦下超框**（case-09 `b-n1` 1285×37 > 1284×28；
  case-10 `a-n-0` 1116×37 > 1036×26.5），拦截发生在发请求之前，所以不计入 73 次请求。
- 服务耗时：40 次成功渲染合计 **41.0 s**（单次最大 3,743.8 ms）；
  73 次请求的 curl 端到端合计 **4,440.8 s**，其中失败请求的等待占大头
  （只算 200 的那 40 次是 1,701.7 s）。**墙钟 7,563.8 s（2.10 h）不等于渲染耗时之和。**
- 计时口径：`wall_clock` = 本题最早与最晚留痕之差；相邻留痕 >900 s 的空档计入
  `idle_gap_seconds` 并逐段列出。本题该阈值为 **0 段**（每段间隔两端都有记录），
  因此 `active_seconds = wall_clock_seconds`，且它只是"有记录的时间上界"。

每件流程：`b05data.py` 取数 → `caseNN.py` 生成 DSL → TextFit 门（有 problems 不发请求）
→ `b05run.py` 真实渲染 → 打开实际 PNG（必要时 PIL 裁图放大复核）→ `iterlog.py` 记录
→ 修改重渲 → `promote.py` 按 HTTP 200 + md5 提升 `final.png`/`final.snapshot` → 写 `case.md`。

## 4. 修改记录与踩坑

**服务与传输层**

1. 后台渲染任务会被上下文压缩杀掉：表现为响应体截断（`got 258182 of 2…`）或
   完全没有响应体。**改成前台请求 + `timeout: 300000` 后稳定**；已发生的 33 次失败
   不删除，作为真实留痕保留。
2. `curl (28) SSL/TLS connection timeout` 是真实服务故障（件-10 v01 首次请求）。
   按原 DSL 重发即恢复，不猜原因、不改配置。
3. `promote.py` 必须从总根运行、`b05run.py` 必须在 `tmp/<run>/B05/` 下运行，
   因为两者的相对路径基准不同。踩过一次 `FileNotFoundError`。

**DSL 与排版层**

4. **TextFit 只校验单个文本盒**：看不见 (a) 元素之间的重叠，(b) 文字越过卡片内容底线，
   (c) 自动换行的断点位置。这三类问题全部只能靠实际看图 + 2× 裁图发现：
   - 件-08 v04：`tree_glyph` 的 `cy` 是**树干底**，树冠顶 = `cy − height − crown_r`，
     圆顶压住 ① 副标题 → 缩小光晕半径与树高。
   - 件-08 v03：时间轴日期盒里的中文"48 h 内"被圆点划掉 → 末点改成绝对时刻
     `10-13 09:58`（= 到场 10-11 09:58 + 48 h），48 h 移到副标题。
   - 件-09 v01：② 两行说明整体落在卡片外并压住 ③ 标题；④ 说明框溢出 59 px。
   - 件-10 v02：⑤ 说明自动换行把"差 9.1"与"%；全市合计…"拆成孤字行 → 改两条显式单行。
   **对策**：卡片高度改为按实测内容推导（`86 + 内容高 + 22`），并在脚本里写
   `assert 内容底线 <= 卡片底线`，把这类问题变成生成期失败而不是看图才发现。
5. `card()` 只给标题不给副标题时仍占 86 px，产生可见空档 → 要么补真实副标题，
   要么换 `panel()`。
6. `credit()` 每行盒只有 `size×1.5+3`，**不会换行**；长句必须自己拆成多个 `lines`。
7. `coltable()` 会把 `w − Σ列宽` 的差额全部塞进第一列 → 列宽必须自己配平到总和等于 w。
8. `Doc.rect()` 无 `border` 参数；`B.line`/`B.dot` 不存在，要用 `d.line`/`d.dot`。
9. 中文串里不能嵌套 ASCII 双引号（Python 语法炸），改用「」。

**数据与口径层**

10. 数据集自身有缺陷，**处理办法是印在页面上而不是修数据**：岩前 −11 户、
    云屿压线 0 而阻路 15、灾情 113 起未去重（30 起待核实）、件-07 2026-09 风速 0 节。
11. `crown_area_m2` 用 0.72·D²，件-08 用正投影 π(D/2)²，同一株差 9.1 %。
    没有回头统一，而是在件-10 ⑤ 把两式两数与差值同页写出。
12. `wind_kts` 是逐月点采样（`int(rnd.gauss(14, 6))`），不是过程极大值 →
    件-09/10 **拒绝引用风力等级**，避免"平均 14 节吹倒 113 株"这种假因果。
13. 认养没有落到单株 → "认养树达标率"算不出，件-10 ③ 标红并在 ⑤ 给出 3.0 人·日补齐方案。

**留痕层**

14. `iterlog.py` **没有 `--type final`**（`invalid choice`），定稿用 `--type visual --complete true`。
15. 收尾核对发现 `iterations.jsonl` 早期 7 条 `version` 缺 `caseNN-` 前缀：
    按 `image_path` 补齐并加 `metadata_correction` 说明，原始问题/改动/看图时间未改。
16. 闸门拦截不产生请求，因此不会出现在 `requests.jsonl`/`build-log.jsonl`；
    已补写进 `case-09/case.md` 与 `task-metrics.json` 的 `gate_blocked_evidence`。

## 6. 设计选择、经验与未解决事项

**为什么十件共用一套构件还各不相同**：`b05kit` 提供 `card/note_band/timeline/credit/
coltable/chip/disc/outline_rect/tree_glyph`，但骨架随介质变——手机件有状态栏与底部导航，
大屏件用 12 栅格与 3 米字号，打印件有页眉页脚与签字位，说明图有比例尺。
复用构件节省的是正确性成本（一次修 assert，十件受益），不是设计成本。

**最有效的三条经验**：
1. **单一数据源 + 脚本派生**让跨件一致性变成可自动核对的事：件-01/02/04/07/08/10 的
   TZ-JS-0417 与件-03/05/09/10 的总量（98/229/669/2,729、327、87、24.9 %）互相对得上。
2. **把缺陷印在页面上**比修数据更可信，也更省事后解释：−11 户、0 压线、9.1 % 口径差
   都是先被发现、先被写出来的。
3. **assert 比目测便宜**：卡片高度按内容算 + 底线断言，把"看图才发现"的类别压缩到
   只剩重叠与换行点两类。

**未解决**（详见 `portfolio.json.unresolved_issues` 与 `product-brief.md` 第 4 节）：
风险分权重未经历史回溯；两套冠幅公式未统一；三项数据缺陷只做到披露与排期，未回源；
**十件均未做真实用户验证**（无访谈、无可用性测试、无真机字号与照度校验）；
件-06 弧线为示意而非规范尺寸。
