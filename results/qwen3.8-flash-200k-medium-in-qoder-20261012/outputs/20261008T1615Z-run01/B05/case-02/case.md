# 件 02 · 巡检员单株档案卡（户外强光模式）

- 成品：[final.png](final.png)（1080×2400，深色高对比）｜同名 DSL：[final.snapshot](final.snapshot)
  （请求 `B05-case02-v03-20261011T114333Z`，200 响应按字节指纹提升，md5 `14af5245…`）
- 使用画面类型：巡检员手持机的**现场录入态**单株卡（不是列表页、不是详情页模板）。
- 回答的用户问题："我戴着手套、太阳直射，能不能在这一屏里读完档案、录完五项、
  并当场知道风险分是怎么算出来的。"
- 版本：v01 → v02 → **v03**（v02 提交过程中有 3 次真实传输故障，见 `requests.jsonl` 与
  `iterations.jsonl` 的 retry 记录）。

## 这张屏的取舍

| 设计决定 | 原因 |
|---|---|
| 深墨底 + 白字 + 最小 15 px（正文 17-21 px） | 强光模式下对比度优先于美观；顶部绿条直接写明"字号已放大一档"，让模式可被确认而不是靠猜 |
| ① 档案与②实测分家 | 档案是"不动的部分"（胸径/树高/冠幅/树龄），实测是"每次要录的部分"，混在一起就会漏录 |
| ② 每行都显示 `子分 ×权重` | 判级依据必须现场可核，否则巡检员只能信一个黑箱分数 |
| ③ 倾角用"姿态 + 0-10° 标尺 + 近四次读数"三件套 | 单画一个 6.8° 的角在 6° 阈值前只差 0.8°，几何上真实但读不出来；标尺和读数序列才讲得清"为什么现在才报警" |
| ④ 结论卡给动作而非结论词 | "拉起 20.2 m 禁入半径 / 确认班组已到场 / 支撑加固＋疏剪三成冠 / 48 h 复测"，每条带一句执行口径 |
| ⑤ 离线队列 | 树下没信号是常态：要让人知道"现在点了也不会丢"，并区分已缓存与待上传 |

## 数据与一致性

- 树号 `TZ-JS-0417`、香樟、建设路、1987 年栽植、胸径 62 cm、树高 14.2 m、冠幅 9.4 m、
  树龄 39 年（= 快照年 − 栽植年）、倾斜 6.8°、空洞 34 %、铺装隆起 78 %、暴露对象 85
  （公交站/停车位）、历史病害 40、子分 100.0/54.4/78.0/85.0/40.0、R=76、档位"立即处置"、
  工单 `WO-20261227`、状态"作业中"、SLA 24 h、班组"园林二班"、上次巡检 2026-09-28（距今 13 天）、
  本路段在册 169 棵——全部由 `b05data.py`（固定种子 20261011）生成的
  `research/{trees,stats,orders}.json` 读出，页面不写死。
- 近四次读数 5.0 → 5.3 → 5.7 → 6.8°、月增速 0.36°/30 天来自 `stats.json` 的 `featured.series`；
  0.30 的加速阈值、6° 参考线、"树高 + 6 m"的禁入半径是本产品自定规则（脚注已声明）。
- 与件-01 同一棵树、同一工单：件-01 的"档案里的实测倾斜 6.8°，风险分 76（陈拓 2026-09-28 开单）"

## 已知限制

- 虚构演示数据；巡检员姓名、班组、设备电量与"回所联网同步 18:00"均为设定值。
- 强光模式的最小字号、控件高度、戴手套可点区域是**设计假设**，未做真实用户验证。
- ③ 的树形是 DSL 近似（旋转矩形树干 + 圆盘树冠，无矢量 path）；倾角数值以标尺与读数为准，
  不以图形目测为准。
- 本屏不联网：⑤ 的状态是"离线时应当看到什么"的设计表达，不是真实同步日志。
