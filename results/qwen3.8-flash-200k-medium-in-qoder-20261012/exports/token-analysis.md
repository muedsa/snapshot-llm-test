# Token 合并数据分析：`当前目录是总任务根目录。请完整阅读AGENTS__` 会话族

数据源：`.qoder-credits/` 下同一会话族的 3 份 credits-inspector 快照（schemaVersion 3.2，pluginVersion 2.7.4）。
本文只包含合并后的数据分析，口径与置信度见 §9。

## 1. 合并方法与去重结论

三份报告的文件名前缀是同一标题、后缀是不同 session id，容易被当成 3 个独立会话重复相加。实测结果是**严格前缀包含关系**，不是并列关系：

| 快照 | session | 生成时间 (UTC) | trips | billed input | credits | compactions | turns | peak ctx |
|---|---|---|---|---|---|---|---|---|
| `__48da18e9.canvas.tsx` | 48da18e9 | 10-08 17:09 | 1,749 | 174,684,330 | 561.747 | 17 | 22 | 49,818 |
| `__dd9e311e.canvas.tsx` | dd9e311e | 10-09 01:48 | 1,922 | 192,081,375 | 617.265 | 18 | 24 | 149,887 |
| `__1f3b658c.canvas.tsx` | 1f3b658c | 10-11 16:16 | 8,017 | 797,444,242 | 2,588.105 | 85 | 95 | 166,832 |

四条独立校验（全部通过）：

1. `startedAt` 三份完全一致（`2026-10-08T08:11:23.039Z`），`turns / toolCalls / compactions / billed` 单调递增 → 同一长任务被 resume 后重新分配 session id。
2. 以 `(time, inputTokens, credits, ratio)` 为签名做前缀比对：A 的前 1,749 项与 C 的前 1,749 项**逐字节相同**（0 处不匹配），B 的前 1,922 项同样 0 处不匹配。
3. 用 C 的前缀求和可精确复现 A/B 的总量：A `174,684,330` diff=0，B `192,081,375` diff=0（credits 差 0.017/0.022，来自逐程取整）。
4. 并集检查：A∪B 的 18 个压缩时间点全部落在 C 的 85 个之内；A 的 297 个、B 的 334 个 `byFile` 标签全部是 C 的 1,251 个标签的子集；A/B 的 `subagents.scanned=false`，磁盘上也不存在这两个 session 的 `subagents/` 目录 → 无 C 未覆盖的子代理。

**合并结论：合并后数据集 = 快照 C 的完整数据集（8,017 程），A 与 B 不提供任何新增请求、文件、压缩或子代理记录，只保留"进度切片"价值**（用于 §3 的分段增速）。任何把三份 totals 相加的做法都会 3 倍高估。

另需注意：`.qoder-credits/report.json` 是**易变文件**，每次 Stop 钩子都会被重写为当前会话的报告（现已被覆盖为 session 33a4a9a8，875,290 tokens / 4.9 credits）。本文全部数字取自三份 canvas 内冻结的 JSON，不依赖 `report.json`。

## 4. 时间口径：墙钟 ≠ 工作量

以 85 个压缩时间点的间隔衡量，间隔 >45min 记为空闲：

- 墙钟跨度 **79.6h**（10-08 08:39 → 10-11 16:16）
- 活跃 **36.4h**，空闲 **43.2h**，分布在 9 段
- 最长三段：`10-10 13:50 → 10-11 05:47`（15.9h）、`10-09 11:29 → 10-10 01:03`（13.6h）、`10-08 17:04 → 10-09 01:26`（8.4h）；另有 6 段 0.8–1.0h 的短停顿

强度必须按活跃时间计：**21,907,169 tokens / 71.1 credits / 220 trips 每活跃小时**。按墙钟摊算是 32.5 credits/h，会把 43.2h 的停顿误读成成本。

## 8. 三个乘数（合并数据揭示的机制）

总账可分解为 `trips × 每程上下文`，两边同时失控：

1. **1.006 calls/trip** —— 8,017 程做了 8,063 次调用，即几乎每次往返只发起一个工具调用。4,395 个 Bash 各自独占一次完整的 99.5K 上下文重发；95 轮用户输入展开成 8,017 程。
2. **均值 99.5K 的锯齿** —— 自动压缩固定在 84% 窗口才触发，每程从 5.3K 涨到 168.8K，均值被顶在 99.5K。
3. **38.4K/程的地板** —— 与工作内容无关的系统提示词 22,574 + 技能附件 8,853 + 压缩摘要 6,983，随程数线性放大。

## 9. 口径与置信度

- **token 全部是推导值**：8,017 程的 `usageSource` 均为 `transcript-ratio`，即 `S = context_usage_ratio × 200,000`（`breakdown.mjs:276`）。代理日志不存在（`logExists:false, configured:false`，`proxy.matched=0`），`availability.tokens = derived`。
- **credits 是实测值**，应作为主口径：2,588.105。`availability.credits = measured`，`coverage = 1`（无遗漏程）。
- **`outputTokens` / `cachedTokens` 不可用**（`availability` 标记 `unavailable`，报告里的 0 只是占位）。归因使用未扣缓存的毛值 → 若服务端有提示缓存，真实计费低于本文估算。
- **`amplification` 指标不可用于跨快照比较**：定义是 `billed / 最后一程上下文`（`breakdown.mjs:499`），分母取决于快照落在锯齿的哪个位置——A 报 3,506×、B 报 1,282×、C 报 4,780×，而三者数据同源。应改用每程均值 99,469。
- **文件级 `billed` 不是 `self × trips`**，而是每程按 `pool × (est / aliveEstSum)` 比例分摊（`:342-346`）。例如 `case08_sky.py` 的 8,972 个 alive trips 分摊后每程仅约 575 tokens。文件级数字**只用于相对排序，不可当绝对单价**。

## 10. 优化杠杆（按量级，区间为估算）

| # | 杠杆 | 作用面 | 估算节省 |
|---|---|---|---|
| 1 | 批量并行独立工具调用（1.006 → 2.5+ calls/trip） | 削减地板付费次数 8,017 → ≈3,300 | −181M / −23% / ≈−590 credits |
| 2 | 提前压缩：84% 阈值 → ≈50%（每程均值 99.5K → ≈60K） | 均值 | 理论 −40%，扣新增 60 次压缩与重读后 **25–35%** |
| 3 | 拆散整文件 Write/Read 循环（kit 模块 + 定向 Edit + offset/limit 读） | 117M 池子砍半 | −58M / −7% / ≈−190 credits |
| 4 | 收窄 Bash 输出（重定向落盘后取局部，而非整段回显） | `tool_result\|Bash` 83.6M | −30~40M |
| 5 | 控制思考重发（机械步骤降低 reasoning effort；更早压缩清空思考） | 141.7M | 与 #2 重叠 |
| 6 | 检索类工作交给子代理 | 2 个 Explore 花 0.79M/6.8 credits 完成的工作，主循环做要按 99.5K/程付费 | 结构性 |
| 7 | 精简根 AGENTS.md | 系统提示词 22,574/程中 AGENTS.md 仅约 2.2K tokens | 减半 ≈ −8.8M / −29 credits（收益有限） |

#1 与 #2 作用在同一个乘数上不可相加；同规模重跑的合适应达到 **−40%~−55%（约省 1,000~1,400 credits）**。
最优先动作是开启 credits 代理日志（`~/.qoder-credits-proxy/usage.jsonl`），把每程从比例估算换成实测，否则以上拆分始终只有 credits 一项可较真。
