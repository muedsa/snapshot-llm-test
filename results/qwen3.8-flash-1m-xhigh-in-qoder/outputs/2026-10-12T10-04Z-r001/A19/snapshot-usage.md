## 2. 题场是怎么构造并核验的

生成器从种子 `20261012` 出发，按“洗牌 + 行内交换 + 组合覆盖重洗 + 尺寸补写”得到 64 个对象，
然后**不看种子、只看结果**逐项核对：颜色各 16、形状各 16、16 种颜色×形状组合齐全、
每种颜色与每种形状都覆盖 48/64/80 三档、每行至少 3 色 3 形、每格恰好一个主体。
`verify_scene.py` 再把服务返回的 PNG 逐格量化：以颜色掩膜 + 手写连通域标出主体，
用外接框读出尺寸、用“填充率 + 5×5 角窗占用 + 中心是否为底色”判形状、用组件像素中位数判颜色，
64 个主体的尺寸/形状/颜色/中心与计划完全一致（中心误差 ≤3 px），且没有任何主体压出本格。

ID 文字固定在主体下方 6 px、左对齐主体左边，**始终在主体框之外**，不计入主体。
圆环按题面：外径 = size，内径 = size/2，内圈以白底画出形成孔。

## 3. 遮挡等价

两份 DSL 由同一个 `build(hidden)` 生成，只有传入的隐藏层节点列表不同（A 遮 3 个、
B 遮 5 个且颜色构成不同）；画布、背景、面板、8 个可见对象、遮挡板与文字全部相同。
隐藏对象全部落在遮挡板内，最小内缩 A 版 32 px、B 版 24 px，隐藏层不使用阴影或滤镜。

像素判定按要求做：Pillow `convert('RGBA')` 解出 8 位未预乘 RGBA 四通道数组直接比较，
不合成白底、不缩放、不忽略 alpha：尺寸相同、**不同像素数 0、最大通道差 0**、
像素数组 SHA-256 相同。文件层也恰好相同（两文件字节数与 SHA-256 一致），
`equivalence.json` 同时记录两者并说明“哈希相同只是本次响应的巧合，判定依据是像素数组”。
另外直接量了每个隐藏对象 footprint 的像素：全部等于遮挡板颜色，即“没有泄漏”是被测出来的，
不是被声称的。

覆盖：复合属性检索（Q01、Q02）、严格中心左右关系（Q03、Q04）、距离（Q05、Q06、Q13、Q15）、

每题都写明坐标原点（画布左上角、x 右 y 下、像素）、比较标准（“中心”“严格大于”“面积键”
“并列按 ID 升序”）与容差；构造时断言答案唯一（最近对象、距离比较、列内最大等都留了
≥1 px 的区分度），避免并列导致多解。
Q17、Q18 的标准答案是“无法确定”，依据正是第 3 节的像素等价：可见部分逐通道相同而隐藏内容不同。

## 5. 遇到的问题与修复

| 现象 | 原因 | 修复 | 验证 |
|---|---|---|---|
| 直角方被读成圆角方 | 形状判据只看 bbox 四个角点，抗锯齿使角点常为空 | 改为 5×5 角窗占用率 + 填充率双判据 | 64/64 形状与计划一致 |
| 圆环颜色被读成橙色 | 取的是中心像素，而圆环中心是孔（白底） | 颜色取组件像素的中位数 | 64/64 颜色与计划一致 |
| B 版隐藏对象距遮挡板边缘只有 12 px | 隐藏坐标按视觉摆放 | 重新排布，最小内缩提高到 24 px | `hidden_insets_px` + 足迹覆盖检查 |
| Q15 初稿“离遮挡板中心最近的可见对象”两对象同距 | 可见对象左右对称布局 | 改成“主体矩形到遮挡板矩形的最短距离”，并断言与次优相差 ≥5 px | 答案唯一（V07，96.0 px） |
| Q04 与 Q03 答案相同 | 第二步过滤（形状）恰好包含第一步全部结果 | 第二步改按尺寸 48 过滤，并断言 Q04 是 Q03 的真子集 | 答案 [G38, G39] |
