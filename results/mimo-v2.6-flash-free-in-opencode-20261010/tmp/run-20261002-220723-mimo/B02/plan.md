## 1. 自选项目

**候鸟湾观鸟站 / MIGRANT BAY BIRD OBSERVATORY**

一个虚构但按真实社区组织方式运作的滨海湿地观鸟站，位于虚构的「候鸟湾湿地公园」。
不是自然保护区管理局，也不是商业景区——是「1 名协调员 + 24 名志愿者 + 小额捐赠」
维持的社区自组织，观测数据回传给地方鸟类记录中心。

| 维度 | 内容 |
|---|---|
| 服务对象 | ① 亲子家庭（孩子 6–12 岁）② 退休/长者观鸟人 ③ 周末上班族新手 ④ 中小学与自然教育机构 ⑤ 站点志愿者 ⑥ 小额捐赠者 |
| 运作方式 | 免费开放 06:00–18:00；每月 1 次公众活动、每年 2 次迁徙季同步调查；靠月捐与政府购买服务维持；望远镜 12 台需登记借用 |
| 使用需求 | 认知（知道有这件事）→ 到访（找到路与规则）→ 参与（上课、看板、借镜）→ 记录（填表、上传）→ 留存（证件、日程、成为志愿者）→ 反馈（看到成果、续捐） |
| 数据来源 | 观测记录（时间/物种/数量/行为/天气）、活动排期、捐赠档位、设备借用 —— 全部自拟演示数据，画面标 `演示数据 DEMO` |
| 真实性边界 | 场景、运作、需求按真实项目写清楚；品牌、站名、地名、人名、电话、数据均虚构，不宣称真实部署、不引用未核实数据 |

## 2. 视觉概念

**「一条迁徙弧贯穿十件」**：所有作品共享同一套「鸟阵人字标 + 湿地深青 + 落日橙强调 +
双细线分隔 + 页脚三段信息」的识别系统；但每件按内容、观看距离与使用环境换构图。

- 主视觉隐喻：候鸟「人字形」阵列 —— 由圆点与斜段组成，可缩放成 logo（24px）或大装饰（600px），
  这就是检验「复用组件在不同密度/比例下是否有效」的主对象。
- 色板：湿地深青 `#0B3B3A`、潮线青 `#7FB2A8`、鸥灰 `#E8EDE9`、滩涂沙 `#D9CBA8`、
  落日橙 `#E4622C`（唯一强调色，全系统只用于「此刻该做的事」）、夜靛 `#132A44`。
- 字号阶：12 / 14 / 16 / 20 / 24 / 32 / 48 / 64 / 96。
- 网格：外边距 = min(w,h) × 6%（下限 40px），主体 12 列。

## 5. 执行步骤与完成标准

1. 写 `design-system.json`（真实用到的规则）→ `lib-b02.ps1`（带 `Fit` 宽度校验的组件库）
2. `gen-b02-a.ps1`（01–05）/ `gen-b02-b.ps1`（06–10），门槛 `problems = 0` 才送渲染
3. 每件真实渲染 → 实际打开看 → 修 → 重渲染 → 再看；不设上限；首版即合格的不制造无意义迭代
4. 整体审查：10 件是否都像同一项目、各自是否适合其环境、复用组件在密度两端是否成立
5. 交付：10×(final.png+final.snapshot+case.md) + portfolio.json/md + gallery.html +
   snapshot-usage.md + task-metrics.json + project-brief.md + design-system.json + touchpoint-map.json

**完成标准（自定，逐件可对照）**
- 文字零溢出（生成期 `Fit` 报警 = 0）、零遮挡、零裁切；
- 每件画面内可见 `演示数据 DEMO`；
- 每件的「任务」在图上能找到完成入口（时间/地点/按钮/编号/列头）；
- 数据自洽（可验算的数字要对得上）；
- 同一系统在 10 件上可辨认（标 + 色 + 页脚），但构图不重复。

## 6. 风险与已知限制

- 读图工具按路径缓存 → 每次看图复制到唯一文件名；
- `browser.preview` 不可用 → 直接打开图片文件；
- 中文自动换行无禁则 → 正文一律 `TLines` 手动断行；
- `Transform matrix` 必须带外层括号；`border` 必须 `width style color`；
- token / 图像 / 费用平台未提供 → 记 `null`。
