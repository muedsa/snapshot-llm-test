## 0. 这份复核的边界（先说清楚不能主张什么）

本题**没有做任何田野调研、用户访谈、问卷、A/B 测试或可用性测试**，全程没有任何真实用户参与。因此下文把「改善」严格分成两栏：

- **从最终图片上直接可观察的改善**（observable from the final image）：任何拿到这张图的人都能自己数、自己比、自己核对的事实，例如「三张档位卡写的是 3 / 9 / 17，最后一根条正好满格」。
- **需要用户实验才能验证、本轮未验证的效果**（not validated by user experiment）：例如「3 秒完成比价」「减少漏服」「读者不再把概率当分钟」。这些是**设计目标**，不是已达成的事实。

资料方面：本轮真实抓取 41 次研究请求，其中 gov.cn 政策检索接口虽然返回 200 但 `totalCount=0`，nmpa 与 nhc 返回 412 反爬页，多词 Bing 查询被截断。**没有取得任何一条法条、国家标准或服务标准原文**。所以画面与本文件都不写条款号、不写罚则金额、不写国标数值，也不写任何机构背书；唯一命中的外部线索是 Bing RSS 短词检索的**二手摘要**，一律标为「检索摘要（Bing RSS，2026-10-08）」。

所有价格、指标、时刻、单号、地址、费率、规则都是**自拟演示样例 DEMO**，画面内已逐处标注。三个从一般常识出发的题目（02 用药、08 降水概率、10 快递时间窗）在来源栏明确写 `self-authored-observation`，不冒充研究结论。

## 2. 逐件复核

### case-01 货架单价换算

- **来源 / 假设**：`self-authored-observation`。「货架标价不写单位价」是日常观察，不是被引用的事实。二手线索：《明码标价和禁止价格欺诈规定》检索摘要（Bing RSS，2026-10-08），只作为「应标明计价单位」的选题依据，画面未引用条文号。假设：同组必须同单位才可比；读者只给 3 秒。
- **场景要求**：家庭采购者，超市货架前举着手机与店内标签对照，单手、光线杂乱。目标是 3 秒内知道哪件单价最低。
- **重构选择**：从「两行总价 + 各自规格」改为三层货架网格（坚果按 100 克、牛奶按 100 毫升、抽纸按 100 抽），每格直接给单位价，并标出「总价最便宜」与「单价最便宜」是否同一件。原本 3 次「取数 → 相除 → 排序」压到 1 次读取；9 个价签的心算全部代做，并把每行原本的心算步数（2 步 / 3 步）作为可见数字显示出来。
- **从最终图可观察的改善**：每行总价与单位价同屏；`disagreeCount = 3` 与三组一一对应，可以逐组核对；单位价一列右对齐、同小数位，可目视比大小；步数标签 2 / 3 把「原本要算几步」变成数字。
- **需要用户实验、本轮未验证**：「3 秒完成比价」是目标，无计时实验；「减少选错商品」需真实购买对照；读者是否真看单位价列，未做眼动或点击验证。

### case-02 当日用药卡

- **来源 / 假设**：`self-authored-observation`。「说明书难读」是日常观察；漏服与禁忌按通行说明书含义整理，**本轮未取得任何具体说明书原文**，无二手引用。假设：一天 3 次、随餐是常见慢病节奏（演示）；读者需要大字号与图示。
- **场景要求**：慢病老人 / 照护家属，厨房窗台药盒旁站着看；竖屏 540×1240，单页可打印贴在药盒上。
- **重构选择**：从「按适应症 / 用法用量 / 不良反应 / 贮藏编排、要翻页」改为上半「今天 3 次」当日时间轴 + 已服/待服双色标记，下半 4 张必答问答卡，底部 7×3 一周药格。翻页 0 次；「今天还剩几顿」由 1/3 进度与待服环直接给出（taken 1 / left 2 / 33.3%）。
- **从最终图可观察的改善**：实心圆 vs 空心环可不依赖文字分辨；图例文字与标记同色且一致（a02 修掉的矛盾已消失）；4 卡各只一问一答、字号明显大于 6 号；21 格 = 7 天 × 3 次，与「一天 3 次」同源。
- **需要用户实验、本轮未验证**：老人能否独立读懂（无使用者测试）；漏服是否减少（依从性需随访数据）；颜色对色觉障碍者是否可辨（只做了明度差，未做色觉模拟）。

### case-03 体检报告行动清单

- **来源 / 假设**：问题观察是 `self-authored-observation`；参考区间含义是 `secondary-search-snippet`（WS/T 402 相关检索摘要，Bing RSS，2026-10-08），画面只呈现区间与动作，**不引用条文号、不给出诊断结论**。假设：出界即需关注，但处理等级是产品化规则而非医学判断。
- **场景要求**：35 岁上班族，体检中心前台拿到纸质报告或回家看手机；深色 1440×1080 横屏。
- **重构选择**：从「项目 + 数值 + 区间 + 一个箭头」改为每项一条参考区间刻度尺 + 当前值指针 + 出界距离，右侧连线到动作卡，最右汇总 3 正常 / 2 复查 / 1 提前并单列「这次不用动的 3 项」。原本「看箭头 → 查区间 → 想怎么办」3 跳压到 1 跳。
- **从最终图可观察的改善**：每项当前值落在自己的区间尺上，偏离幅度可横向比较；区间条中性色、指针状态色，不再把区间误读成异常（a01 修掉）；数值去掉无意义尾零（142 而非 142.00）、单位为 μmol/L 而非 ASCII umol/L（a02 修掉）；汇总 3 / 2 / 1 与逐项动作卡数量一致。
- **需要用户实验、本轮未验证**：任何健康判断效果都不能在无临床 / 用户验证下主张；「看完知道该做什么」无理解度测试；三档动作阈值未经医学审核。

### case-04 电费阶梯账单

- **来源 / 假设**：`secondary-search-snippet`。阶梯机制依据发改价格〔2011〕2617号 检索摘要（Bing RSS，2026-10-08），账单栏目表述亦来自检索摘要；**三档电量与三档单价是自拟 DEMO**，画面不引用条文原文。假设：读者关心「为什么涨」，且归因必须能加回去核对。
- **场景要求**：家庭月底看电费短信的人，手机横屏 1760×980，纸色底。
- **重构选择**：从「两个总额 + 一个百分比」改为水位阶梯 + 分档瀑布：本期柱切成三档叠块，左对上期、右列增量，底部把分档增量加总回到 105.77 元做闭合核对。原本 3 跳压到同屏。
- **从最终图可观察的改善**：标题与页脚都是 +80.8%，与 KPI 同源（a01/a02 修掉的 80.6% / 80.8% 矛盾已消失）；单价 4 位小数使画面上的 60 × 0.6380 = 38.28 真的成立；两期柱共用刻度，220 度与 356 度长度差真实；分档增量之和 = 105.77 元，可当场加总核对。
- **需要用户实验、本轮未验证**：读者能否理解归因（无测试）；「涨阶梯是真主因」在真实账单上需用户数据；80.8% 电量 vs 11.8% 单价的并置是否易被误读，未做实验。

### case-05 站台到发与换乘

- **来源 / 假设**：`secondary-search-snippet`（上海地铁官方页面检索摘要，2026-10-08），画面写「末班车进站前 3 分钟停止售票」并标出处；班次、台号、换乘距离是 DEMO。假设：候车只有约 40 秒注意力；等待时长需要可比较的长度而非纯数字。
- **场景要求**：通勤者在站台候车，人多、时间紧；1920×620 超宽横条，模拟站台大屏。
- **重构选择**：从「方向屏 / 到发屏 / 换乘指引三块分开」压到同屏一次扫视：顶部线路色带、左侧去向、中间大字倒计时 + 三条按分钟等比的到发条、右侧换乘卡（7 号线 180 m 本侧、12 号线 240 m 对侧）。
- **从最终图可观察的改善**：三条长度按 3 / 9 / 16 分钟等比，可目视比较；倒计时是全屏最大字号、色带横贯全宽，不需切换视线；换乘卡同时给距离与「本侧 / 对侧」，把米数翻译成走哪边；非首班填充与轨道明度差明确（a01 修掉）。
- **需要用户实验、本轮未验证**：「40 秒内判断」无计时测试；站台强光与远距离可读性未实地测量；与真实班次准点率无关、未做对照。

### case-06 信用卡分期真实年化

- **来源 / 假设**：`secondary-search-snippet`（央视 2025-07 关于「分期」诱导的检索摘要，2026-10-08）；画面**不引用任何条款、不引用利率上限数字**。商品价、期数、费率是 DEMO。假设：读者只记得住一个数字，必须把多个口径放在同一量程；年化按每期现金流 IRR 计算。
- **场景要求**：购物后被收银员推荐分期的人，收银台前、手机在手、当场决定；竖屏 900×1400 深色底。
- **重构选择**：从「432 元 / 36 元 / 0.6% 三个说法各说各的」改为 12 期每期现金流竖排（本金 + 手续费）+ 一根共同量程尺把 7.20% / 13.03% / 13.84% / 13.29% 并列。原本 4 跳（取数 → 除 → 换年 → 比）压到 1 次目视比较。
- **从最终图可观察的改善**：全页费率统一两位小数，标题 / 刻度 / 图例 / 页脚完全一致（a01、a02 修掉的 13.8% vs 13.84%、7.2% vs 7.20%、缺百分号问题已消失）；四口径同尺，可直接看出真实年化接近名义的两倍；536 标签压在本金条上，柱义与标签对齐；12 段本金 + 手续费加总回到 6432 元。
- **需要用户实验、本轮未验证**：「读者因此拒绝分期」是假设、无行为数据；同尺呈现是否导致高估/低估未测；IRR 口径是否被普通读者正确理解未测。

### case-07 退租押金扣减瀑布

- **来源 / 假设**：`secondary-search-snippet`（租赁押金相关检索摘要，Bing RSS，2026-10-08）。画面写「合同约定退租后 7 日内退还（演示约定 DEMO，以合同为准）」，**不引用任何法条或罚则金额**。假设：扣减分「固定可扣」与「可争议」两类；读者最关心差额。
- **场景要求**：租客退租前一晚在家逐项对账；竖屏 560×1180 纸色底。
- **重构选择**：从「中介给一个总数」改为 6000 元向右逐项扣减的瀑布 + 逐项台账（可争两笔打斜纹）+ 末端两条结局卡与余额条。原本 4 跳（问明细 → 分类 → 加总 → 算差额）压到一条瀑布画完，差额 600 元单独成卡。
- **从最终图可观察的改善**：押金中性墨、扣减靛蓝、争议琥珀三类一眼可分（a01 修掉）；斜纹透明度降到 33 后仍标得住行又不遮 14px 原因文字（a02 修掉）；说明在两句之间换行、不再拆短语；两条结局差额 600 元 = 争议项合计，可核对。
- **需要用户实验、本轮未验证**：真实纠纷中争议项能否争回，本轮不能主张；「读者敢去争取」需行为验证；斜纹在低亮度屏上的可辨性未测。

### case-08 降水概率怎么读

- **来源 / 假设**：`self-authored-observation`。两种常见误读是日常观察；概率解释按通行气象含义整理，**本轮未取得官方定义原文，画面明写不引用任何标准条文**。假设：100 格点阵能把「长期 100 次里有多少次」变成可数；决策只需二值结论。
- **场景要求**：早上出门前看手机的通勤者，门口换鞋几秒钟；方形 1000×1000 深色底，手机满屏。
- **重构选择**：从「一行『降水概率 40%』让读者自己想象」改为 100 格点阵（40 格填色）+ 三句翻译卡分别否掉两种误读并给出长期频率含义 + 三小时卡片与出门结论。原本 3 跳（读 → 想 → 决定）压到点阵直读 + 一行结论。
- **从最终图可观察的改善**：点阵确实 40 / 100 格，与文字「青格 40 个 · 暗格 60 个」一致，**可逐格数**（`(i × 37) mod 100 < 40` 在 i=0..99 上是 0..99 的排列，恰有 40 个）；三句翻译都在第一个逗号处断开、每卡恰好两行、无单字孤行（a01 修掉）；三小时条按 40 / 70 / 20 等比，最高者带「最高」标签；结论行用最大强调色给二值答案。
- **需要用户实验、本轮未验证**：「不再把概率当分钟」需前后测理解度实验；100 格是否真比一句话易懂未做对照；**本轮无官方定义原文，不能主张画面解释等同任何官方口径**。

### case-09 路侧停车限时计费

- **来源 / 假设**：计费规则本身是 `self-authored-observation` 的演示 DEMO；停车价格线索来自 `secondary-search-snippet`（Bing RSS，2026-10-08）。**超时后果写为「不是继续收费，而是按违规停放处理（演示规则 DEMO，以现场标志为准）」，不引用罚则金额、不引用条文**。假设：2 小时限时可以画成一个整圆；累计与分段费用必须分开呈现。
- **场景要求**：临时办事的司机，站在路边车边用手机查；竖屏 840×1340 纸色底。
- **重构选择**：从「一句文字规则 + 一个限时数字」改为钟面（2 小时 = 整圆、三段扇形、指针 27 分钟）+ 一根 120 分钟计费刻度（自带数字与两道档位切换线）+ 三张累计卡。原本 5 跳（读规则 → 拆段 → 逐段乘 → 累加 → 和现在比）压到钟面与刻度一次画完。
- **从最终图可观察的改善**：三张档位卡写**累计 3 / 9 / 17 元**，最后一根比例条正好满格（a01 把分段增量 3 / 6 / 8 误标成累计、条画成 8/17 的错误已消失）；刻度自带 0 / 15 / 27 / 60 / 120 分钟数字与两道切换竖线，不再靠说明文字才知道量程；钟面三段与三卡一一对应；「距限时 93 分钟」= 120 − 27，可核对。
- **需要用户实验、本轮未验证**：「钟面比文字易懂」是假设、无对照；超时后果是否被正确理解未测；真实停车场费率与本图演示规则无关、未实地核对。

### case-10 快递到件时间窗

- **来源 / 假设**：`self-authored-observation`。「节点多但没有时间窗」是日常观察；到件时间窗与异常判定是**产品化自拟规则，标注演示 DEMO**；**本轮未取得快递服务时限的官方原文，画面不引用任何服务标准条文**。假设：预计到达应表现为一段窗而非一个点；等待与窗宽必须用同一条时间轴。

## 3. 跨件的设计判断

**做得对的地方**

1. **一个数字只有一个出处**。全部数值先在 `calc-b06.json` 算好，生成器只读不改，所以每个百分比的分子、分母、单位与时间范围都同源。视觉迭代中暴露的三处数字矛盾（case-04 的 80.6/80.8、case-06 的 13.8/13.84 与 7.2/7.20、case-09 把分段增量当累计）都是被读图发现的，不是被脚本发现的 —— 说明**看图这一步不可省**。
2. **每件都有可当场核对的闭合关系**：case-04 分档增量和 = 105.77、case-07 两结局差 = 争议合计 600、case-09 120 − 27 = 93、case-10 43/78 = 55.1%、case-08 点阵 40/100 可逐格数。读者不必信任，可以自己加。
3. **先探针后依赖**。case-07 的斜纹、case-09 的钟面扇形与刻度、case-04 的分档瀑布都先做了独立探针 / 冒烟渲染（`B06-smoke-01`、`B06-probe-hatch`、`B06-probe-hatch-a2`）并用像素扫描验证几何，再让正式作品依赖它们。
4. **失败如实记录**。412 反爬、`totalCount=0`、多词查询被截断、一次 `read` 串图判定 `not-verified`，都原样留在日志里，没有被抹平。

**这次踩到、值得写下来的坑**

- **看图工具会串图**。本次有多次 `read` 返回了别的文件的像素。对策是每次都核对 `PLAINSIGHT NN / 10` 报头，不符就丢弃，用新 GUID 文件名 + 画一圈描边 + 等待后重读。case-02 的 a03 正是因此被判 `not-verified`，同一处改动在 a04 上重新确认。
- **PowerShell 变量不区分大小写**。探针阶段一个 `$L` 静默覆盖了 `l`（left）参数，服务返回 200 但几何全错 —— 这类缺陷只有看图和像素扫描能发现。
- **不能在画面里临时算数**。早期所有数字错误都源于「画面上顺手算」，改为只读 calc 之后没有再出现同类问题。

**如果继续迭代，我会改的三件事**

1. case-07 的 560×1180 竖屏在四条扣减之后，台账区仍偏密；可以再收一档字号换取行距。
2. case-05 的 3.097 超宽比例在手机上必然要横持；若目标是竖持，需要另做一版 1080×1350 的裁切方案（本轮未做）。
3. 十件里深色 5 件 / 纸色 5 件是按题目内容分的，不是按观看环境分的；若要服务夜间场景，case-01 / 04 的纸色版本应补一个深色变体（本轮未做）。
