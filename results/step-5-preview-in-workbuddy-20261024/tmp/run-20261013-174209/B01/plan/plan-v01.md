## 一、总体创作主张

十件作品覆盖**十种实质不同的使用任务与视觉语言**，不共用同一版式：
控制室数据墙、店内菜单板、赛事集结屏、医疗叫号屏、游戏主视觉、个人财务复盘、
博物馆导览海报、电竞社交对比卡、城市环境看板、音乐节日程卡。
每件都回答「谁、在何时何地、用什么设备、要完成什么」，并据此决定媒介尺寸、
信息密度、字号下限与配色。全部数据为自拟演示数据（部分按真实规律计算生成，
如轨道角度、海拔剖面、24h 污染物曲线），计算过程与几何比例保持一致。

## 二、逐用例定义与完成标准

> 每条标准含 ID / 可观察条件 / 检查方法。检查方法记为实际执行的动作：
> `view-zoom`（实际打开成品图并分区放大）、`pixel`（程序化像素/几何核对）、
> `dsl`（DSL 结构与参数核对）、`calc`（数值/几何复算）。

### case-01 远瞳 7 号 · 深空遥测数据墙（2560×1440）
- 受众/场景：任务控制中心飞控团队，4K 值守大屏，24 小时运行
- 使用目标：一屏掌握探测器健康度、能源预算、下行链路强度、轨道相位与
  下一事件倒计时；异常须最先被看到
- 内容范围：子系统状态矩阵、电源预算环、信号强度曲线、轨道扇形示意、
  事件时间线、底部告警条（虚构探测器「远瞳 7 号」木星飞掠前 36 小时）
- 观看环境：3–8 米外大屏，暗环境，数字须等宽易读
- 标准：
  - C01-1 完整呈现：6 子系统状态 + 电源 4 段 + 链路曲线 + 轨道示意 + ≥5 个
    事件，无占位文本。检查：view-zoom 六区逐块
  - C01-2 等宽字体用于全部动态数字，字号 ≥22px。检查：dsl + view-zoom
  - C01-3 告警条（1 条 CRITICAL + 2 条 WARN）在视觉层级中最高，位于视线
    起点区。检查：view-zoom 整图
  - C01-4 信号曲线由真实函数生成（仰角 → 信噪比），采样点几何与数值表一致。
    检查：calc + pixel
  - C01-5 深空黑底上文字对比度 ≥7:1，无低对比灰字。检查：pixel

## 三、通用完成标准（适用于十件）

- G-1 每件 `final.png` 为 open-snapshot 服务真实响应字节，同名 `final.snapshot`
  完整自包含（无外部文件依赖、无 Image 嵌入）。检查：dsl + 请求日志
- G-2 每件至少一次整图实际查看 + 分区放大查看；裁切/遮挡/对比度问题修复后
  重渲染并复查。检查：iterations.jsonl + 查看记录
- G-3 文字无裁切：所有 Text 声明盒宽度 ≥ 估算墨迹宽 1.03 倍（CJK 1.0em、
  ASCII 0.56em 估算 + 成图墨迹核对）。检查：dsl + pixel
- G-4 数值类图形（环/条/曲线/剖面）几何比例与源数据一致。检查：calc + pixel
- G-5 十件在尺寸、场景、视觉语言上实质不同；同版式换色不计入。检查：
  portfolio.json 逐件对照
- G-6 虚构品牌/数据/角色在 case.md 与 portfolio.json 标注，不宣称实际部署
