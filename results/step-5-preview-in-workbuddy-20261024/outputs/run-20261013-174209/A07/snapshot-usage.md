## 6. 设计选择、经验与未解决事项

关键设计选择：

- 路线算法用「状态 (station, line) + 字典序代价 (edges, transfers)」的 Dijkstra。
  把「换乘次数」编码进状态的第二维，可以在同一边数下自动选换乘最少的方案，
  不需要先求全部最短路径再排序。
- 无障碍约束按题面精确实现：起点/终点必须 `accessible`；扩展时若「改变线路」
  且当前站 `accessible=false` 则禁止该转移。中间经停 inaccessible 站是允许的。
- 独立核验：另写一段「BFS 求距离 + DFS 枚举全部最短路径 + 逐路径计算换乘数」
  的代码，确认 Dijkstra 得到的换乘数确实是全部最短路径中的最小值。
  三个 query 均通过。
- 地图布局让三条线各占一条水平带（y=200/430/660），转折只在需要避开重叠时
  使用 45°/90°；换乘站用方形「换」徽标与普通圆点区分，避免与线条交叉混淆。
- 无障碍缺失站用「白底彩环」而非删除，并在图例与状态表中说明「可乘车通过」，
  既不删线路也不误导。

可复用经验：

1. 「边数最少 + 换乘最少」这类双目标最短路，把第二目标编码进 Dijkstra 状态的
   字典序代价最省事，且天然满足「边数相同时换乘最少」。
2. 折线角度合规性可以用「从 DSL 的 transform 矩阵反推 atan2」的方式自动核验，
   比肉眼可靠；本题即靠此发现 68.2° 的违规段。
3. 约束语义要先回读题面再写代码：本题「可乘车通过但不能作为起点/终点/换乘站」
   与「完全不能经过」是两种完全不同的图，误读会导致 3 个 query 全错。
4. 枚举全部最短路径做独立核验，是验证「换乘最少」这类次级目标的有效手段。
