# case-08 · 分享给下一任租客的「这套房的故事」

- **载体**：手机长图 900×1900（竖向分享卡，比例 0.474，社交软件里点开即全屏、不能缩放）
- **受众**：下一任租客（未署名，画像：看房阶段，只关心「这房以前出过什么问题」）
- **时刻**：2026-10-01，由房东陆文君从房谱导出并分享
- **用户意图**：30 秒看完这套房 39 个月里发生了什么，
  并且知道「哪些事他们已经提前替我做完了」
- **状态**：结算完成后导出 · 含 2 处新增损伤的坦白说明 + E-02 暂挂这一件没做完的事

## 场景与内容

这不是 App 界面截图，是一张**会被导出成图片发出去的东西**。七段结构：

1. **封面**（0–496）：品牌块 + 生成日期；一句人话作为标题——
   「这套房住了 3 年零 3 个月，换过 2 处零件，**2 个地方有新的划痕和钉孔**。
   这些我们没有藏。下面是逐条明细。」下面三张锚点卡（K-02 已修 / B-02 已修 / K-01 新增），
   底部一条黄黑危险条纹
2. **01 · 三十九个月里，这套房发生了什么**：真实时间轴，5 个节点
   （2023-07 入住首拍 → 2024-03 R-2403-118 → 2025-06 R-2506-042 →
   2026-09 退租拍摄 → 2026-10 差分完成），节点上下交替、首尾标签左右对齐
3. **02 · 12 个锚点现在各自是什么状态**：3×4 状态卡网格，每张卡带自己的黄色标记牌
   与判定色（未变化 / 已修复 / 新增损伤 / 暂挂 / 未拍摄）
4. **03 · 两处新增损伤，共 ¥200**：K-01 ¥120、W-02 ¥80，各带判读与「判定：租客责任」
5. **04 · 还没做完的那件事**（琥珀）：E-02 阳台地漏，退租时 4 张都没拍到标记牌，
   判「暂挂」——「这一块既不计入损伤，也不当成没问题。补拍期限 2026-10-07」
6. **05 · 你搬进来时，会拿到什么**：四栏数字（12 个锚点标记牌 / 39 个月的历史照片 /
   2 条维修闭环记录 / ¥200 本次已结算），每栏带一句解释
7. **06 · 电表抄见**：`1284 → 3611 kWh` + 「你只需核对这两个数」
8. **页脚条**（深色 158px）：导出人、导出时间、扫码说明、**虚构声明**、二维码示意块

## 视觉选择

- **正文改用衬线体（Noto Serif CJK SC）。** 前面 07 张全是无衬线的操作界面，
  这张是「给人读的说明」，衬线让读者知道内容性质变了。
- **把结论放在最上面，而不是把数据放在最上面。**
  下一任租客最先需要知道的是「这房出过什么问题」，不是「12 个锚点的编号规则」。
- 锚点卡在封面和状态网格里重复出现（同一套黄黑标记牌），
  让读者在看到编号之前先见过这个物体的样子。
- E-02 单独占一段而不是塞进状态网格的注脚：
  **这份交接说明里唯一还没解决的事，值得单独一段。**
- 虚构声明直接印在成品长图底部——这张图会被转发出去，声明必须跟着它走。

**本轮实际发现并修掉的缺陷（4 处，每处均重渲染并复验通过）**：

1. **底部三块（电表抄见 / 页脚 / 虚构声明）互相压住并超出 1900px 画布**：
   v01 里这三块的总高超过剩余空间，虚构声明的最后一行落在画布外。
   定位：crop 放大 40,1740 区域，确认声明最后一行被切。
   修复：全局竖直预算重排——封面 560 → 496，网格卡 96 → 88（间距 12 → 10），
   页脚与声明合成一条 158px 的深色底栏。
2. **时间轴首尾标签超出左右版心**：
   首节点标签向左溢出、末节点标签向右溢出到画布边缘。
   修复：标签宽度 120 → 116，首节点改左对齐、末节点改右对齐并向内收。
3. **封面第三张锚点卡压到黄黑危险条纹上**：
   卡片 54px 高、间距 62px，三张累计到 `ty+124 = 504`，而条纹在 484。
   修复：起始 348 → 330、间距 62 → 52、卡高 54 → 46、标记牌 66×30 → 62×28。
4. **虚构声明第二行掉出画布**：底栏只有 148px 时，116 字的 CJK 声明
   在 640px 宽度下需要两行，第二行落在 `BAR_Y+106+15` 之外。
   修复：改用 `wrap_cjk` 显式分行（不依赖 `softWrap`），宽度收到 600
   （实测 632 时最后几个字会压到二维码的静区），底栏 148 → 158px。
