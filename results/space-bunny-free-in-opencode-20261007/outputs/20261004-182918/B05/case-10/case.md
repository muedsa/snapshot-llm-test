# case-10 · 三年房龄履历曲线

- **载体**：桌面浏览器窗口 1600×1000。与 case-04 同载体，但**版式完全不同**：
  case-04 是「这一轮退租的判定表」（逐锚点、逐行、可签字），这一张是
  「这套房三年被照顾得怎么样」（时间轴曲线 + 花钱分布 + 体检结论），**没有判定表**
- **受众**：新接手这套房的房东陆文君，明年还要经手另外 7 套；
  她想拿这一张做「这套房要不要提前安排维修」的判断依据
- **时刻**：2026-10-01，结算完成后的年度视图
- **用户意图**：看三年曲线，回答两个问题——
  ① 哪些位置在反复坏？② 这套房被照顾得怎么样（有没有被拖着不修）？
- **状态**：年度视图 · 数据截至 E-02 补拍期限前 · 下一次体检已排期 2027-01-05

## 场景与内容

- **窗口 chrome + 左侧 rail**（A5 房龄履历为当前项）
- **五个健康度指标卡**：已闭环维修 `2` 次 · ¥440 / 反复出问题的位置 `2` 个（K-02 / B-02）/
  平均响应时长 `3.2` 天 / 最长未修 `0` 天 · 无拖延 / 未确认项 `1`（E-02 暂挂）
- **主图：台盆下逐月湿度读数（%RH）**
  - 39 个月的真实读数（23-07 无基线 → 26-09），带 65% 以上的警戒底色带
  - 两次维修是竖直标记线 + 顶部注释卡：`R-2403-118 换龙头阀芯` 与
    `R-2506-042 换 U 型弯`，各带一个「↓ 读数下降」的绿色箭头
  - 两个峰值标记：`74% 峰值`（24-03 前后）与 `68% 峰值`（25-06 前后）
  - 当前读数 `48%` 带外环，标注「最近一次」
  - 图下注明「数据为演示：39 个月逐月读数由房谱按锚点 B-02 的复拍照片推算，
    非实测传感器记录。」
- **「这三年花在什么上」** 三栏：
  - 左：按报修单的两条条形（¥180 / ¥260，满量程固定 ¥300 = 220px）+ 下方两行结论
    （两次维修平均 3.2 天闭环 / 钱不是问题，问题是这两处为什么会坏第二回）
  - 中：**「没花的 ¥0」**——因拖到退租才产生的赔偿，K-01 ¥120 与 W-02 ¥80
    都是搬走前才拍到的
  - 右：**「下一轮日常轮拍建议」** 三条（B-02 每季度 / E-02 每半年 /
    退租前 30 天加 K-01 / W-02），底部「已加入下一轮日常轮拍 · 首次执行 2027-01」
- **右侧深色「房龄体检」栏**（336px）：
  - 5 项检查：管道系统「需要注意」/ 墙面与五金「正常」/ 门与锁「正常」/
    防水与地漏「未确认」/ 记录完整度「10 / 12」
  - **一句话结论**：「这套房不是被住坏的，是被拖坏的。」+
    「两年两次维修都在两周内闭环，管道却反复坏；真正花钱的 ¥200 是在搬走当天才发现的。」
  - **12 个锚点状态条**：一格一个锚点，按判定着色（含 2 个「未拍」）+ 五色图例
  - 页脚：下一次体检 `2027-01-05` · 已按三条建议排期 · `B-02 / E-02`
- **页面页脚**：口径说明（读数为推算演示数据；「反复出问题」= 同一锚点 39 个月内
  闭环维修 ≥ 2 次）+ `打印年度履历` / `加入下一轮日常轮拍` 两个动作

## 视觉选择

- **把逐月读数做成主曲线，是这一页唯一真正说服人的主张。**
  case-04 是一张表，看完就知道结论；这一页要让人看出**趋势**：
  两次维修在曲线上是肉眼可见的两个下降台阶，而台阶之后又是缓慢上升——
  这就是「管道在反复坏」的视觉形态。
- 「没花的 ¥0」是一个刻意设计的反事实栏。
  它把「履历的价值」从「记录了已经发生的」推向「本可以不发生」，
  这也是这张图存在的商业理由。
- 右侧体检栏用深色反相，因为它承载的是结论而不是数据。
- 底部「加入下一轮日常轮拍」是整条旅程的闭环出口：
  case-10 排的日程，正是 case-01 那次第一次拍摄的下一次。

**本轮实际发现并修掉的缺陷（3 处，每处均重渲染并复验通过）**：

1. **两条绿色条形与「没花的 ¥0」栏重叠**，¥200 那行文字也穿过了该栏：
   v01 的条形按 `amt/300 * 560px` 计算，最长 485px 从 `BARS_X+184` 起算，
   终点已越过 `BARS_X+392` 的分隔竖线。
   定位：首次看图即可见——`¥260` 后面直接压着「因拖到退租才产生的赔偿」。
   修复：条形满量程固定为 **¥300 = 220px**（`BAR_SCALE = 220/300`），
   三栏宽度改为 420 / 234 / rest，并把面板高度 214 → 300 以容纳第三栏。
2. **「一句话结论」的两行文字超出 292px 面板被静默截断**：
   35 字的 CJK 串在 292px 下需要两行，但单个 `Text` 元素在不显式分行时
   会被服务按框宽静默丢弃超出部分（不是换行）。
   定位：crop 放大 1210,690 区域，看到最后停在「真正花钱的 ¥」处被面板边缘切断。
   修复：改用 `wrap_cjk` 显式分行（不依赖 `softWrap`），
   并把标题也拆成两行「这套房不是被住坏的，/ 是被拖坏的。」。
3. **两条维修注释卡与 `74% 峰值` 标签压在曲线上**：
   `GY0 = CH_Y+68` 意味着曲线上方没有留白，注释卡只能盖在数据区上。
   修复：卡片高度 330 → 356、`GY0` 下移到 `CH_Y+104`，
   腾出 40px 的专用注释带；注释卡改放在带内并用短竖线连到曲线；
   两个峰值标签改到点的**下方**并加白底 chip（原本在上方，穿过曲线）。

- [x] 未使用任何外部素材：湿度曲线、面积填充、警戒带、条形图全部由 DSL 几何与
  扫描线填充构造（DSL 没有路径图元，折线由旋转矩形拟合，面积由逐扫描行填充）
