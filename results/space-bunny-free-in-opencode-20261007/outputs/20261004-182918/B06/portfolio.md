## 策展逻辑

这十件作品的共同问题不是「信息太少」，而是**信息的量纲不对**。

- 该比的不是标价，而是每 100 克多少钱（case-01）
- 该看的不是月供总额，而是本金占比（case-02）
- 该算的不是几级能效，而是 10 年总拥有成本（case-03）
- 该读的不是 ↑ 箭头，而是医学决定水平与危急值（case-04）
- 该对齐的不是 AQI 数字，而是同一天的 PM2.5 浓度（case-05）
- 该拆的不是月度总额，而是三档电量构成（case-06）
- 该算的不是折扣率，而是每多花 1 元的边际收益（case-07）
- 该看的不是应发与实发，而是每涨 1 元到手多少（case-08）
- 该摊的不是当前月费，而是 24 个月的累计与切换时点（case-09）
- 该记的不是说明书的小字，而是一天里的三个具体时刻（case-10）

每一件都先把用户手里的那一个数换算成真正可比的量纲，再把它排成一条尺子。
十件的作品形态、画布尺寸、配色、阅读顺序与观看场景都不同
（货架把手 / 房贷 App / 卖场 / 冰箱 / 天气 App / 电表箱 / 结算按钮 / 工资条 / 营业厅 / 药盒），
共享的只有间距节奏与字阶，这样十件读起来像同一个人的十张作品，
而不是一个版式换十次字。

## 使用说明（怎么看这个作品集）

1. **gallery.html** 是本地画廊：十件全部列出，点图打开原尺寸 PNG，
   每件旁边有它的 `final.snapshot`（同一次渲染的完整 DSL）与 `case.md`。
   页面只用相对链接、不加载任何远程脚本或远程字体，断网可浏览。
2. **portfolio.json** 是结构化索引：每一件都带受众、使用场景、内容基础、
   真实来源 URL 与访问日期、真实数值、自拟演示清单、DSL 能力、
   自定的完成标准、看图证据、该件真实使用的请求 ID 与 DSL 版本列表。
3. **problem-evidence.json** 由 `tmp/.../B06/data.py` 直接生成——
   十个难题的事实源只有一份，所以图上数字与证据文件不会漂移。
4. **design-review.md** 是逐件复盘：原难题是什么、信息架构怎么解决它、
   视觉选择解决了什么、取舍与不足，以及本次复审中实际发现并修掉的四处缺陷。
5. **case.md**（每件一份）给的是单件视角：场景 / 内容 / 视觉选择 / 实际自检 / 素材情况 / 来源与假设。

## 复现方式

每一件的 `final.snapshot` 都是自包含的完整 DSL，直接 POST 到
`https://open-snapshot.muedsa.com/snapshot`（请求体为 UTF-8 纯文本 DSL，
必须带浏览器 User-Agent）即可重现该 PNG。
生成脚本在 `tmp/20261004-182918/B06/build_c01.py … build_c10.py`，
共享构件在同目录的 `kit.py`（复用 B01 的 `atelier.py` 与套件的 `dsllib.py`），
事实源在 `data.py`。所有草稿版本按 `case-XX-vNNN.snapshot` 递增保留在 `drafts/`。

## 声明

- 所有最终图都是 `run-config.json` 指定的 `https://open-snapshot.muedsa.com/snapshot`
  的真实响应原始字节；没有用别的绘图库画主体再嵌图，没有使用 `<Image>`，
  没有引用任何外部位图或生成素材。
- 自拟的演示设定（人物、价格、机型、资费、用电序列、购物车、血糖曲线）
  在每件图面与 `case.md` 上都写明，并在 `problem-evidence.json` 的
  `declared_demos` 里逐条列出。
- 没有做过现场调研或用户实验；所有关于「更好用」的表述都只是
  从最终图上可观察到的可读性改善。
- token、图像用量与费用：平台未提供任何计量口径，一律为 `null`，未做估算。
