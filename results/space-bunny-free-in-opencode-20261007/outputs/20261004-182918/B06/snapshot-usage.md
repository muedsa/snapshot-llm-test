## 3. 「惊艳」与「好用」如何同时成立

- **好用**：每件都先把原难题的信息结构拆开——把「只有一个数」还原成它由哪几项构成、
  把「一个大数字」按分位/档位切开、把「一条总价」按真实生效时点铺开——再决定视觉。
  `design-review.md` 逐件写了「原难题 → 信息架构 → 视觉选择 → 取舍与不足」。
- **惊艳**：视觉不是装饰，而是承担信息任务。例如 01 的尺子刻度本身就是比较工具；
  05 的分位色带把「指数」翻译成「你排在多少人前面」；08 用双轴把「到手金额」和「到手比例」
  叠在同一张图上，让税率台阶变成可见的折点。
- 三条底线：**数值必须由脚本按公开口径算出**（不是手填）、**来源必须可追溯**、
  **「自拟演示设定」必须在图上写明**。

- 10/10 张 PNG 均为 `POST /snapshot` 的**原始响应字节**，无任何后处理；
  同名 `final.snapshot` 与产出该图的 DSL 逐字节一致。
- 10/10 个 case 目录均含 `final.png` + `final.snapshot` + `case.md`。
- 10/10 张都用 read 工具**逐张打开看过**；迭代记录 26 条，其中 **17 条计为完整视觉迭代**
  （`查看旧图 → 改 DSL → 重渲染 → 再看并比较`），另有 4 条基线、1 条语法修复、4 条整体审查。
- 元素数最高的作品在 4096 上限的 20%–82% 区间内，从未触发上限。
- 生成器每轮打印文字溢出告警并逐条处理（`Text` 在单行高度框里放不下会**静默丢弃溢出**，
  这是本库最容易踩的坑）。
