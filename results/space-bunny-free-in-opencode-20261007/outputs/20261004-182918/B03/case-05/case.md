# case-05 · 三种取景 · 海洋浮标观测卡

## 场景与受众

- **受众**： fictional 海洋浮标「屿东 07」的运维工程师（看整幅谱），
  以及需要快速判断能量集中频段的值班研究员（看圆形镜头）。
- **使用场景**：一张观测卡要在同一屏里给出三种取景——全幅扫描、圆形放大镜、
  圆角卡片——因为不同的人要在不同尺度上读同一份数据。
- **用户要完成的事**：确认 24 小时里有两次能量峰、峰值频段约 0.17–0.21 Hz，
  并把窗口放大到 15:24–18:36 看主峰的形状。
- **观看环境**：桌面 1600×1060，值班室双屏。

## 内容依据

浮标编号、站位、时次、Hs/Tp/浪向/水温/气压全部为**自拟演示值**，页脚已注明。
谱型是真实计算：

```
fp(t) = 0.17 + 0.035·sin(2π(t − 3)/12.4206)            峰频随 M2 漂移
E(f,t) = [exp(−(f−fp)²/2·0.085²) + 0.22·exp(−(f−2.35fp)²/2·0.06²)]
         × (0.55 + 0.45·sin(2π(t − 1.5)/12.4206 + 0.6))
```

三种取景调用**同一个 `energy()`**，所以全景放大镜和卡片缩略图的数值必然一致。

## 视觉选择与探索的能力

主打**裁剪家族**。先用 `tmp/20261004-182918/B03/probes/probe-c05-clip.png`
（12 格：每格放一个 460×300 的故意越界子节点，红框是裁剪边界）逐项验证，
再用第二次探针单独证明 `ClipPath` 不存在：

| 手法 | 用在哪 | 实测结论 |
|---|---|---|
| `ClipRect clipBehavior="HARD_EDGE"` | ① 全景 | 像素对齐硬边 |
| `ClipOval clipBehavior="ANTI_ALIAS"` | ② 圆形镜头 + 描边圈 | 唯一能拿到椭圆/圆的裁剪 |
| `ClipRRect` 四角独立圆角 | ③ 圆角卡（对角大圆角 64） | 与 `Container` 圆角格式一致 |
| 嵌套裁剪相乘 | ③ 卡内第二层 ClipRRect 缩略图 | 内层先裁、外层再裁 |
| `clipBehavior` 四档对比 | ③ 底部四格 | `NONE` / `HARD_EDGE` / `ANTI_ALIAS` / `ANTI_ALIAS_WITH_SAVE_LAYER` 都能写；`SAVE_LAYER` 是**非法缩写**，要写全称 |

### 三条实测出来的边界（都写进了页面本身）

1. **`shape="CIRCLE"` 不裁剪子节点。** 探针 B 里，276×138 的圆角容器装着
   460×300 的红块，红块照样溢出圆外。`shape` 只改变自身装饰的形状。
   （另外 `shape="OVAL"` 直接 400 —— `BoxShape` 只有 `RECTANGLE` 和 `CIRCLE`。）
2. **`ClipPath` 这个标签没有被注册。** 单独发一次请求拿到
   `400 PARSE_ERROR: Unknown element tag [ClipPath]`。
   解析器一共注册 38 个标签，裁剪只有 ClipRect / ClipOval / ClipRRect 三个。
   想要任意形状的取景，只能用这三个近似。
3. **裁剪会吃掉子节点的投影。** 探针 J（ClipRect）红框外没有光晕，
   探针 K（Stack 自己的 HARD_EDGE）红晕直接穿出。要裁影必须用 Clip*。

5. **v3**：复查三视图 —— 全景看出两次能量峰、镜头看清主峰随时间的横向漂移、
   圆角卡的对角圆角与内嵌层都成立。

## 遗留 / 不足

- 圆形镜头里的网格没有铺满圆盘（角上露出底色），这是 `ClipOval` 的正确行为，
  但如果产品上需要「满幅圆形热图」，只能把网格画得比圆更大再裁，
  或者干脆用 `shape="CIRCLE"` 的渐变近似——后者不能做逐格数据。
- 谱型是演示模型，不是实测反演谱；没有做频率分辨率、窗函数、测地修正。
- 未提供 `ClipPath` 的替代方案（例如把热图先画成位图再按形状加载），
  因为本套题不允许嵌入位图。
