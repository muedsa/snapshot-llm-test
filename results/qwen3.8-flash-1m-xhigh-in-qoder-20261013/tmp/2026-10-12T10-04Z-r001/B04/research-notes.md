原计划主题是"城市树木如何改变一条街的热、水与碳"，需要 EPA / USDA Forest Service /
Berkeley Lab 等公开网页。2026-10-13 06:26 用 WebFetch 尝试读取
`https://www.epa.gov/heatislands/heat-island-basics` 与
`https://www.fs.usda.gov/managing-land/urban-forests/istree/benefits`，
两次都被本会话的权限分类器拒绝（返回 "action blocked by classifier … 外部 HTTP 请求
超出当前工作区/受信本地路径范围"）。**因此该主题被放弃**：按题目要求
"无法取得材料时调整到可查证主题，仍不能伪造研究"，不能把未访问的页面写成已读来源。

改选**在本环境中真实可查证**的主题：一个声明式图像渲染服务把 XML 变成 PNG 的实测报告。
它的材料全部在本地且可追溯到真实网络访问记录：

1. 官方文档 58 页，2026-10-12 10:10–10:13（+08:00）真实抓取，
   逐条记录在 `tmp/2026-10-12T10-04Z-r001/_suite/requests.jsonl`
   （`kind=document`，含 URL、状态、字节、本地缓存路径），
   原始 HTML/Markdown 缓存在 `_suite/docs/`，纯文本在 `_suite/docs-txt/`；
2. 服务自身的 `GET /fonts` 与 `GET /openapi.yaml` 响应（同一日志，真实字节）；
3. 本套 A01–B03 期间对 `POST /snapshot` 的 553 次真实请求日志
   （含 server-timing、缓存头、错误码、请求/响应字节、图片尺寸），
   这是**一手测量数据**，任何人可用同一批 JSONL 复算。

## 读者与核心问题

受众：要用（或要自建）声明式图像/图表渲染服务的工程师与技术编辑。
核心问题：这类服务的**能力边界与代价**到底在哪里——文本度量谁负责、失败长什么样、
构图预算有多少、时间花在哪一段。这些问题官方文档不会直接回答，只能测。

## 叙述路线（十件）

1. 封面：一份实测报告的规模感（553 请求 / 58 文档页 / 458 张图）
2. 管线：一次 POST 到一张 PNG 的八段旅程 + 每段实测耗时
3. 词汇表：官方标签树与实测可用性（哪些属性被静默忽略）
4. 文本度量：CJK/Latin/Mono 前进宽度与行距的实测常数（本报告最"硬"的一页）
5. 失败分类学：95 次非 200 的类型、触发条件与可诊断性
6. 构图预算：4096 元素上限下，1 元素与 N 元素的取舍（字节/元素散点）
7. 色彩插值：渐变色标之间按线性光混合的证据与误差
8. 字体清单：`/fonts` 真实响应里的族名与覆盖
9. 时间与缓存：server-timing 分布、3.1% 命中率、一个 249 s 的离群值
10. 边界与不确定：只在特定条件下成立的结论、未复现现象、无法验证的部分

## 证据分级约定（贯穿全特辑）

- **事实**：文档原文或响应/日志中可直接指认的内容（给 source_id + 定位）
- **测量**：本套日志与像素回读得到的数值（给请求 ID 或脚本名，可复算）
- **解释**：我对上述证据的推断（明确标"自行解释"）
- **演示**：为说明机制构造的示意（明确标"演示，非事实"）

## 已知限制

- 样本只覆盖这一个服务与这一个时间窗（2026-10-12 → 10-13），不能外推到其它渲染服务；
- 文本度量是在服务返回的 PNG 上回读得到的近似（±1px），不是它的内部实现；
- 未访问任何外部网页，因此没有第三方对照；
- 一次 249 s 的离群请求未重复出现，原因未知（不推测为"网络抖动"，只登记）。
