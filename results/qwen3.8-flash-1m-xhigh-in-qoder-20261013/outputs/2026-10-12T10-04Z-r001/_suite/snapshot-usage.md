## 2. 已在真实服务上确认的边界（不是文档转述）

| 结论 | 影响 | 证据 |
| --- | --- | --- |
| 单文档元素上限 4096，超出 400 | 密集网格必须折叠成单个 ClipPath | B03 probe-nodes4000 |
| 未裁剪的 `BackdropFilter` 会不透明重合成整幅画布 | 玻璃效果必须套 ClipRRect/ClipPath | B03 probe5–7 |
| `LINEAR` 渐变的 tile 模式不可见，`RADIAL` 的 radius 决定平铺周期 | 闪光/平铺纹理只能用 RADIAL | B03 case-03 |
| `SWEEP` 不接受 gradientRadius/Center，0 弧度在 3 点钟方向顺时针 | 表盘/日晷需换算角度 | B03 case-02 |
| `border` 线宽 > `borderRadius` → 500 INTERNAL_ERROR | bkit 构造前拦截 | B03 |
| `Transform` 必须同时给 matrix 与 alignment；`origin` 只接受 `"(x,y)"` | 旋转一律用矩阵 | B03 |
| 全 `Positioned` 子节点的 Stack → “Layout size is infinite” | Stack 需要一个有尺寸的子节点 | B03/B05 |
| `Positioned` 必须是 Stack 的直接子节点 | 不能包在 ColorFiltered 里 | B05 |
| `fillType` 被忽略，非零环绕决定挖孔（反向环=洞） | 剖面/挖孔用反向子路径 | B03 case-06 |
| `ClipPath` 路径坐标是子节点局部坐标 | 平铺图形要本地化 | B03 case-08 |
| `smcp` 接受但 0 像素变化；`tnum` 有效；letterSpacing/wordSpacing 有实测增量 | 数字对齐用 tnum + 等宽 | B04 |
| 渐变中点在线性空间插值（中间调 Δ 最大 69，端点 0） | 色带标注不能按 sRGB 猜 | B03/B04 |
| Emoji 只能内联在 Text 中且需 dataUri；`url` 拒绝 `data:` | 表情符号用法受限 | A17 |
| Container 的 border 不沿 ClipPath 描边 | 需要逐边画线 | B03 case-08 |
| 缓存命中时 `server_timing` 只有 `cache;desc=hit`，不带 `render;dur` | 分位数统计须剔除命中 | B04/B05/B06 |

## 3. 跨题经验（哪些做法真的省了时间/救了质量）

1. **共享 bkit，且把踩过的坑写成断言。** 服务边界一旦进 `bkit`（border/radius、
   Stack 无限大、Transform 参数），后续题目就不可能再犯——B04–B06 的 400/500
   失败为 0，而 A 类早期题目为此各付过 1–13 次失败。
2. **文本度量模型是界面类作品的命门。** 实测 CJK 1.0em、拉丁 0.62em、
   等宽 0.52em、行距 1.46em、粗体 CJK 仍 ≈1.0em。有了它，溢出与重叠在送服务之前
   就能算出来；没有它，只能靠反复渲染猜。
3. **自检要覆盖「文字 vs 容器」和「静默截断」。** B05 起新增
   `panel/spill` 与 `maxw/truncated` 两道检查，B05 拦下 6 次、B06 拦下 6 次真实缺陷
   （文字掉出卡片、"372 滴"被截成"372…"、"儿童输液室"差 1px 被截），
   逐条见 `tmp/<run>/B05/iterations.jsonl` 与 `tmp/<run>/B06/iterations.jsonl`。
4. **自检有盲区：形状与文字的重叠它看不见。** B06 case-01 的灰条与叉线盖住了时间列，
   五项检查全绿。这类问题只有真的看图才会发现——所以「每张成功响应都必须打开看」
   不是形式要求。
5. **数据要单源、要断言。** B05 十屏共用 `data.json`；B06 十件作品共用另一份。
   两次跨屏矛盾（7 天格 vs 14 天依从率；印刷效期 vs 开封效期）都是靠
   「派生量集中在一个模块 + 断言」暴露并修好的，而不是靠逐屏校对文案。
6. **文案里的数字必须是算出来的。** B06 抓到三处：手写「约 100 元」实为 75.3/59.3；
   写死「17%」税率为 5%；决策树把「否」分支的扣款张冠李戴。看图时必须连着数字一起看。
7. **编码本身要能分辨。** B06 case-04 的散点有 5/7 项挤在边界线上，case-06 的四列
   每列只剩 8 字一行——两者都是「布局选择让信息又变得难读」，推翻重做而不是微调。
8. **诚实边界要写进画面。** B05 的「未采集字段」「本页不替代医嘱」、
   B06 的「未查证权威清单」「示例数据（自拟）」，比在文档里声明更有效，
   因为它们会随画面一起被看到。

## 4. 失败与重试的实际情况

- 91 次逐题失败集中在 A 类与 B01–B03：A10 12、A11 13、B01 22、B03 26；
  B04/B05/B06 三题为 0。
  B03 的失败绝大多数是**故意探针**（试探 4096 上限、非法属性值、SWEEP 参数、
  border/radius 组合），用于换取边界结论，已计入 `iterations.jsonl` 的
  `probe` 类而不算视觉迭代。
- 全套失败响应错误码分布（760 条日志）：`null` 32 / PARSE_ERROR 25 /
  RENDER_ERROR 19 / INTERNAL_ERROR 16 / IMAGE_LOAD_ERROR 1。
  `null` 多为客户端读超时或 403（无服务端错误码），在 B04 的失败分类里单列。
- 未使用任何重试绕过质量问题的做法；429/503 未触发（无 `Retry-After` 记录）。

## 5. 环境限制与如实处理

- **外部 HTTP 抓取在会话后半段被权限分类器拒绝**（WebFetch 两次、curl/urllib 探测各一次）。
  处理：B04 改用本地可复算的主题（本套真实日志与像素回读），并在
  `outputs/<run>/B04/snapshot-usage.md` 与 `problem-evidence` 类文档中写明
  「未做外部检索」；B06 全部数据标注为示例编制，不假称引用外部资料。
- **`POST /snapshot` 需要 `X-API-Key`**，密钥只从环境变量读取，未写入任何 DSL、
  日志或文档；`GET /fonts` 可匿名。会话中途出现一次环境变量不可见，
  经 `render.py`（curl 传输）实测仍能正常出图，故未中断交付。
- 运行时缓存（`__pycache__/`、`*.pyc`）按根 `.gitignore` 排除，不作为过程证据；
  请求/响应原始字节、草稿、失败响应、预览与脚本全部保留。
