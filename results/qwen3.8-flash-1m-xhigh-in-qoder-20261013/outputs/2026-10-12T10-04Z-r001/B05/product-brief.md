# 药盒 · 产品简报（B05）

> 一套面向「一家三代、其中一人慢病多药」家庭的用药看守产品。
> 本简报中的每一个数字都来自 `tmp/<run_id>/B05/data.json`，由 `b05data.py` 推导；
> 十张画面读同一份数据，不各自编数。

## 1. 要解决的真实问题

周成 47 岁，和 78 岁的母亲周秀兰同住，女儿 12 岁。母亲每天要吃三种药、四个时点：
08:00 降压、08:00 与 20:00 降糖、22:00 降脂。周成自己吃维生素 D 滴剂，女儿只在哮喘
发作时用吸入剂。

这个家庭的实际困难不是「记不住吃药」这一件事，而是四件交织在一起的事：

1. **余量看不见。** 药盒里的铝箔板剩几片没人数过。本次样本里，阿托伐他汀钙片只剩
   3 片（可用 3 天），而社区医院开同一种药要 7 天——等到发现已经来不及。
2. **效期是两种。** 未开封看盒上日期，开封后要按更短的天数算。维生素 D 滴剂盒上写
   2028-03-31（535 天），但 2026-10-08 开封，实际只能用到 2027-01-06（85 天）。
   家庭药箱几乎总是把这两件事混在一起。
3. **照护者没有回看手段。** 子女周末回家，无法回答「这两周我妈到底吃全了没有」。
4. **交接没有载体。** 复诊时把一袋药带给医生或社区药师，说不清哪些是自购、哪些是
   哪个科室开的、还剩多少。

现有方案（手机闹钟、便签、分药盒）各自解决其中一件，且都不留记录。

## 2. 受众与设备

| 人 | 角色 | 设备 | 使用方式 |
| --- | --- | --- | --- |
| 周秀兰 78 | 主要服药者，视力弱 | 手机（大字）+ 手表 | 只看「现在该吃什么」，长按确认 |
| 周成 47 | 管理员 | 手机 + 平板 + 打印 | 录入、补货、回看、复诊交接 |
| 周雨桐 12 | 按需用药 | 家长代管 | 不直接使用 |
| 家庭其他成员 | 临时照护 | 冰箱卡（离线） | 扫一眼，不需要账号 |
| 社区药师 | 交接对象 | 桌面浏览器 + A4 | 核对、签字 |

产品不假设老人会用智能手机之外的功能：手表与冰箱卡是「不需要联网也能给出正确
答案」的两条退路。

## 3. 产品机制

**唯一数据源。** 3 位成员、5 种药、14 天服药日志；派生量全部由脚本算出：

- 可服天数 = 剩余量 ÷ 每日时点数。降压药 5 片 ÷ 1 = 5 天；降糖药 26 片 ÷ 2 = 13 天；
  吸入剂按需、无固定时点 → 明确显示「无法按天数估计」，不硬造数字。
- 有效效期 = min(盒上效期, 开封日 + 90 天)。所有屏的颜色、排序、分级都读这个数，
  因此不会出现「警报页说 85 天、打印页说 535 天」。
- 补货判定 = 可服天数 ≤ 补货提前量 + 3 天。命中 3 项：M1（5 ≤ 10）、M2（13 ≤ 13）、
  M3（3 ≤ 10）。
- 依从率 = 已确认时点数 ÷ 应服时点数（14 天窗口），按需药不计入分母。
  周秀兰 52/56 = 92.9%（漏 4 次）、周成 4/14 = 28.6%（漏 10 次）、周雨桐不计。
- 漏服判定 = 超过时点 60 分钟仍未确认。**这条阈值是设计假设，未与真实用药习惯核对。**

**确认动作只有一个。** 手表长按、手机今日页勾选，都写回同一个时点状态；其余界面
（警报、平板、打印）是这份日志的不同投影，不引入第二套状态。

**产品不给用药建议。** 界面只说「该吃什么、还剩多少、什么时候到期、要不要补货」，
不说「要不要加量、能不能同服」。每条可能被视为建议的文案都指向说明书或药师。

## 5. 视觉与可读性约定

- 一个语义一种颜色（绿=已确认、蓝=待服、红=需处理、琥珀=警告），**颜色之外必须有
  文字**：所有徽章都写「需补货 / 开封期 / 待药师确认」，A4 页在黑白打印下仍完整可读。
- 手机正文 ≥16px、按钮与关键数字 ≥18px；手表 200×240 上最小 14px；冰箱卡 ≥18px
  （1 米外可读）；A4 页最小 14px，按 96dpi 折算约 10.5pt。
- 数字统一用等宽字体，避免「372 滴」与「3 片」在扫读时错位。
- 每屏底部交代数据边界：截止时刻、同步周期、未采集字段。

| 回收点/药房位置 | **未查证任何权威清单**，界面只给通用做法并要求问药师 |

本套没有真实用户参与，因此不声称做过可用性测试、访谈或对照。上述内容如需验证，
需要至少 3 个真实多药家庭的两周记录。

## 7. 演示数据说明

5 种药、3 位成员、14 天日志均为**演示样本**，用于展示机制如何落到界面上；
姓名、地址、医院名称为虚构。产品逻辑不依赖这些具体数值：换成真实药箱后，
同一套派生规则（可服天数、有效效期、补货判定、依从率）直接复用。

## 8. 复现方式

```
python tmp/<run_id>/B05/b05data.py            # 生成 data.json（含推导断言）
python tmp/<run_id>/B05/b05pages.py all       # 生成 10 份 DSL，逐屏布局自检
python tmp/<run_id>/_suite/scripts/render.py --dsl ... --out ...   # 送服务出图
```

`b05pages.py` 在写文件前对每屏做几何自检：文字两两不重叠、不出画布、不出卡片、
不被省略号截断、不低于该设备最小字号；任一条件不满足即中止，不产出该屏。
