# B06 · Snapshot 使用记录与踩坑

43 次 `/snapshot` 请求全部 200（33 次迭代 + 10 次定稿），无失败、无重试；
10 件作品共 12 种画布尺寸（含 case-07 改版前的 1200×800、1200×700 两个中间形态）。
全部请求经 `tmp/<run_id>/_suite/scripts/render.py` 发出，逐条记录在
`tmp/<run_id>/B06/requests.jsonl`。

## 1. 用到的 DSL 能力

十件作品仍是纯类 DOM 结构，没有使用滤镜、裁剪路径或外部素材：

| 能力 | 用在哪 | 备注 |
| --- | --- | --- |
| `Container` + `borderRadius` | 所有卡片、色块、徽章 | `borderRadius = h/2` 即胶囊；圆形点用正方形 + 半径一半 |
| `Container` + `boxShadow="0 6 18 #18202814"` | 卡片 | 自定义属性，四值 `x y blur color`，颜色带 alpha |
| `Container` + `border="N SOLID #RRGGBB"` | 描边、层级强调 | 线宽 > 圆角时服务返回 500，bkit 在构造前拦截 |
| `Transform` + `matrix2d(cos, sin)` | 所有斜线、45° 斜纹、时间轴针 | 必须同时给 `matrix` 与 `alignment` |
| `Text` + `overflow="ELLIPSIS" maxLines="1"` | 有宽度预算的名称列 | 服务端截断不回报调用方，所以 bkit 先自行截断并计数 |
| `Text` 等宽字体 | 所有数字列 | `Noto Sans Mono CJK SC`，避免数字宽度漂移 |

元素数最多的一屏是 case-09（296 个元素，24,980 B 请求体），远低于 4096 元素上限；
本题没有触发任何 4xx/5xx。

## 2. 图形技法（全部由 DSL 现算）

- **发散条形阶梯**（case-01）：以「现在」为零点，正负两侧条长 = 分钟数 × 固定比例；
  收班一侧用两条交叉线做「叉」，而不是靠颜色。
- **时间带**（case-02）：31 格 × 30 分钟，色阶四档各配文字图例；指针位置由
  `分钟/30` 的小数插值算出，不目测。
- **瀑布 + 年化**（case-03）：同一比例尺（1 元 = 0.0333 px）贯穿月度与年度两节。
- **每项独立参考带**（case-04）：每条带的定义域由该项自身的 `min(low, value)`、
  `max(high, value)` 加 30% 余量算出，因此不同量纲的指标各自可读。
- **45° 斜纹严格裁剪**（case-08）：`hatch_rect()` 用 `x + y = c` 逐条求与矩形的交点，
  端点落在矩形边上——第一版手工夹取端点，斜纹溢出了条形右端。
- **建筑剖切**（case-09）：每层东西区的色块宽度与该层科室数量成比例；
  科室名按块宽自动在 18–20px 间选号（`dept_size()`），放不下直接抛错而不是截断。
- **双基准占比**（case-05）：成人 8400 kJ 与儿童 7100 kJ 两条基准并排，
  同一包在两条基准下的占比由同一份数据算出。

## 3. 自检模型（实测值）

文本度量沿用 B03/B05 校准的模型：CJK 1.00 em、拉丁 0.62 em、等宽 0.52 em、
行距 1.46 em（另加 4px 段间距）、字形在 em 框内下沉约 +6px @17px。

五道检查在写文件前全部为 0 才放行：

| 检查 | 含义 | 本题命中次数（修复前） |
| --- | --- | --- |
| `overlap_n` | 文字两两不重叠 | 5（case-08 标签列、case-07 路径行、case-10 表头） |
| `outside_n` | 不出画布（含 8px 安全边） | 4（case-06 页脚、case-04 注脚、case-03 说明、case-05 表头） |
| `spill_n` | 不出所属卡片 | 3（case-06 解除行、case-07「是」标签、case-04 注脚） |
| `truncated_n` | 没有被省略号吃掉的字 | 4（case-07 节点问题、case-09「儿童输液室」、case-04「TI-RADS」、case-05 名称） |
| `below_min_font_n` | 不低于该形式的目标字号 | 0 |

## 4. 踩坑清单

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 斜纹画到条形外面 | 手工夹取线段端点，未按矩形求交 | 改为 `x+y=c` 与矩形求交后逐条裁剪 |
| 自检全绿，图却明显压字 | **审计只比文字框，不比「形状 vs 文字」**：case-01 的灰条与叉线盖住了时间列 | 把主轴右移，让最长灰条的左端与时间列之间留出 26px |
| 散点图没有信息量 | 7 项偏离里 5 项 <0.2，全部堆在边界线上 | 换成每项自己的参考带；编码本身要能分辨才成立 |
| 四列并排反而更难读 | 800px ÷ 4 列 → 正文每行只有 8 字 | 改 2×2，行宽翻倍 |
| 「否 → 扣 200 元」是错的 | 桩标签回退取了节点的 `yes_fee` | 在数据层为每个「否」显式写结果并断言 |
| 「高出约 100 元」与样本不符 | 行动项文案是手写的 | 全部改为从 12 个月样本计算（75.3 / 59.3） |
| 「17%」税率与 600 元矛盾 | 比例写死在画面里 | 改为 `tax / gross` 计算值（5%） |
| 表头与数值列不对齐 | 表头右对齐位置与数值列不同 | 统一按数值列的右沿对齐 |
| `maxw` 静默截断 | 预算宽度按估计给，未按实际字宽核 | 由 `truncated_n` 断言兜住，宁可抛错也不留省略号 |
| 名称替换出现「能量（能量）」 | 用字符串 replace 生成显示名 | 改为显式映射表 `NAME_CN` |

## 5. 服务侧观察

- 服务端渲染耗时：n=42（缓存命中的 1 次不带 `render;dur`），
  p50 368ms、p90 947ms、最小 160.6ms、最大 2728.7ms；
  客户端总耗时 135.6s / 43 次。
- 缓存：42 miss、1 hit（同一 DSL 重复提交时命中，与 B04/B05 结论一致）。
- 画布最大 1200×1600 级（case-09 为 900×1600），未触及任何尺寸限制。

## 6. 复现

```
python tmp/<run_id>/B06/b06data.py          # data.json（含 30+ 条派生断言）
python tmp/<run_id>/B06/b06works.py all     # 01-05 的 DSL + 五道几何自检
python tmp/<run_id>/B06/b06works2.py all    # 06-10 同上
python tmp/<run_id>/_suite/scripts/render.py --dsl ... --out ... --log ...
python tmp/<run_id>/B06/archive.py          # 校验字节并归档 + problem-evidence.json
python tmp/<run_id>/B06/make_docs.py        # portfolio / gallery / metrics / design-review
```

`archive.py` 的归档条件是：请求日志里存在一条 200 响应，其 `request_file` 与当前 DSL
文件同一路径、响应字节以 `\x89PNG` 开头，且取该 DSL 的**最后一次**渲染结果——
因此最终图必然对应最终 DSL。

## 7. 与前几题的关系
