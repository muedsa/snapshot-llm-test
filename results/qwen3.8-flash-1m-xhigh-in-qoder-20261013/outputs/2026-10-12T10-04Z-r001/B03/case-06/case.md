# case-06 · ZK-14 钻孔柱状图（ClipPath 挖孔与岩芯编录）

- 场景：岩土详细勘察报告附图，工程师要能量出层厚、查采取率、对深度读标贯
- 画布：960 × 2000，PNG 205 KB，服务请求 `B03-case06-v3`（944 元素）
- 主能力：`ClipPath` 反向子路径在岩层条带中**挖通**漏失井段 ＋ 嵌套 ClipPath 花纹 ＋
  `rich` 混排深度/岩性/采取率 ＋ `tnum` 深度列

## 手法

每层是一个 Container，被自己的 ClipPath 裁出条带；漏失井段作为**同一条路径内的反向环**
被减掉，露出纸色——不是涂白，所以任何底色下都成立。花纹（砂的圆点、粉的横线、粘土的砖缝、
砾石三角、灰岩溶隙、填土碎屑）同样画在该层的 ClipPath 内，绝不跨层出血。
深度轴 50 px/m 精确，条带高度＝层厚×50，可直量校核；标贯柱与取样旗共用同一 y 映射。

## 文档依据与实测

- `ClipPath` 属性名是 `path`，`fillType` 被解析器忽略、保持非零环绕
  （`widget_painting_clip-path.txt` ＋ 早期实测），因此孔必须反向绕行：
  顺时针外框 `M 0 0 L W 0 L W h L 0 h Z` ＋ 逆时针内环 `M 0 c L W c L W a L 0 a Z`
- 第一版内环与外框同向 → 像素回读 (185,168,143)＝层色，孔没有打通；
  改为反向环后同一坐标回读 (246,243,236)＝纸色 #F6F3EC，三处漏失井段
  （0.9–1.35 / 13.3–13.9 / 30.2–31.4 m）全部验证通过
- 嵌套：花纹 Stack 需要至少一个带尺寸的非 Positioned 子节点，否则
  `Layout size is infinite`（同 `B03-misc`）
- 砾石三角第一版把路径坐标写成绝对 y，被 44×13 的本地盒子裁光 → 改为每颗三角
  自带局部路径（放大图 `zoom-c06-upper.png` 可见）

## 看图与自检

- `v1`：文字与标贯列相碰、页脚溢出、38 段文字小于 16px → 画布 780×1900→960×2000，
  字号统一 ≥16，比例锁定 50 px/m（assert SCALE==50.0）
- `v2`：漏失孔未打通（见上）→ 修反向环
- `v3`：audit `overlap_n=0 outside_n=0 below_min_font_n=0`，84 段文字 / 71 图形
- 断言：Σ层厚＝32.000 m、Σ标贯井段＝30.2 m（表层 1.8 m 杂填土不做标贯）、
  漏失井段均在 0–32 m 内且 lo<hi

## 数据自洽

9 层、15 节标贯、7 个取样点、4 段漏失全部写进 `case06-data.json`，
每层记录 top/bottom/厚度/像素高度/采取率；采取率 <80% 的 4 层在图上标红，
与数据字段一致（65/71/58/79/40%）。

## 边界与取舍

真实柱状图的岩芯照片、钻进回次表无法由 DSL 生成，这里只画"可由数据支撑"的部分；
没有把漏失画成白色矩形冒充，因为白色矩形在有色底纸上就是错的表达。
