## 3. 设计选择与几何决策

### 3.1 全轴对齐 elbow 走线，而不是曲线或斜线

A01–A05 的探针已经量清：`<Transform matrix>` 的 2×2 部分非单位时（旋转、错切、缩放
都一样）**整块子树不输出任何像素**——不是报错，是静默空渲染。而 DSL 文档 39 个标签里
没有 `Path` / `Line` / `Polyline`。

所以本题放弃"一条 Path 画一条边"的实现，改为：

- **边走线只用水平段与竖直段**（`hseg` / `vseg`，各是一个矩形），直角拐弯；
- **箭头只用沿坐标轴的矩形堆叠**：5 根逐级缩窄的窄条拼出三角轮廓，尖端指向四种正
  方向之一，不需要旋转；
- **长期先决 N04→N13 与两条反馈回路走左侧嵌套走廊**（x = 145 / 195 / 265），
  右侧 x ≥ 1080 整块留给说明面板。

代价是 DSL 体积 59 619 B / 379 个 `<Positioned>`，比"一条 Path 一条边"大得多。
收益是每条边走线都严格可审计：折线顶点写进 `graph-audit.json`，核验器可以逐像素
沿折线采样。

### 3.2 零交叉是构造出来的，不是碰巧的

走线刻意安排为"层内不横向穿越、走廊不互相穿插"：

- 11 层各占一行（`ROW_Y = 128 + i*63`），层与层之间的横向段互不相交；
- 三条长边走线在左侧走廊竖向嵌套，x 坐标彼此不同且都小于任何节点盒的左缘（323），
  因此与层内横向段无交点；
- 两条反馈回环用 x = 195 / 265 分道，N09→N08 的横向段在 y=443、N10→N08 的横向段在
  y=506，箭头都指向 N08 左边框。

153 对边组合（18 条边的全组合 + 自配对排除）逐段做严格内部相交判定：**端点相接不算
交叉**（那才是合法连接），平行或共线不算，只有水平段 × 竖直段且交点严格落在两段
开区间内才算。结果 0 处。

### 3.3 拓扑层用最长路径松弛，不用最短

层号定义为"从源节点到该节点的**最长**先决路径节点数 − 1"，这样同层节点在先后关系上
真正等价，不会因为某条短路径把它们错拉到更浅的层。用 Kahn 拓扑排序 + 最长路径松弛
计算，11 层连续无空洞；最长先决路径 11 节点 / 10 边，共 2 解，图中都画出来了。

### 3.4 反馈边为何虚线 + 专用色 + 反向

若把 2 条反馈边计入拓扑排序会产生环，"先决边不指向过去层"的布局就无从谈起。所以
按题面另行标出，视觉上用虚线 + `#D97706` 与实线 `#334155` 区分，并明确标注
`excluded_from_dag_layering: true`。图内另有两处解释：回环内侧的短标签与右侧面板的
两张解释卡，避免只看图的人把反馈边误读成普通先决依赖。

- **核验器自身缺陷 3 条**：`min_chroma` 门槛、短段端帽、float 切片。
- **服务报错 0 条**。

### 踩坑要点

1. **"渲染成功"完全不能当验收依据。** v3 是最典型的一次：服务返回 200、PNG 大小甚至
   正常（353 264 B，跟相邻版本接近），但 18 条边全部不见。唯一可靠的发现手段是整幅
   看图 + 结构计数（`Positioned` 379→137）。
2. **面板内容总高必须算，不能看缩略图。** v5 的卡片越出 8px 在整幅图上几乎看不出来，
   只有逐像素量三列（面板内侧、卡正下方、卡右侧）才看得清：同一段 y 区间在卡正下方
   还是卡片底色、在卡两侧却是画布色——这一对照直接证明是越界而不是别的。
3. **核验器的色彩门槛不能跨题沿用。** A05 的 `min_chroma=40` 在本图把饱和度只有 34 的
   `#334155` 整条边排除了，16 条边全部判成没画。定位线索是"同一颜色下的箭头断言却
   通过了"，矛盾点立刻指向色彩门槛而不是几何。
4. **短段会被端帽吃掉。** elbow 的转折段只有 10.5px，两端各留 6px 就把它吞成空数组，
   于是"覆盖率 1.000"是假象——它压根没量过那一段。端帽上限必须随段长收缩。
5. **`Transform` 的 2×2 部分是静默失效，不是警告。** 想画斜线或旋转箭头时没有任何
   错误返回，只是那一整块不输出像素。这类边界最好在 A01–A04 阶段用探针量清再定架构。
6. **右对齐盒必须算左缘。** `txt_box` 的定位参数是盒的左缘；想右对齐到
   `RP_X+RP_W-24`，就要减去盒宽，否则盒直接越出画布。
7. **`Text` 的 `textAlign` 无效。** 自适应宽度的 `Text` 上设对齐没有效果，列对齐只能
   走 `Container alignment` + `Alignment` 枚举名。
8. **容器高度 ≤ fontSize 会裁掉字形底部。** `txt_box` 一律把容器底边钉住、把顶边向上
   撑高到 `fontSize + 2`，文字只上移 2px，行内与列间对齐关系不变。
