# Snapshot：一次提交，按序完成全部任务

把这个完整目录作为模型工作根目录，发送START-PROMPT.txt的指令即可。
默认包含24道进阶题A01–A24和6道开放创作题B01–B06，共30题；包括预置多轮
与每开放题至少10件作品，合计至少124张指定最终图片，预览和额外探索另计。
不必选单题、不必逐题发消息；任务开始后从清单第一项自动做到最后一项。

## 启动

1. 直接使用task-suite/作为工作根目录；模型需有文件、文档/网络、
   HTTP和实际图像查看工具。输入资料全在这个目录中。
2. 发送[START-PROMPT.txt](START-PROMPT.txt)，或“阅读AGENTS.md和TASKS.md，按
   默认配置实际完成全部30题，逐件看图完善，保留过程并交付全套汇总”。
3. 模型在统一outputs/<run_id>/<任务ID>/交付、tmp/<run_id>/<任务ID>/保留过程，
   outputs/<run_id>/_suite/为总索引、gallery.md画廊、报告、过程统计与进度。
   画廊覆盖全部最终图，包括多轮和开放作品；Markdown逐图预览并相对链接PNG/DSL。
   不限制请求/迭代。

默认all包含全部任务；仅在你明确需要其他范围时修改run-config中的default_profile
为advanced或creative。服务地址和两赛道素材政策也可以统一配置。子题沿用
原内容与标准，总AGENTS明确覆盖它们原先的独立运行目录/逐题结束方式。

## 可迁移路径

所有本地路径使用明确基准的相对路径，或直接指向目录的环境变量；DSL、程序脚本、
命令、配置、自建日志和报告都不能写死当前机器的位置。用户目录按语言读取USERPROFILE/HOME。
配置相对配置文件，记录默认相对总任务根，Markdown本地链接相对文档且不使用变量。
详见[PATHS.md](PATHS.md)，生成报告时按实际位置重新计算链接。

## 连续多轮与恢复

A21/A22第二、三轮要求已放入各自rounds/；前轮真实完成并归档后模型自动
继续，不等待新消息。这里是预置三轮连续执行版本，未来要求可提前访问，
适合看执行/回归能力。此套件直接提供全部轮次要求，评测时应按连续执行模式记录。

一次会话30题工作量较大；持续进度在输出_suite/suite-state.json，历史检查点
在临时_suite/checkpoints/。若平台中断，把run-config.resume_run_id设为原run_id，
让模型读取进度并继续未完成部分。题库不能绕过平台实际时限或自动唤醒会话；
中断时如实保存部分状态，只有全部任务与总审查通过才标完成。
