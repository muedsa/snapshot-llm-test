## 时间边界与优化目标

采用release.json的+08:00发布日时间，09:00至16:00是连续420分钟工作窗口，
不另扣午休或其他休息，不跨天。以09:00为第0分钟，所有任务start≥0、end≤420，
end−start严格等于输入minutes；16:00整完成允许，16:00后完成不允许。
占用区间用[start,end)；同团队上一任务结束时可立即开始下一任务。
所有依赖的end≤后继start即可在相同时间边界衔接；无额外准备或切换耗时。
风险说明用于解释返工或等待可能消耗缓冲，不擅自加到题设固定时长中。

目标是尽量减小所有任务end的最大值（相对09:00的完工分钟数），不是只让某个
选定任务提前或尽量填满团队空档。缓冲=420−最大end；关键路径下界只用依赖和时长，
资源工作量下界=全部任务minutes之和/2，两者均以分钟记录且不提前取整。
提供可行排程及改进依据即可，不要求额外的全局最优证明；未知最优性如实标明。
schedule.json同时记录精确分钟偏移和带时区的起止时间，三张图使用同一份排程。
