# 开放创作评测端材料（不要提交给被测模型）

模型只接收task-suite完整任务根目录。固定同样的服务/字体/文档/
工具能力与素材政策；用实际文件权限隔离旧作品和评分材料。允许各种
实际工具，不以调用工具数量、复杂标签数量或耗时作为创意得分代理。

## 最低完成与独立性

至少10件独立完整作品，各自解决明确真实使用任务、状态、媒介或内容问题。
同图改色/改字、简单适配、草稿/预览/接触表与局部裁切不算独立件。B02/B05
同一系统中不同触点/任务/状态可以计数，不能要求它们必须不同风格；B01
看场景与视觉思路广度，B04看叙事和资料准确，B03看实际手法而非标签堆砌。
根据任务和最终图判断，不因为模型自称10件就在元数据上照单全收。

每件的PNG/同名DSL必须是真实服务响应。实际工具记录支撑逐件看图、改进、
最终整体审查和素材来源；HTTP成功或写了长报告不能代替视觉和事实核查。
辅助素材允许时，分辨素材本身的质量与DSL组织/构图/效果的贡献；不得把
整图或主体预绘后嵌入当完成。没有素材工具仍可纯DSL完成，不直接扣分。
有具体平台阻塞则标环境受阻；不足10件如实标部分完成，不用低质图补数量。

## 评分

0–4分，权重：原创性与视觉主张25、实际场景价值20、视觉完成度20、作品组合
与深度10、文档/DSL/工具工作能力10、视觉迭代与审查10、交付与可复现5。
权重总计100，总分为分项/4乘权重。完成率与总分分别报告，不以一张旗舰图
代替整个合集：逐件评原创/价值/视觉，再报告平均、中位数、最低件与缺陷分布；
组合项整体评。缺件不补成优秀件，同一作品重复不计数。记录实际完整独立件数。
不预设某种风格、配色、滤镜或“越花越酷”。好信息设计/克制构图也可能高分。
一次真实检查通过不低于多次改善；无效迭代不加分。记录最终质量、请求/迭代与耗时，
不以调用少加分或调用多扣分。真实数据/引用错误与审美偏好分开。

## 盲评与证据

至少两名评审隐藏模型身份看原尺寸、同样展示规则的缩略和画廊，再独立评分；
分歧记录原因。对场景价值另核对简短需求/内容说明，不把宣传性解释当视觉证据。
重点看作品的辨识度、形式与内容关系、使用环境可读性、真实内容、组合多样性
或一致性、自主发现问题与改进、未解决问题的诚实度。checklists只提示方向。
先用少量模型试跑校准工作量、件数独立性与评审一致性，再冻结正式对比版本。
随意选题/自拟内容也是能力的一部分，但要记录选题难度，避免只凭合成演示
推论真实部署成效。没有实际用户试验就不能宣称用户成功率提高。

## 指标核对

逐用例请求+共享请求应等于整体请求；重试是子集，HTTP/其他工具事件不要
重复计算。基线、视觉改进、语法修复、方案探索分别计数，父版本可追溯。
并行时间和等待不重复累计。评测端复核请求
单独记录，不混进模型请求统计。../task-suite/authoring-validation.json仅为任务输入与分发检查，
六题没有标准作品也尚未完整执行，不能把静态检查通过当作品质量通过。
